# SceneGuard

**CCTV의 침입 의심 구간을 사건 카드와 근거 영상으로 검토하는 로컬 프로토타입입니다.**

원본 영상과 기존 카메라 설정을 선택하면 분석 결과를 저장하고 기존 웹에서 카드·근거 영상·검토 이력을 확인합니다. 영상만으로 출입 권한이나 법적 무단침입을 판단하지 않습니다. 정상 접근 오탐과 추적 단절이 남아 있어 자동 판별 성능은 충분히 검증되지 않았습니다.

## 실제 확인한 흐름

```text
로컬 원본 + 명시적 C3/C6 + 분석 구간
  → 원본·모델·설정·PTS가 일치하는 검출 캐시 확인
  → 캐시가 없을 때만 기존 canonical GPU 큐의 FCOS 검출
  → 기존 ByteTrack gap · 접근/소실 · 침입 의심
  → 출입구별 사건 카드 · 원본 근거 클립 저장
  → 기존 결과 화면 등록 · 근거 시점 확인
  → 별도 수동 검토 상태·메모·수정 이력 저장
```

**저장 결과 재생 / 저장 검출 결과를 이용한 CPU 분석 / 새 GPU 검출 분석**을 구분합니다. 현재 시연은 선택 구간을 모두 처리한 뒤 결과를 보는 비실시간 분석입니다.

| 항목 | 실제 확인 범위 |
|---|---|
|단일 실행 명령|007의48–105초,030의84–100초를 원본 선택부터 등록까지 실행|
|새 검출 연결|기존 캐시에 없는00745–48초90프레임을 기존 GPU 큐에서1회 실행|
|사건 카드|00710알림→2카드,0308알림→3카드. 사람 수/정답 사건 수 아님|
|알림·근거|첫 알림·후속 무음 갱신, 원본 PTS 표시, 되감기/근거 시점 이동 확인|
|검토 저장|자동 상태와 별도 상태·작성자·메모·버전·이력, 충돌409·텍스트 렌더 확인|
|검토 복구|자동 갱신·새로고침·서비스 재시작 뒤 검토/영상 위치/펼친 상세 유지|
|재실행|동일 명령에서 완료 단계의 바이트 결속 확인 후 재사용, 추가 추론 없음|
|추적 단절 후처리|007·030 각1회 비교에서 감소0. 미채택, 기존 의심 규칙 유지|
|전체 원본/독립 평가|`--whole`은 구현됐으나 이번 전체 원본 실행·새 독립 평가 미수행|

기능 연결과 실제 시연은 완료했지만 **침입 판별 성능 개선은 확인하지 못했습니다.** [EXP-0037 결과](docs/experiments/EXP-0037-results.md) · [독립 검토](docs/reviews/EXP-0037-independent-review.md) · [게시/화면 전달 기록](docs/experiments/EXP-0037-delivery.md).

## 실행 및 확인

이미 구성된 로컬 저장소 루트에서 다음 명령을 사용합니다. 아래 절대 경로는 현재 사용 중인 기존 서비스 설정입니다. 환경 경로와030 명령은 [CLI 안내](docs/design/MVP_FINISH_CLI.md)에 있습니다.

```bash
.venv/bin/python -m sceneguard.video_cards \
  --video data/TS_침입/E01_007.mp4 --camera C3 \
  --start 48 --end 105 --cache outputs/exp0029/cache007 \
  --output outputs/exp0037/video007-v4 \
  --register-config /home/jhc7484/dev/sceneguard-orca-lab/runtime/orca-lab/local_config.json \
  --registration-id exp37-cli-007-final
```

동일 명령은 검증된 완료 단계를 재사용합니다. 원본·설정·구간·코드가 달라지면 새로운 출력 경로와 등록 ID를 사용해야 합니다. 새 검출에는 기존 Run의 활성 Task/Dispatch와 담당 터미널이 필요하며, GPU 여유6144MiB 미만에서는 모델을 실행하지 않습니다. 새 큐나 우회 실행을 만들지 않습니다. 최종 exact-job 선택 보호는 CPU 회귀 시험으로 확인했고, 그 수정 뒤 GPU를 다시 실행하지 않았습니다.

기존 화면 **http://127.0.0.1:8765/ → 담당3 → EXP-0037 → 사건 카드 재생과 검토**에서 영상을 선택합니다. `007/030`은 저장된 후처리 비교이고 `E01_007/E01_030`은 단일 CLI 분석 결과입니다. 같은007의 짧은45–48초와48–105초는 결과 선택의 시간 범위로 구분합니다. 카드의 **근거 시점 보기**와 **수동 검토 및 이력**을 사용합니다.

검토 상태는 **침입 의심 / 침입 확인 / 침입 아님 / 판단 불가**이며 자동 상태를 덮어쓰지 않습니다. 화면 시험용 메모에는 `Codex 기능검증·정답 아님`을 명시했습니다. 확인된 사용자 정답이 아닙니다. 이미 최초 알림을 표시한 같은 녹화 세션을 다시 재생하면 영수증에 따라 무음입니다.

기존 환경·원본·모델·사용자 영역·로컬 서비스 설정이 필요합니다. 저장소만 내려받아 실제 CCTV를 자동 실행하는 구성은 아닙니다. 모델/영상/캐시/근거 클립/검토 메모·DB/인증정보는 Git에 포함하지 않습니다. 서비스 중지 전 영상 연결을 닫는 방법과 복구 명령은 [전달 기록](docs/experiments/EXP-0037-delivery.md)을 따릅니다.

## 구조와 테스트

- `sceneguard/video_cards*.py`: 선택 영상 분석, 기존 큐 연결, 완료 단계 재사용, 로컬 등록.
- `sceneguard/`: 기존 검출·추적·소실·의심·사건 카드·검토 저장.
- `orchestration/`, `webapp/`: 기존 큐·결과 등록·영상 및 수동 검토 화면.
- `mvp/`: 기존 VLM 실험 보존. 현재 자동 침입 확인에 사용하지 않음.
- `docs/experiments/`: 조건·실측·실패·한계, `tests*/`: 관련 계약/회귀 시험.

```bash
.venv/bin/python -m unittest discover -s tests -p test_mvp_finish.py -v
.venv/bin/python -m unittest discover -s tests -p test_video_cards.py -v
```

관련 CPU/큐156테스트와 웹/브라우저 확인을 수행했습니다. 테스트 수는 침입 정확도가 아닙니다. 전체 저장소의 모든 분리 환경 테스트를 통과했다는 의미도 아닙니다.
