# 최신 사용자 승인 — EXP-0039 검출·영상 연속성 보강

2026-10-31. [CODEX_EXP0039.md](CODEX_EXP0039.md)를 우선한다. 이번에는 VLM 확대나 학습이 아니라 **저장 검출 누락/ID 연결 실패를 구분하고, 원본의 짧은 특징 추적으로 CV 관측을 보강**한다. 이전 실험의 종료 문구는 당시 범위 종료이며 최신 사용자 승인을 막지 않는다.

## 코드 준비 완료 / 실제 로컬 실행 전

- `sceneguard/gap_observation_support.py`: 모든 저장 검출의 연결 상태 감사 + 전후방 검증 광학 흐름. 추적 예측과 실제 검출을 구분한다.
- `sceneguard/exp0039_application.py`: 기존 EXP-0035·원본·관측·영역을 보존하면서 007/030 소실 의심 전체를 CPU 처리한다. 특징점은 동일인/침입 정답이 아니다.
- `tests/test_gap_observation_support.py`: 22개 합성 시험 통과. 실제 CCTV 실행·기존 전체 저장소 회귀·사용자 환경의 시험 결과는 아직 없다.

## 실제 진행할 작업

1. 로컬 변경을 보존해 최신 main을 반영하고 새 테스트를 기존 CV 환경에서 실행한다. 007·030의 기존 EXP-0035 결과에 CPU 진단/짧은 영상 추적을 각 한 번 적용한다.
2. 정상 접근에서 ID만 끊겼는지, 침입 의심 구간에서 관측 자체가 끝났는지 원본·검출·특징점 경로를 함께 확인한다. 검출은 남았는데 tracker 관측에 연결되지 않은 경우도 기록한다.
3. 영상 연속성이 뒷받침하는 후보는 원래 알림을 보존한 별도 제안 보기에서 오탐 통지를 줄일 수 있는지 비교한다. 광학 흐름 실패, VLM 판단 불가, 반대편 미관측 때문에 기존 침입 의심을 다시 차단하지 않는다. 의심 생성 조건과 3초/10초 사건 카드 묶음은 그대로다.
4. 저장 검출이 없는 구간에만 지시서의 조건을 충족하면 같은 FCOS/기존 ROI로 최대 2구간×3초의 확대 검출 비교를 허용한다. 기존 canonical 큐 사용. 새 모델·학습·데이터 수집·수동 박스·전체 재추론·영역/임계값 탐색은 없다.
5. 실제 변화 또는 변화 없음을 보고서에 남기고, 기존 담당3에 비교 자료를 등록해 실제 재생/표시를 확인한다. 코드/문서/비식별 결과만 GitHub에 게시한다. VLM은 계속 보조수단이며 이번 VLM 재실행은 없다.

기본 코드의 알림 변경은 0이다. 비교를 통해 효과를 확인하는 단계이지 이미 오탐이 줄었다는 완료 선언이 아니다. 구현한 범위와 실제 실행한 범위를 나누어 보고한다.
