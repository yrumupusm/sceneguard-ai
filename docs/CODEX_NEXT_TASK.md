# 최신 사용자 승인 — EXP-0041 사건 묶음과 통지 분리

2026-10-31. [CODEX_EXP0041.md](CODEX_EXP0041.md)를 실행한다. 목표는 **접근·대기의 불필요한 경보 감소 + 필요한 침입 의심 유지**다. 이전 종료 문구는 당시 실험 범위이며 최신 승인을 막지 않는다.

준비된 코드:
- `sceneguard/incident_notifications.py`: 전체 후보로 사건을 묶은 뒤 통지 여부를 구분. 중간 후보가 제외돼도 카드/ID가 분리되지 않는다.
- `sceneguard/exp0041_application.py`: EXP-0040 저장 baseline·감사 점수만으로 0.55/0.65/0.70 비교. 새 특징/검출/추적/VLM 호출 없음.
- `tests/test_incident_notifications.py`: 작성 환경에서 CPU 합성 시험46개 통과. 실제 로컬 데이터·웹 적용은 아직 전이다.

실제 진행:
1. 기존 환경에서 새 시험/관련 회귀 후 007·030의 저장14소실 전체를 비교한다. 0.55는 우선 검토할 후보이지 자동 채택값이 아니다. 점수/가중치/영역은 바꾸지 않는다.
2. 전체 후보로 원래3초/10초 사건을 유지하고 통지 대상이 처음 생기는 시각에 알린다. 전부 검토 전용인 사건은 이력만 남기고 경보하지 않는다. 과거 최초 시각으로 소급하거나 미래 결정을 앞 화면에 표시하지 않는다.
3. 추가 제외 구간을 원본/기존 경로로 검토한다. 이미 확인된00759.666667초 대기는 기존 사용자 검수를 재사용한다. 완벽한 개별ID 정답/수동박스를 요구하지 않는다.
4. 007 접근·대기의 불필요한 사건 경보와 00770–73초/03090–94초 의심, 첫 통지 시각을 함께 평가한다. 어떤 기준이 실제로 더 쓸 만한지 결과로 제시한다.
5. 새 contract의 `cards`는 전체 이력, `alert_cards`는 통지 보기다. `created`가 아니라 `notify`를 기준으로 표시한다. 기존 담당3에 최소 어댑터를 연결해 실제 재생/되감기/폴링을 확인한다. 기존 검토DB/알림 영수증은 초기화하지 않는다.
6. 유용한 결과면 설정 후보를 고정해 연결 방안을 명시한다. 가능한 보유 독립 구간 확인은 하되 새 학습·데이터/박스 제작·모델 탐색으로 확대하지 않는다. 실제 결과·독립 검토·전달 기록을 GitHub에 게시한다.

코드 준비를 성능 개선 완료로 보고하지 않는다. VLM은 보조수단으로 유지하며 이번에는 실행하지 않는다.
