# Codex 다음 작업 — CV baseline 제한 구현 및 첫 로컬 실험 (Phase 2A)

**2026-10-27 사용자 승인:** 소규모 CV 구현·진단 실험을 시작한다. 이는 [ADR-0006](decisions/ADR-0006-limited-cv-baseline-prototype.md)의 **개발용 프로토타입 승인**이며, AI-Hub 메인 데이터 G1E 확정·모델 최종 선정·외부 성능 검증 승인은 아니다.

먼저 [AGENTS.md](../AGENTS.md), [CV baseline 계약](design/CV_BASELINE.md), [평가 구성안](data/AIHUB_INTRUSION_EVALUATION_PLAN.md), [사용자 검수](data/AIHUB_INTRUSION_USER_REVIEW.md), [ADR-0005](decisions/ADR-0005-minimal-boundary-baseline-design.md)을 읽어라. 이전 데이터셋 감사와 정답 원본은 보존한다.

## 단계별 구현 범위
1. **환경 및 모델 후보 확인:** 로컬 WSL2/RTX 3080의 드라이버·CUDA·PyTorch 등 실제 가용성을 기록. 사전학습된 **사람 탐지 모델 하나**를 용량·작은 사람 인식 적합성·라이선스/가중치 출처·의존성·로컬 실행 가능성으로 비교해 최소 후보 선정. 불필요한 프레임워크 다중 설치/대용량 다운로드 금지. 설치/다운로드한 실제 항목·버전·출처와 선택 이유 기록. 현재 환경을 훼손할 위험이 있으면 격리 환경 사용.
2. **최소 실행 코드:** 로컬 MP4 → 원본 PTS를 유지하는 디코딩 → 사람 bbox 검출 → 최소 IoU 기반 프레임 간 일대일 ID 연결 → 카메라별 ROI/유한 경계선 양측에서 같은 사람의 **실제 관측** 확인 → 이벤트 **후보** 출력. 입출력·불명확함 처리·경계 양측 지속 조건은 `docs/design/CV_BASELINE.md`를 따른다. 어려운 가림은 우선 unknown/연결 단절로 기록하고 고급 tracker 도입 금지.
3. **실행용 경계 설정:** 카메라별 좌표/방향을 명시한 로컬 config를 별도 저장하고, 코드에는 특정 카메라 픽셀 값을 하드코딩하지 않는다. 정답 구간/원본 캡션을 추론 입력으로 사용하거나, 테스트 결과에 맞춰 경계선을 사후 조정하지 않는다. 배경 프레임을 통한 수동 설정은 development 진단 목적으로만 수행하고 설정 버전·방법을 기록. 필요한 로컬 preview는 Git 제외.
4. **작은 테스트부터:** 인공 좌표/track 시퀀스로 경계 방향, 평행 보행, 경계 접촉만 한 경우, 양측 관측, 누락/ID 연결 단절, 중복 경보, PTS 처리 테스트. 그다음 이미 확보한 **E01_006, E01_007, E01_030, E01_031 중 2~4개** 개발 영상을 대상으로 구간 smoke test(예: 각 10~20초) 후 부담이 허용되면 전체 클립 진단. 006 119~132초 평행 보행은 **비이벤트 후보**이고 검수된 negative ground truth는 아님. 006/007은 같은 카메라 후보이며 전부 평가/튜닝에 사용된 개발 데이터로 명시.
5. **출력과 실패 기록:** 로컬 JSON/CSV로 `video_id, boundary_id, track_id, observed_pts_before/after, candidate_pts 또는 candidate_interval, emitted_at_pts, direction, uncertainty, evidence_refs, model/config/code_sha`와 중단/누락을 기록. 사람 등장·접촉을 자동 침범 이벤트로 취급하지 말 것. 물리적 울타리 넘기 완료/법적 무단침입 판단은 `unknown`으로 둔다. 031은 종료를 완료로 단정하지 않는다.
6. **진단·성능 기록:** 검출 성공/실패·가림·경계 병행 보행·넘기 시점 대비 후행 출력 등 **관찰 가능한 사례**, 단계별 처리 시간, 전체 throughput FPS, 가능하면 VRAM·지연을 **실측값만** 기록. 영상 FPS, 처리 FPS, 추정 사건 시점, 출력 시점을 구분. 평가 manifest/사람별 정밀 시작/검수된 negative 미확정이므로 **최종 precision/recall/F1/FP/hour나 새 카메라 일반화 성능 주장 금지**; 숫자가 나오면 개발 표본의 탐색적 통계로만 명시.
7. **문서·커밋:** 재현 명령·사용 라이브러리/가중치 라이선스·model SHA·버전·기기·한계·실행 결과를 `docs/experiments/` 및 필요하면 `docs/troubleshooting/`에 작성. `docs/HANDOFF.md`, `docs/WORK_PLAN.md` 갱신. 테스트·`git diff --check` 등 수행 후 작은 단위로 코드·문서만 커밋/푸시하고 변경/테스트/결과/남은 문제를 사용자에게 보고.

## 안전장치
- **별도 라벨 검수 작업은 독립적으로 남겨 둔다.** E01_006의 **실제 4,006프레임 vs JSON 4,011프레임** 차이를 자동 보정하지 마. 원본 PTS로 추론하고 공식 시간 정답 비교는 보류.
- 미검수 구간을 정상/사건 정답으로 임의 지정하지 않는다. 공식 JSON과 사용자 정답은 추론 입력에서 분리.
- 추가 대량 자료 수집, 파인튜닝, VLM, 웹 UI/API, 배포, 민감 미디어 공개 금지. 원본 CCTV·이미지·원 JSON·모델 가중치·캐시·환경 비밀은 Git 제외 로컬에만.
- 모델 사용권이나 GPU 지원이 막히면 무리하게 우회하지 말고 막힌 원인, 재현 조건과 소규모 대안을 기록. **사용자는 이미 본 단계의 소규모 구현·테스트를 승인했으므로 같은 범위에서 재승인 요청 없이 진행 가능**.
