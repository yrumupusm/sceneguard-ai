# 다음 작업 — 기존 MVP 출력의 소규모 평가와 마무리

2026-10-28 사용자가 진행을 승인했다. **이번에 GitHub에 반영한 것은 작업 지시와 출처 정정이다. 평가/로컬 실행이 완료됐다는 뜻이 아니다.** 이전 자원 차단 재개 지시는 종료된 이력이며 GPU 작업을 다시 시작하지 않는다.

이번 명시적인 사용자 승인에 따라 이전 배치 종료 문구를 **저장 결과의 CPU 평가·문서 마무리 범위에서만** 대체한다. AGENTS의 최신 작업 안내도 이 범위로 짧게 갱신하되 과거 실험 결과·승인 이력은 유지한다.

## 총괄에게 맡기는 한 작업 묶음

1. **출처 정정 적용.** 영상 끝까지 집단 전체가 넘기를 마치지 않았다는 사용자 관찰은 031이다. 030 EOF에 인용한 근거로 쓰지 않는다. 007 순간 박스 변화의 ChatGPT 검토와 사용자 직접 확정도 구분한다. 기존 보고서/binding을 몰래 덮어쓰지 말고 이번 평가에서 부가 정정 기록을 연결한다.
2. **기존 B/C 출력 읽기.** 저장된 원시 창별 결과·PTS·모델 상태·근거 참조를 같은 창끼리 연결한다. 새 추론 없이 실제 원천까지 추적 가능한 비교표를 만든다. 긴 병합 후보가 넘기 시점을 덮었다는 이유만으로 성공을 세지 않는다.
3. **작은 평가 목록 고정.** 007·030·013의 기존 5초 분석창에서 최대12개를 기존 관찰/주석/시간 분포에 따라 선정한다. 같은 감시 경계와 자료로 B/C를 비교하고 ROI 밖·카메라 중복·013 재사용을 분리한다. 알려진 실패 장면은 진단 표로 별도 표시한다.
4. **이미 제공한 사용자 근거 재사용.** 행동 존재/정상 구간/미확정의 근거 범위를 구분한다. 사용자가 이미 답한 사항을 반복 질문하지 않는다. 추가 확인이 꼭 필요하면 최대6개 짧은 구간의 단순 질문을 한 번에 모아 기존 웹/로컬 영상으로 제공한다. 답이 없는 항목을 AI가 정답으로 채우지 않는다.
5. **평가 코드·최종 요약.** 라벨이 충족된 부분에서 후보 명중·누락·잘못된 후보·유보와 분모를 계산한다. 형식/근거의 정확성/완료 주장은 별도다. 미확정이 많으면 점수를 만들지 말고 평가 가능한 부분과 필요한 확인을 보고한다. 처음 실행한 CPU 평가와 라벨 확인 후 재집계를 구분하며 GPU 작업은 없다.
6. **독립 검토와 전달.** 기존 총괄/Sol 평가 담당/Astra 검토를 사용한다. 이번 검토는 비식별 창별 상태·시간·출처·분모까지 확인하고 집계 숫자 일치만으로 성능을 승인하지 않는다. 결과를 새 평가 ID로 등록하고 기존 화면·GitHub 반영을 확인한다. README/한 페이지 최종 요약에 실제 기능 완성과 평가 수준을 분리해 기록한다.

## 허용·금지와 종료

- 허용: 기존 출력의 CPU 분석, 소규모 평가 스크립트와 영향 범위 테스트, 필요한 짧은 로컬 검수 자료, 출처 정정, 기존 화면 결과 등록, 재현 문서 정리.
- 금지: 새 GPU 추론/모델 다운로드/재학습/판정 기준·프롬프트·ROI 튜닝/새 웹 기능/새 큐·총괄/원본 미디어 클라우드 전송/유료 API 전환.
- 기존 모델 raw 응답·영상·가중치·공식 라벨·실험 결과를 보존한다. 코드·공개 가능한 평가 메타데이터/요약만 게시한다.
- 이 범위의 세부 단계는 다시 승인을 요청하지 않는다. 기존 확정 근거만으로 충분하면 평가·정리까지 진행한다. 사람 확인이 필요하면 가능한 작업을 완료하고 **하나의 질문 묶음**과 함께 `평가 준비 완료·사람 확인 대기`라고 보고한다. 전체 성능 검증 완료로 표현하지 않는다.
- 성능이 부족하면 실제 실패를 숨기지 말고 가장 큰 실패 유형 하나와 다음 선택 근거를 제시한 뒤 멈춘다. 새 모델 실험을 자동 등록하지 않는다.
