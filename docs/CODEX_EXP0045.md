# EXP-0045 — 문 근처 관측 이력과 문 바로 안쪽의 새 관측

2026-11-01 사용자 승인. 사용자가 마지막으로 강조한 조건은 **안쪽 영역 아무 곳이 아니라 실제 문 선분 바로 안쪽에서 처음 생성된 실제 관측**이다. 새 ID만 붙은 것은 새 출현이 아니다. 침입 인원수/완벽한 개인 재식별 대신 같은 출입구의 사건을 판단한다. 이전 실험 종료/영역 동결은 그 실험 재현에만 적용하며, 이번 명시적 승인에는 아래 새 비교를 진행한다.

## 준비 상태

- `gate_episode_evidence.py`: 과거 3초의 문 근접 이력을 활용하는 소실 확인 보완 + 최초 관측 위치가 문 바로 안쪽인 관측열 탐색.
- `exp0045_application.py`: 기존 EXP35 후보/EXP42 실제 저장 경로를 검증한 뒤 원래 보기, 이력 보완, 새 출현만, 결합 보기를 만든다.
- `test_gate_episode_evidence.py`: 작성 환경에서 표준 라이브러리 합성/순수 함수 시험 **48개 통과**, 두 실행 모듈 문법 검사 완료. 기존 전체 저장소/실제 CCTV/SavedGateDirection·grouping 통합/웹은 미실행이다. 시험 숫자를 침입 정확도와 혼동하지 않는다.

## 1. 두 근거를 분리

### A. 문 근처 → 안쪽 이동 → 관측 소실

기존 EXP44의 마지막 박스 중심 근접 여부가 아니라, 같은 실제 관측 이력의 최근 3초에서 문 부근을 지났는지 본다. 각 이전 관측의 실제 박스 높이/위치로 기존 0.8 높이·최소12px 근접 의미를 평가한다. 마지막 25×29 같은 작은 박스가 앞선 큰 박스의 이력과 근접 범위를 지우지 않는다. 측정된 안쪽 방향의 시각 이전/동시의 근접 근거만 쓴다. 3초는 과거 이력이지 추가 대기가 아니다.

기존 SavedGateDirection의 실제 방향/관측지속 검사와 1초 소실 대기를 재사용한다. 안쪽 방향·최근 문 부근 이력·소실 가정이면 자동 침입 확인, 불명/바깥 방향이면 의심 유지. 실제 관측이 다른 박스로 이어지는 경우를 소실 확인으로 승격하지 않되, 그것만으로 기존 의심/경계 근거를 삭제하지 않는다. 원래 자동 확인은 유지한다. 실측 방향이 없는 사례에 임의 방향을 넣지 않는다.

### B. 문 바로 안쪽에서 새 관측 시작

전체 프레임의 실제 저장 검출을 시간순으로 읽는다. **첫 박스의 중심이 안쪽 영역에 있고, 실제 문 선분의 안쪽 근접 띠에 있을 때만** 새 출현 후보가 될 수 있다. 선의 무한 연장선·안쪽 먼 통로·이미 통로에서 걸어오던 관측은 제외한다. 이 검사는 최초 위치에만 적용하며 이후 안쪽으로 멀어진다고 그 출현 이력을 지우지 않는다.

최근1초의 검출 기하 연결로 ID 교체/짧은 누락 후 재검출을 새 출현과 구별하려 시도한다. raw ID는 연결 조건이 아니고, 단일 프레임의 중복·포함 박스도 추가 사람으로 세지 않는다. 이 연결은 완벽한 사람 재식별이 아니며 겹친 두 사람을 합칠 수 있는 한계가 있다. 기존 FCOS/ByteTrack 결과를 바꾸는 작업이 아니다.

초기 근접 띠는 박스 높이0.8배, 최소12px, 이미지 짧은 변의0.12까지로 제한한다. 큰 박스로 안쪽 영역 전체가 '문 근처'가 되지 않도록 하는 초깃값이며 그림에 띠/첫 중심/거리/허용폭을 보여준다. 0.1초 이상 떨어진 최소2회 관측으로 한 프레임 오검출을 줄이고, 전 프레임 연속이나 전신·VLM·동일 ID는 요구하지 않는다. 분석 시작/소스 공백 직후에는 1초의 과거 관측을 확보한 뒤 새 출현을 판단한다. 실제 검출 누락은 소스 프레임 공백과 다르다.

새 관측 단독 출력은 **침입 의심 근거**다. 박스 하나를 침입 확인/정답/새 사람 수로 바꾸지 않는다. 앞선 방향＋소실 확인이 같은 출입구 사건에 있으면 사건의 자동 확인 상태와 함께 근거를 표시한다. 두 경로를 모두 만족해야만 A가 동작하도록 묶지 않는다. B가 나타날 때까지 A를 기다리게 하지 않는다.

## 2. 007 수정 영역 명시

먼저 [후속 대화](experiments/EXP-0044-followup-discussion.md)와 [영역 수정](experiments/007-inside-region-revision-20261101.md)을 읽는다.

007에는 `runtime/region-revisions/007-inside-20261101-v1/scene007.json`을 명시적으로 넘긴다. 원래 EXP35/42 입력은 **옛 영역과 원래 해시로 검증한 뒤**, 새 정책의 안쪽 영역만 별도로 선택한다. 예전 설정/해시를 새 영역 값으로 덮어써 통과시키지 않는다. 030은 기존 영역을 유지한다. 이번 007은 승인된 영역+정책 적용 비교이지 영역 자체의 A/B 성능 시험이 아니다.

새 영역으로 안쪽 방향 부호가 맞는지 원본에 화살표를 그려 확인한다. 기존 특징 경로는 기존 추출 범위에서 만든 것이므로 영역 확대만으로 새 경로가 생기지는 않는다. B는 원래 actual_boxes 전체를 이용한다. 기록된 마지막 박스를 새 검출로 넣지 않으며 화면에는 현재/마지막관측을 구분한다.

## 3. 로컬 실행

로컬 변경을 보존해 최신 main을 반영하고 기존 CV 환경/Run/서비스를 사용한다. 새 모델·학습·수동 박스·검출기/ByteTrack/flow/VLM 재실행은 없다. 새로운 기하 관측열 연결/판정 CPU 처리는 수행한다. 원본 미디어는 로컬만 사용한다.

```bash
  --baseline outputs/exp0035/007-v1.json --paths outputs/exp0042/007-v1 \

```

실제 통합 오류는 원인을 기록하고 수정한다. 숫자를 맞추려고 시각/ID 예외를 넣지 않는다.

## 4. 실제 끝낼 범위

두 전체 저장 구간(00748–105,03084–100)을 동일 정책으로 비교한다. 이전 기준을 새 영상에 몰래 튜닝하지 않는다. 코드/형식 오류 수정은 허용하되 판정 조정은 별도 기록한다. 다음을 결과로 남긴다.

- 00772초대에서 안쪽 방향을 얻고도 마지막 작은 박스에 막힌 사례가 바뀌는가? 앞선 실제 문 부근 관측이 어느 시각인지 원본으로 확인한다.
- 접근·대기, 일반 보행을 자동 확인으로 잘못 승격했는가? 원래 의심 오탐은 삭제하지 않으므로 단순 확인 증가를 오탐 감소로 보고하지 않는다.
- 새 출현 후보별 **첫 실제 박스가 문 바로 안쪽인지**, 이미 통로에서 오던 사람/단순 ID 교체/중복·가림 해제인지 확인한다. 첫 박스와 이후 위치를 따로 보여준다.
- 여러 인물의 근거는 출입구 카드에 모으고 개별 인원수나 정확한 동일인 연결 성공으로 세지 않는다. 최초 의심 시각과 최초 자동 확인 시각을 구분한다.

`baseline-cards.json`은 원본 그대로, `history-cards.json`은 원래 후보에 이력 보완 자동 상태만, `birth-only-cards.json`은 새 출현 독립 진단, `combined-cards.json`은 결합 비교다. 원래 이벤트 payload/ID/PTS와 수동 검토는 보존한다. **결합은 새 후보로 사건 묶음과 첫 통지가 달라질 수 있다.** 기존 필요 알림이 앞선 접근 카드의 무음 갱신으로 바뀌면 숨기지 말고 첫 통지/첫 확인을 대조한다. 결합 보기가 곧 운영 기본값은 아니며, 불리한 묶음이면 기존 사건에 보조 근거로 연결하는 표시 방안을 보고한다.

원본/문 선분/안쪽 방향/실제 관측/최초 박스/문 접촉 이력/판정의 간단한 영상과 기존 담당3 최소 어댑터를 로컬에서 마무리한다. 작성 코드에는 렌더러와 웹 어댑터가 아직 없다. `inside_birth_events` source_ref를 명시 지원하고 되감기 시 미래의 첫 박스·자동 확인을 표시하지 않는다. 새/부분/마지막관측 박스와 사람 이동을 구분한다. 기존 수동 검토/알림 영수증 초기화나 새 서버 생성은 하지 않는다.

대화에서 이미 본 007의 접근/대기,70–72초 안쪽 이동·가림,76–78초 재등장 맥락은 재사용한다. 뒤 재등장을72초 판단에 소급하지 않는다. 새로 애매한 자동 확인/출현이 있으면 **그 짧은 영상만** 보여주고, 반복적인 동일인 정답·수동 박스 작성을 요구하지 않는다. 코드 숫자만으로 영상 의미를 확정하지 않는다.

결과 보고서·독립 코드/수치 검토·실제 화면 재생/seek/폴링/상태 전환 확인을 기존 GitHub 흐름에 게시한다. 관련 입력/소스/DB만 보존 확인하고 수만 파일 재감사나 새 실험으로 확대하지 않는다. 실패/OOM/대기 없이 실행됐다는 사실과 의미 있는 판정 향상을 구별한다. 기본 MVP는 비교 결과 검토 전 자동 교체하지 않는다.
