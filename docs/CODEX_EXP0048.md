# EXP-0048 — 사건별 상태 연결과 007 일반 보행 확인

2026-11-01 사용자 승인. 목표는 **한 후속 소실로 과거 여러 카드를 동시에 확인하지 않고, 007의 일반 보행을 포함해 의심 후 바깥 이탈이 실제 해제되는지 확인**하는 것이다. 사람별 신원/인원수 복원은 목표가 아니다. 기존 종료 문구는 당시 실행 범위다.

## 준비한 코드와 현재 확인 범위

- `incident_outcome_scope.py`: 기존 실제 `IncidentLifecycle`을 상속한다. 원래 후보/카드 묶음/방향/소실 조건은 그대로다. 후속 결과의 적용 범위와 근거 계보만 관리한다.
- `passage_audit.py`: 의심이 없던 관측까지 포함해 **전체 저장 관측열**의 끝점을 진단한다. 진단 때문에 의심을 새로 만들거나 사람 정답을 생성하지 않는다.
- `exp0048_application.py`: EXP35/42/46 입력과 성공한 EXP47 결과를 검증한 뒤 동일 관측으로 후속 상태를 다시 계산하고 전후 알림/전체 관측 진단을 저장한다. 새 검출·ByteTrack·flow·VLM은 없다.
- 작성 환경에서 상태 시험28개와 진단 시험14개, 총42개를 통과했다. 상태 시험은 Git blob이 원격과 일치하는 실제 `incident_cards.py` / `incident_lifecycle.py`로 실행했다. 전체 관측 스케줄 시험 하나는 주입된 관측/평가 fixture다. 실제 `SavedGateDirection`/전체 CCTV 입력·뷰어 통합은 아직 미실행이다. 문법 검사는 통과했다.

## 바뀐 정책 — 복잡한 동작 점수로 돌아가지 말 것

1. **관측 연결과 사건 확인을 분리한다.** 겹친 사람 주변의 연속 관측은 참고할 수 있다. 그러나 같은 후속 키에 합류했다는 이유로 과거의 모든 카드/접근 근거를 확인하지 않는다.
2. 후속 소실은 연결된 카드 중 가장 최근 후보가 들어온 카드 하나에 귀속한다. 이 소유권은 다음 프레임/새 pending 목록/후속 인계에도 유지한다. 최신 근거가 먼저 확인됐다고 다음 프레임에 오래된 카드로 돌아가 확인하면 안 된다.
3. 안쪽 소실은 선택된 카드의 근거 하나를 확인해 **사건을 확인**한다. 같은 카드에 있던 모든 접근 근거를 동일인/침입 정답으로 바꾸지 않는다. 확인 알림은 카드당 한 번이며 기존 A 근거의 시각/출처도 보존한다.
4. 바깥 소실은 해당 관측에 연결된 의심을 해제한다. 한 계보에 독립 관측 출처가 합류한 경우, 그 하나의 바깥 소실로 전부 해제하지 않고 사유를 기록한다. 단순 1→1 ID 변경에는 이 제한을 붙이지 않는다. 안쪽 사건 확인은 이 출처 혼합만으로 막지 않는다.
5. 이전 카드는 근거가 없으면 미결로 남긴다. 새 확인을 넘기지 않았다는 이유로 자동 정상/해제로 만들거나 숨기지 않는다. 이는 중복 상태전파 보완이며 오래된 의심/일반 오경보 해결까지 한 것은 아니다.
6. 최초 의심, 첫 자동 확인, 해제는 원래 시각 이후에만 표시한다. 자동 확인과 사용자 수동 확인은 별도다. 외부 경보 발송/운영 영수증 claim은 하지 않는다.

이 소유권은 실용적인 사건 처리 선택이지 올바른 사건 경계/신원을 보장하는 기술이 아니다. 원래 3초/10초 묶음을 무작정 늘리거나 모든 카드를 합치지 않는다. 실제 비교에서 득실을 보고한다.

## 007 일반 보행을 반드시 포함

사용자는 007에 그냥 지나가는 사람이 많다고 명시했다. 이미 제공된 `continuous.mp4`의 원본시각 약84–104초를 시간순 표본 프레임으로 확인했을 때 도로를 오가는 보행자가 보였다. 이는 과거 비교 영상의 관찰이며 EXP47 저장 박스에 대한 새 정밀 정답은 아니다. 아래 구간은 검토 위치일 뿐 판정 코드의 시각 예외가 아니다.

00748–105초,03084–100초 전체 저장 관측을 처리한다. 007 후반 일반 보행과 문 주변 접근·대기,70–73초 안쪽 이동을 함께 대조한다. 모든 관측열을 다음처럼 구분한다.

- 의심이 처음부터 없었음: 그대로 지나간 경우. **의심 해제 성공으로 세지 않는다.** 실제 일반 보행 여부는 원본에서 확인한다.
- 의심 생성 후 해제: 해제 전후 원본을 모두 확인한다. 다른 보행자가 떠난 것을 기존 침입 대상의 해제로 사용했는지 확인한다.
- 의심 생성 후 미결: 기존 관측 연결, 방향 없음, 선과 평행, 관측 지속, 대기 부족/영상 끝을 나눠 기록한다.
- 확인 관련: 안쪽 이동 근거가 어느 사건 하나에 적용됐는지와 기존 확인 유지 여부를 확인한다.

`all-observations-audit.json`은 모든 원래 기하 관측열을 다룬다. 관측열 수는 사람 수/독립 평가 표본 수가 아니다. `box_motion_diagnostic`은 특징점이 없는 보행자의 대략적인 영상 이동을 설명하는 값일 뿐 **상태를 바꾸는 방향 근거가 아니다.** 박스 크기 변화/부분 신체도 표시한다. 바깥 보행에서 기존 저장 특징점이 없다는 사실을 사람이 없었다는 뜻으로 쓰지 않는다.

실제 의심 후 이탈 사례가 없으면 해제 성능 미평가라고 기록하되, 일반 보행 관측이 왜 해당하지 않았는지 보여준다. 의심이 있었고 실제 바깥으로 떠났는데 해제되지 않으면 그 사례와 막힌 단계를 명시한다. ‘해제0이니 실패/안전’ 중 하나로 뭉뚱그리지 않는다. 의심을 인위적으로 주입해 실제 성공처럼 만들지 않는다.

## 전달과 성공 판단

원래38후보 payload와 A의00772.6초/03092.733333·93.033333초 근거를 확인한다. 새 후속 확인 시각은 다를 수 있으나 동일한 소실의 결과가 여러 카드로 전파되는지 별도로 검사한다. 원래 카드가 남는 것과 같은 확인 알림이 중복되는 것을 구분한다. 한 사람의 이탈이 다른 미결/확인을 지우지 않는지도 비교한다.

기존 담당3에 EXP47/48 상태와 알림을 나란히 연결한다. `outcome-routing.json`에서 선택/제외한 사건과 이유를 표시하고, 전체 관측 감사에서 보행 관측을 확인할 수 있게 한다. 새 계약을 이전 EXP47로 위장하지 않는다. 전체007 비교영상과 실제 해제/남은 문제의 필요한 짧은 영상만 만든다. 영상/현재점/과거박스/원본PTS를 구분하고 재생·되감기·폴링·확인 알림 중복방지를 확인한다.

현재 업로드된 과거 영상만으로 새 판정 화면을 봤다고 하지 않는다. 기존 행동 검수와 사용자 의도(개별 신원보다 출입구 사건)를 재사용하며, 원본 없이 판단하기 어려운 **새 구간만** 영상을 요청한다. 원본/좌표/영상/DB는 로컬 전용이다. 코드·집계·결과·독립검토·전달 기록은 GitHub에 게시한다. 기본MVP 자동 교체는 하지 않는다.
