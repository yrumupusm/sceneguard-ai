# 포트폴리오 증거 수집 가이드

목표: 개발 과정에서 면접·포트폴리오에 사용할 실제 기술 선택 근거를 누적한다.

| 단계 | 남길 근거 | 위치 |
| --- | --- | --- |
| 문제 정의 | 요구사항, 관찰 가능한 사건의 경계, 비목표 | `docs/PROJECT_CHARTER.md` |
| 선행연구 | 논문 링크, 성능 지표 정의, 보고된 한계 | `docs/research/` |
| 의사결정 | 대안 비교, 채택/배제 기준, 번복 조건 | `docs/decisions/` |
| 데이터 | 라벨 매핑, 샘플 영상 감사, 라이선스 | `docs/data/` |
| 실험 | 코드 SHA, 명령, 환경, 지표, 오탐·미탐 | `docs/experiments/` |
| 문제 해결 | 로그/재현/원인/수정/회귀 검증 | `docs/troubleshooting/` |
| 구현 | 코드 커밋, 테스트, 실행 지침 | GitHub 코드 |
| 개선 | 동일 조건에서 전후 성능과 부작용 | ADR + EXP |

## 작성 원칙
- 기술을 나열하기보다 **왜 필요했는지**를 설명한다.
- 성공뿐 아니라 실패·버린 대안·교체한 모델도 기록한다.
- 데이터 및 화면은 공개 가능 조건이 확인된 경우에만 저장소에 게시한다.
- 실제 구현하지 않은 기능과 자체 실험하지 않은 수치를 성과로 쓰지 않는다.
- 최종 구조: 문제 → 근거/제약 → 검토 대안 → 결정 → 구현/실험 → 오류/개선 → 결과/한계.
