## 인과성·원본·사건 계약

기존0079건·0305건 소실 의심 전체의 저장 점수와 원래18후보를 확인했다. 각 입력의 baseline·audits·summary·request 해시는 영수증과 같고, 신규 baseline도 원래 JSON과 일치한다. 세 기준 모두 `events`는 원본과 같으며 활성/검토 전용은 중복·누락 없는 완전한 payload 분할이다. 원래 event ID, source pointer, 판단PTS, source payload를 재생성하지 않는다.

원래5개 사건의 ID·event membership·source refs·원래 첫/마지막 후보PTS·raw ID 목록은 여섯 실제 결과에서 모두 보존된다. 3초 간격/첫 후보부터10초 제한은 기존 모듈을 사용한다. 검토 전용 행이 중간 연결을 유지하므로 같은0.70의 EXP0040에서 생긴6번째 카드와 추가 최초 통지가 없어졌다. 사건 수는 사람 수나 정답 사건 수가 아니다. 가까운 다른 상황을 한 사건으로 묶을 가능성은 기존 시간 제한 안에서도 남는다.

각 저장 seed 시각은 마지막 관측 이전이고 저장 evidence 종료는 원래 판단PTS다. 기존 점수에서 각 기준의 적격 seed와 경로 간 공간 충돌을 독립 계산했고, 해당 시각 이전의 별도 경계 근거 보호를 적용한 분할이 모든 결과와 같았다. 미래 경계 후보를 과거 의심 보존의 근거로 쓰지 않는다. 새 흐름이나 미래 재등장 입력을 만들지 않았으며 정지·가림·겹침 일괄 veto도 추가하지 않았다.

모든 timeline prefix에서 그때까지의 원래 행과 통지 대상만 snapshot에 포함된다. 첫 검토 전용 후보는 통지하지 않고, 나중의 첫 활성 후보에서 `updated, notify=true`가 가능하다. 이 유형은 실제 여섯 결과에는 없으므로 합성 시험 근거로만 기록한다. 이미 통지한 사건의 후속 검토 전용 행은 무음 갱신하며 통지를 취소하거나 재발행하지 않는다. 되감기 snapshot에는 미래 event ID·통지 상태가 남지 않는다. `first_alert_pts`와 `first_notification_pts`의 의미를 분리했다.

## 웹·채택·전달의 경계

검토 시점의 최소 웹 어댑터는 `group_all_then_notify_v1`을 별도로 처리하고 전체/활성/검토 전용·카드·timeline을 검증한다. JavaScript는 `created`만으로 알리지 않고 `notify`를 소비하며 원래 시각별 snapshot에서 통지 사건과 검토 전용 사건을 나눈다. 비교 등록은 실시간 통지 비활성으로 제한한다. 기존 검토·영수증을 초기화하도록 요구하지 않는다.

이 검토자는 실제 브라우저 재생/seek/폴링, 최종 등록 또는 GitHub 게시를 인증하지 않는다. 해당 수행 여부와 최종 화면 상태는 [전달 기록](../experiments/EXP-0041-delivery.md)을 따른다. 원본/경로 영상의0.70 표시는 과거 EXP0040 결과이며 새 기준의 의미로 오인하지 않도록 보고서가 구분한다.

최종적으로 처리 순서 수정과0.55의 개발 구간 실용 개선을 비교 자료로 수용한다. 추가 제외 장면 검수, 더 이른 필요한 의심 누락, 독립 호환 입력 부재, 실제 온라인 성능은 남는다. 따라서 우선 개발 시연 후보 선정과 운영 기본 채택을 구분하며 후속 튜닝·추론을 자동 시작하지 않는다.
