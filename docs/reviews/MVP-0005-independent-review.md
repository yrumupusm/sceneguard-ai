## Baseline findings and required tests

1. **Native rate and full coverage.** The baseline admits exact 30 FPS only. The new path must retain rational `30000/1001`, real integer PTS, original time base, decoded order and every frame. A nominal rate change alone is insufficient. Compare the complete source clock against cache, tracking, image features, and source/final evidence maps; reject omitted, duplicated, reordered or consistently relabelled timestamps even when frame count matches.
2. **006 has an actual timestamp gap.** The previously audited clock has 4,006 frames at time base `1/90000`: 4,004 deltas of 3,003 ticks and one delta of 6,006 ticks. At zero-based decoded indices 2458→2459, native PTS are 7,381,374→7,387,380 (82.0152666667→82.082 seconds). No inserted source frame, resampling or gap compression is permitted. A bounded native-cadence lattice is a smaller change than arbitrary VFR support.
3. **006 EOF edge.** Its final native PTS is 12,030,018, exactly equal to its declared stream duration. Existing `[0,duration)` filtering would drop that real final frame. A whole-source request must decode to EOF; tests must cover a duration equal to last PTS, preserve all 4,006 frames, and distinguish declared stream duration from inferred last-frame end. Do not silently rewrite the old inventory denominator.
4. **Tracker time.** The old adapter advances one internal frame step per arrival. A source gap must age its prediction/expiry state on the admitted native cadence without fabricating detector/evidence rows. Test one missing tick, a gap spanning retention, low/high association behavior and unchanged regular-30 tracking. Predictions remain distinct from actual measurements; any internal empty tick must not create a source arrival or an event input.
5. **Render time.** The old evidence writer uses `index × dt`, compressing a gap. Encode source-relative native timestamps and independently decode the result to compare every presentation time and frame count. Test whole video and a card clip crossing a gap, including a nonzero clip origin; playback/source maps must agree. Evidence must not display future state when seeking or rewinding.
6. **Explicit registry.** Bind source path/hash to exactly one authorized camera and bind camera configuration, base scene, selected scene, regions and portal by hash. Reject wrong source, wrong camera, missing/duplicate assignment, modified geometry, mismatched portal scene digest and stale request/code/profile. Keep existing default C3/C6 paths compatible. No fallback may silently substitute C3/C6 for a new camera.
7. **Same detector and rules.** Compare frozen code against pre-change Git bytes and all policy/default/config values against the baseline. Preserve FCOS weight and postprocessing, precision, input size, sampling and score/association thresholds; preserve direction, disappearance, portal, candidate, confirmation and activity rules. Test C3/C6 existing regressions and explicit-registry equivalence. A camera/FPS compatibility revision is not the historical MVP-0004 analysis revision.
8. **Execution/report separation.** Keep the old evaluation and truth bytes; create new revision/output paths. The full-run orchestrator must bind the reviewed registry/code before queue submission, still use the canonical queue and reject changed source/config/code. Every source needs a truthful complete/partial/unsupported/failed/not-run status.
