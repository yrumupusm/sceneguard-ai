# EXP-0034 독립 검토

상태: **CPU·GPU 실제 수치 및 최종 보고서·지표 검토 완료 / 자동 적용 보류**.

검토자는 CPU 의미·출처·큐 계약·수치와 최종 파일 결속만 검토한다. 원본 영상을 독립 시각 검수하지 않았고 새 사람 정체 정답을 만들지 않는다. 정적 가림 주석과 외형 대조의 시각적 의미는 총괄의 별도 초안이며 사용자 정답으로 승격하지 않는다.

## 실행 전 발견 사항

기존 합성 테스트 32개는 통과했다. 다음 세 사항은 별도 합성 재현으로 확인했으며 구현 담당자에게 전달했다. 검토자가 구현 소스를 변경하지 않는다.

1. 안정된 영역이 한 번도 성립하지 않아도 `stable == origin == z == None`이면 `침입 아님`이 출력될 수 있었다. 안정된 출발 영역을 명시적으로 요구해야 한다.
2. 과거 양측 관측의 경계 근접 판정에 전체 구간의 박스 높이 중앙값을 사용해 미래 박스를 추가하면 이미 지난 시점의 `침입 의심`이 생길 수 있었다. 해당 시점까지의 관측만 사용해야 한다.
3. 외형 호환 답변 하나와 미비교 경쟁 후보 하나가 있어도 일대일 연결 제안을 만들 수 있었다. 미비교·판단 불가 경쟁 후보를 배제된 대상으로 간주하면 안 된다.
4. 마지막 실제 관측의 급격한 박스 크기 변화를 제외하고도 이전 속도를 새 박스에 붙여 신뢰 가능한 방향으로 표시할 수 있었다. 마지막 방향 단계가 제외되면 방향 근거를 무효로 처리해야 한다.

로컬 재현은 `runtime/EXP-0034/independent_semantics.py` 및 `independent_semantics_initial.json`에 보존했다. 공개 문서에는 실제 좌표·원시 응답을 포함하지 않는다.

총괄이 승인한 구현 계약 수정으로 1·2·4를 해결했고, 원래 32개 및 신규 CPU 9개 테스트를 독립 실행해 통과했다. 정책값 변경은 없다. CPU 실행 허용 의견의 analyzer SHA-256은 `acda41b7c15884acbbfeec6e2a6382dbb4d6f21d1f68e04647c69442803fff47`이다. 기존 영역·선·ROI·양방향 설정을 그대로 대조하는 입력 검증이 030의 480프레임 및 007의 1,710프레임에서 통과했다. 정적 주석은 원본 PTS 0의 총괄 초안으로 출처와 동결 시각이 있으며 독립 시각 검수로 표현하지 않는다.

신규 GPU phase의 전용 연결 제안은 미비교·형식 오류·판단 불가 경쟁 후보가 남으면 연결을 보류한다. 원래 `link_proposals`에도 같은 제한을 추가했다. pinned 로컬 processor의 다중 이미지 준비를 GPU 비활성 환경에서 독립 검증했고 최종 14개 테스트가 통과했다. 영상 질문과 정답 라벨은 입력하지 않으며 A/B 이미지·고정 외형 질문만 사용한다.

사전 보존 감사: 보호 1,132파일 및 기존 큐 46 jobs/46 attempts의 모든 행이 스냅샷과 같았다. 검사 receipt는 로컬 `runtime/EXP-0034/independent_preservation_preflight.json`에 있다.

## 실제 CPU 산출물과 입력 동결 검토

030은 8개 segment·12개 연결 후보와 `침입 의심` 1회, 007은 20개 segment·18개 연결 후보와 `침입 아님` 6회다. 후자의 6회는 두 segment에서 발생했으며 독립적인 사람 또는 에피소드 6개의 검증이 아니다. 소실 기반 `침입 의심`은 두 영상 모두 0회이고 28개 loss 상태는 전부 `판단 불가`다. 007의 종료 시점에 남은 두 항목은 분석 구간 끝의 관측 제한이며 원본 전체 영상 종료를 뜻하지 않는다. 실제 관측 4,171행이 기존 입력과 빠짐없이 대응하고 예측은 제외됐다.

전체 후보 30쌍 중 각도 정보가 있는 것은 13쌍, ±90° 안은 10쌍, 밖은 3쌍, 방향 판단 불가는 17쌍이다. 이는 기하학적 보조값의 분포다. 독립 검토자가 새 동일인 정답을 만들지 않았으므로 사람 검증에 기반한 각도 적중률 분모는 0이며 정확도를 산출하지 않는다.

총괄이 미리 선택한 연결 후보·서로 다른 대상 대조 2쌍·혼합 대조 1쌍을 포함한 6쌍을 확인했다. 총괄의 시각적 역할·정체 초안은 별도 로컬 파일에 있고 모델 입력에는 포함되지 않는다. native PTS와 원본 전체 박스 크롭 27개의 RGB 픽셀 일치를 CPU에서 독립 확인했다. 전체 경쟁 후보 30개 edge와 6개 선택의 segment·raw ID·관측 프레임 대응을 대조했다.

실행 전 GO는 다음 정확한 바이트에만 한정한다. 기존 canonical 큐의 한 작업·한 시도, 6쌍 각 1회, 최대 192 생성 토큰이며 재시도·추가 탐색은 포함하지 않는다. 기존 모델 해시, 실제 lease/부모 프로세스, 활성 Task/Dispatch, 자원 게이트가 유지된다.

- Source hash: `444763469ec1280f3d66e8c05e5d2984ef983f6a748f1700d325530cd36caba6`
- Input contract SHA-256: `6417f963d359122c71e268b630b49eb3ad06d8be192a6931efd7265eb6d2a6d2`
- Manifest SHA-256: `996ecdb638b624d69c54a70ff0e44027c95a3d2dd04a78efa00a69856af3ec90`

전체 로컬 결속은 `runtime/EXP-0034/independent_input_audit.json`과 `independent_preflight_go.json`에 있다. 검토자는 GPU를 실행하지 않았다.

## 실제 GPU 수치 감사

한 작업·한 시도가 성공했고 6쌍/27이미지에 생성 6회, 입력 토큰 3,501개, 출력 토큰 132개를 기록했다. 각 답변은 22토큰이며 토큰 한도 도달·재시도는 0회다. 실제 processor 이미지 27개의 저장 바이트·메타데이터·확장 질문이 실행 전 CPU 준비본과 같았다. 저장 토큰을 로컬 tokenizer로 다시 디코딩해 원시 응답과 일치함을 확인했고 전용 parser를 다시 적용해 저장 판정과 대조했다. 신규 GPU 추론이나 독립 미디어 시각 검수는 하지 않았다.

원시 응답은 모두 코드 fence를 포함해 bare JSON 0/6이고 기존 fence 제거를 적용한 parser는 6/6이다. 이는 형식 통계다. 외형 호환 2개·외형 차이 4개이며 미관측 처리와 판단 보류 응답은 없었다. 총괄이 혼합 대조로 사전 기록한 쌍에도 외형 호환이 나왔으므로 형식 통과를 외형 검수 성공으로 해석할 수 없다. 가려진 신체의 근거 및 실제 인물 대응은 총괄의 별도 시각 초안과 구분한다.

전체 30개 후보 중 24개가 미비교이고 외형 호환 2개 모두 경쟁 후보 미검토로 보류됐다. 일대일 연결 제안·raw ID 병합·모델의 침입 판정은 0개다. 이 결과가 동일인 정답을 새로 만들거나 기존 경보를 지우지 않는다.

모델 적재 10.178199초, 이미지 준비 합계 0.085743초, 생성 합계 5.721548초다. 생성 peak allocated는 4,390,882,816 bytes이고 시작 자원 게이트의 free VRAM은 8,746 MiB였다. 큐 시도 전체 63.513496초는 입력·출처 검증 등의 비용도 포함하므로 생성 시간과 분리한다. 보호 1,132파일 및 과거 46 jobs/46 attempts의 모든 행은 그대로이며 신규 1개씩만 추가되어 47/47이다.

로컬 수치 감사: `runtime/EXP-0034/independent_output_audit.json`, 보존 감사: `independent_preservation_postrun.json`.

## 최종 파일 검토와 정확한 바이트 결속

사전 GO와 수치 감사는 기술 실행·출처·계수에 대한 의견이고 외형·사람 정체·침입 상태의 정확성 인증이 아니다.

최종 보고서는 소실 기반 `침입 의심` 미출력, 혼합 대조의 외형 호환, 가림 부위의 부적절한 차이 주장과 미비교 후보를 명시하고 기본 적용을 보류한다. 총괄의 원본/processor 시각 초안과 독립 수치 검토를 분리하며 새 동일인 정답·정확도·실시간 성능을 주장하지 않는다. 이 서술은 실제 저장 출력과 일치하며 시각적 의미 자체를 독립 인증한 것은 아니다.

공개 metrics 20행의 원본 SHA, 값, 단위 변환 및 집계식을 읽기 전용으로 다시 계산해 모두 일치함을 확인했다. `orchestration.complete.public`로 보고서·검토 문서·등록 package·assignment를 검사하고 `metrics(..., 'EXP-0034')` 형식 검사를 통과했다. 최종 등록 package도 아래 두 해시를 참조한다. 초기 초안에 있던 관측 공백 조건과 출력 보존 대상의 표현을 정확히 고쳤고 지표 상태명을 `침입 의심`으로 통일한 뒤 최종 바이트를 다시 검사했다.
