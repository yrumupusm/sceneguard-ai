- 목적: 정답 JSON과 연결되는 공개 산업 CCTV MP4 4~6개를 확보해 사고 영상 검토 지원 적합성 평가.

## 1. 실제 접근 결과

인증 없는 Python urllib HTTPS 요청으로 확인했다. 재현 스크립트는 `scripts/check_steelbench_access.py`이며 원문 응답·해시·시각은 Git 제외 경로 `data/steelbench_audit/access/`에 보관한다.

| 대상 | 결과 | 의미 |
| --- | --- | --- |
| `steelbench/SteelBench` 데이터셋 API | HTTP 401 | 현재 revision·파일 목록 확인 실패 |
| 같은 저장소 README.md / LICENSE / ethics.md 원문 | 각각 HTTP 401 | 현행 이용 조건 원문 확보 실패 |
| 같은 저장소 `tree/main/sample` API | HTTP 401 | 공개 MP4·JSON 연결 목록 확보 실패 |
| 논문 부록의 `steelbench/SteelBench-release` API | HTTP 401 | 다른 공식 기재 주소도 접근 실패 |
| HF 공개 검색 `api/datasets?search=SteelBench` | HTTP 200, 빈 배열 | 이 요청에서 공개 검색 결과 없음 |
| 대조군 `raiyaanabdullah/isafety-bench` API | HTTP 200 | HF 전체 연결 장애로 보이지 않음 |
| 다른 계정 `ThinkingHub/PP` API 및 고정 revision README | HTTP 200 | 접근 가능하나 공식 이전 여부 미확인 |

401 응답 본문은 `Invalid username or password.` 또는 같은 문구의 JSON이다. 인증을 보내지 않은 요청이므로 비밀번호가 실제로 틀렸다는 뜻으로 해석하지 않는다. 비공개 전환·삭제·이름 변경·접근 제한 중 원인은 확정할 수 없다. 토큰만 추가하면 해결된다고 단정하지 않는다.

추가 수동 검사: 검색에 남아 있는 과거 revision `974b75756130c43f64c7cfe83dc5dd1d46b87025`의 LICENSE resolve URL도 401, 논문 연결 코드 저장소 `anonymous.4open.science/api/repo/steelbench-release-0FD6`는 403이었다. 과거 검색 캐시는 현시점 다운로드 가능성의 증거가 아니다.

## 2. 출처와 배포 조건: 확인 범위 구분

- [논문 본문·부록 F](https://arxiv.org/html/2607.05264v1)는 산업 CCTV, 다층 주석, 모델 보조 주석의 사람 검토, CC BY-NC 4.0 배포 및 재식별 금지 등을 설명한다. 부록에는 두 HF 경로가 혼재한다. 이는 저자 설명이며 이번 로컬 영상 실측이 아니다.
- [지정 배포 주소](https://huggingface.co/datasets/steelbench/SteelBench)의 검색 캐시에는 공개 카드가 남아 있지만 직접 접근은 실패했다. 현행 LICENSE·ethics 원문과 실제 미디어 익명화 상태는 미확인이다.
- [다른 계정의 카드](https://huggingface.co/datasets/ThinkingHub/PP/blob/2a927fb86450332942fb5f4ffac8a20700cd539a/README.md)는 SteelBench라는 제목과 기존 공식 경로를 그대로 사용한다. API revision은 `2a927fb86450332942fb5f4ffac8a20700cd539a`, private/gated는 false였다. 이 사실만으로 공식 이전·동일 해시·현재 배포 권한을 입증할 수 없다.
- 해당 카드에는 비상업·연구 이용, 재식별 금지, 별도 합의 없는 관제 제품 학습 금지가 기재되어 있다. 이전 MP4 비익명화 설명과 v1.1 재익명화 설명이 함께 있어 실제 버전·파일별 적용도 확인해야 한다. 카드만으로 모든 영상의 익명화를 보증하지 않는다.
- 다른 계정에서는 API와 README만 읽었다. 미디어·정답 JSON은 받지 않았고 공식 대체본으로 채택하지 않았다. 공식 경로가 제한된 이유와 복제본의 출처·권한이 불명확한 상태에서 임의로 대체하지 않는다.
- 기존 조사 문서의 1,345개 전체, 50개 샘플 MP4·47개 연결 JSON 등은 **이번에 실측한 수치가 아니다**. 현재 공식 접근 가능 수량으로 인용하지 않는다.

## 4. 재현 및 오류 처리

```bash
python3 scripts/check_steelbench_access.py
```

- Python 3.10.12, Linux/WSL2 `6.6.87.2-microsoft-standard-WSL2`, 표준 라이브러리만 사용.
- 스크립트 SHA256: `aded2b43c1d68d335dd80b90df84020bffa7c4a61d755e9938a3f7357bea3319`.
- 요청당 30초 timeout, 정상 응답 8 MB 제한, 메타데이터만 조회. 인증·모델·GPU·seed·해상도/FPS 설정은 사용하지 않음.
- 성공/HTTP 오류/연결 오류를 구분해 기록한다. 종료 코드 0은 검사 실행 완료를 뜻하며 데이터 확보 성공이 아니다.
- 로컬 `report.json`에는 실행 기준 커밋, 스크립트 해시, 요청별 상태·응답 크기·SHA256이 포함된다. 재실행은 같은 경로의 접근 기록을 갱신한다.
- 자체 모델 지표, 사건 시점 오차, 처리 FPS, VRAM 사용량은 측정하지 않았다.

## 5. 다음 단계와 판단을 뒤집을 조건

1. 작성자 측의 접근 가능한 공식 배포 주소 또는 정상적인 접근 권한을 확보한다. 다른 계정 배포본을 사용할 경우 공식 연결·버전·이용 조건부터 확인한다.
2. 최신 revision을 고정하고 LICENSE·ethics·익명화 이력, 샘플 파일 목록 및 정답 구조를 확보한다.
3. 주석과 연결되는 4~6개를 카메라·행동·가시성 다양성을 고려해 선택하고, 로컬 전체 디코딩·해시·PTS 프레임 검사 및 사용자 연속 재생 검수를 진행한다.
4. 사건 시작·종료/주체별 정답 유무와 사람 보정 필요량을 확인한다. 태그의 근거가 영상 외 정보라면 시각적 정답으로 전환하지 않는다.
5. 카메라·원본 세션·시간 인접 구간별 누수 위험을 확인한 뒤 Go/Conditional Go/No-Go를 다시 제안한다. 최종 채택은 사용자 결정이다.

**현재 필요한 입력:** 접근 가능한 공식 주소 또는 작성자가 확인한 대체 배포 근거. 인증이 필요하면 로컬 로그인으로 처리하고 토큰을 문서·대화·Git에 기록하지 않는다. 이 조건이 해결되기 전 영상 감사 완료 처리나 모델 단계로의 이동은 하지 않는다.
