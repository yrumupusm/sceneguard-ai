## 4. JSON 구조와 불일치

**로컬 확인:** JSON 45개와 MP4 45개의 `metadata.file_name` 집합이 1:1 일치. 전체 라벨은 `Invasion`, 이벤트 구간 합계 53개. 정수 프레임 범위는 JSON의 frame_count 안에 있으며 구간 겹침은 발견하지 못했다. **미감사 영상 36개의 실제 프레임 수까지 검증한 것은 아니다.** 표본 9개에서는 해상도·실제 디코딩 프레임 수와 JSON이 모두 일치했다.

스키마는 영상 메타데이터와 `event_class`, 복수 `event_frame`, `event_length`, 문장 설명 `event_caption`, 비식별화 표기 등을 포함한다. 검사한 라벨에는 사람별 track ID·bbox·경계선 좌표·명시적 정상 시간 구간이 없어 별도 검수가 필요하다. 캡션의 '침입' 표현은 법적 권한의 정답이 아니다.

- **시간순 배열 아님:** 036/039/045. 표본 표는 원래 배열 순서를 유지했다. 시간 평가용 정렬과 원문 배열을 분리하고 캡션의 문장 순서를 구간과 기계적으로 결합하지 않는다.
- **길이 불일치:** 표본의 `event_length − Σ(끝 PTS−시작 PTS)`는 021 **+0.397초**, 031 **−0.897초**, 045 **−0.333초**. 나머지 6개는 절댓값 0.004초 미만이다. 단순 한 프레임 포함 여부만으로 세 차이가 모두 설명되지는 않는다. 원문을 고치지 않고 정의/수작업 오차 가능성을 미확정으로 남긴다.
- **끝 경계:** 031의 라벨은 마지막 프레임까지 연결되며 해당 추출 화면은 검정이다. 디코딩 성공이 의미 있는 사건 끝을 보장하지 않는다. 검은 화면의 시작 시각은 이번 희소 추출로 확정하지 않았다.
- **카메라 필드:** 45개 `cctv_distribution` 값 모두 각각 파일 stem과 같다. 서로 다른 값 45개를 독립 물리 카메라 45대로 해석하면 안 된다.
- 기존 manifest의 `official_json_matched=false`는 최초 영상 단독 검사 상태다. 최신 실제 라벨 대조 결과는 별도 `label_audit.json`/`label_sample_audit.json`에 보관하며 원문 주석을 Git에 올리지 않는다.

## 5. 평가 적합성과 정상 구간

**카메라 누수:** 013/039/045는 노면 표시·문·현수막·건물 배치상 같은 구도 그룹 후보다. 나머지 6개와 합쳐 7개 시각 구도 후보지만 독립 장소 7개가 아니다. 9개 소스 해시는 서로 다르며 카메라 독립성을 입증하지 않는다. Training 자료만 검사했고 공식 Validation의 중복은 미검사다. 파일별 랜덤 분할 대신 camera/site/session 그룹 검수가 선행돼야 한다.

**경계 설정:** 고정 CCTV의 문/울타리/줄에 카메라별 ROI·선을 지정할 단서는 있다. 그러나 004의 낮은 줄 통과와 030의 문 넘기, 031의 울타리 시도는 별도 행동이다. 이미지상의 선 통과만으로 물리적 넘기 완료를 판정할 수 없다. 013/039/045의 현수막 가림, 021의 그늘, 031의 원거리 사람·차량 가림을 실패 조건으로 남긴다. ROI나 모델은 아직 구현하지 않았다.

**비이벤트 검수 완료 0개:** 이전 희소 관찰 후보 001 0~40초, 007 5~40초, 030 105~150초는 이번 JSON 이벤트와 겹치지 않는다. 하지만 라벨 밖 행동의 누락·가림을 배제하지 못하므로 정상 gold가 아니다. 사용자 연속 재생으로 `event / verified_non_event / unreviewed`를 구분한 뒤 검수 완료 시간만 오탐 평가 분모로 사용해야 한다.

**판정:** 사건 후보 시각을 찾아 사람이 검토하는 연구에는 Conditional Go. 새로운 카메라에서의 일반화, 사람별 정확한 사건 탐지, 시간당 오탐 평가를 바로 주장할 근거는 부족하다. 메인 데이터 채택·모델 선택은 사용자 의미 검수 후 결정한다.

## 6. 재현과 문제 해결

Python 3.10.12 / WSL2 Linux 6.6.87.2 / FFmpeg 7.0.2 / imageio-ffmpeg 0.6.0 / Pillow 12.3.0. 기존 감사 의존성을 재사용했다.

```bash
# 새 환경에서 기존 8개부터 재현
uv run --no-project --with imageio-ffmpeg==0.6.0 --with pillow==12.3.0 python scripts/audit_aihub_intrusion.py
# 기존 manifest를 보존하고 031만 추가 (누적 최대 10개)
uv run --no-project --with imageio-ffmpeg==0.6.0 --with pillow==12.3.0 python scripts/audit_aihub_intrusion.py --ids 031 --append
# 45개 라벨 구조 검사 + manifest의 9개 원본 PTS 대조/근거 프레임 추출
uv run --no-project --with imageio-ffmpeg==0.6.0 --with pillow==12.3.0 python scripts/audit_aihub_intrusion_labels.py
```

- 실행 결과: 9개/12구간 연결, 83개 선택 프레임의 수와 PTS 일치 검사 성공. FFmpeg 오류 시 중단한다. 각 전체 영상 디코딩 수는 최초 manifest에 보존한다.
- `--append`는 표본 추가 시 앞선 결과가 덮어써지는 문제를 해결한다. run.json은 마지막 영상 검사 실행, manifest는 누적 검사 결과다.
- 공개 페이지 예시만 보던 상태에서 실제 로컬 JSON으로 전환했다. 이전 004의 28~45초 관찰과 공식 이벤트 60~62초를 분리해 잘못된 의미 연결을 방지했다.
- 이전 공개 페이지 JSON 파싱은 non-breaking space 정규화로 해결했다. 원문·이전 실행 로그는 로컬 보존.
- `data/aihub_intrusion_audit/`의 manifest, native PTS, label_audit, label_sample_audit, previews/details/label_previews, 실행 코드 SHA·기준 커밋은 로컬 전용. 원본 TL/TS 폴더 유지. Git에는 이 요약과 스크립트만 반영한다.
