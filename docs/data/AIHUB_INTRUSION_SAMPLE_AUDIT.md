## 1. 접근과 기존 로컬 자료

`data/TS_침입/`에서 `E01_001.mp4`~`E01_045.mp4` **45개, 총 2,590,961,985 bytes**를 발견했다. 원본을 복사·수정하거나 추가 다운로드하지 않고 재사용했다. 이번 전체 디코딩 대상은 그중 8개이며 45개 전체 시각 감사가 아니다.

프로젝트 `data/`에서 대응 `E01_*.json`은 발견되지 않았다. 다른 경로/이름의 라벨 파일 존재까지 부정하는 것은 아니다. 사용자에게 별도 라벨 경로와 미리보기 4/7번의 실제 파일명을 요청했으며, 이번 기록 시점에는 아직 답을 받지 못했다.

**다음에 필요한 사용자 동작:**

3. `파일 목록(API 다운로드)`에서 **Training → 라벨링데이터 → TL_침입.zip (파일키 555921)**만 선택해 로컬로 받는다. 영상 45개는 이미 있으므로 전체 데이터/원천 ZIP을 다시 받을 필요가 없다. API를 사용할 경우 공식 안내에 따라 사용자 로컬에서 인증한다.
4. 압축을 로컬 `data/TL_침입/` 등에 풀고 경로를 알려준다. 비밀번호·API키·쿠키는 대화나 Git에 보내지 않는다.

## 4. 실제 JSON 부재와 공개 예시의 제한적 대조

다운로드 JSON과 영상의 1:1 연결은 **0개 완료**다. 공식 페이지가 제공하는 스키마 설명에는 `metadata.file_name`, `width/height`, `frame_count`, `cctv_distribution`, `date`, `night`, `annotations.event_class`, `event_frame`, `event_length`, `event_caption`, `depersonalization`이 있다. 이것을 로컬 전체 라벨 스키마를 검사한 결과라고 보고하지 않는다.

공개 문서 예시는 이름이 같은 로컬 파일과 아래처럼 대조했다. 별도 `page_example_mapping.json`에 **public_page_example_not_downloaded_ground_truth**로 표시했으며 정답 파일을 임의 생성하지 않았다.

| 문서 예시 | 로컬 프레임 수 대조 | 예시 프레임을 로컬 0-based PTS로 변환한 구간 |
| --- | --- | --- |
| E01_021 | 문서 4,171 = 로컬 4,171 | 약 64.233~78.667초 |
| E01_039 | 문서 3,908 = 로컬 3,908 | 약 12.100~33.500, 78.600~117.967, 53.300~76.767초 (문서 배열 순서) |

E01_039의 문서 배열은 시간순이 아니다. 향후 시간 평가에서는 정렬·겹침·종료 포함 여부를 확인해야 한다. 1-based로 읽으면 약 0.033초 앞당겨지며 기준이 확인되지 않아 둘 다 로컬 기록에 남겼다. E01_021의 문서 `event_length=14.83`은 예시 양 끝 PTS 차이 약 14.433초와 다르므로, 파일 라벨·가이드에서 정의를 확인할 필요가 있다. 웹 예시의 오류인지 다른 계산 규칙인지 확정하지 않는다.

문서 예시와 관찰한 인물 이동은 대체로 같은 시기지만 사람별 시작/끝 및 완전한 행동 일치는 미확정이다. 특히 **event_class Invasion/caption 표현을 법적 권한 위반의 정답으로 사용하지 않는다.** 예시 `cctv_distribution` 값도 영상 ID처럼 보이므로 독립 물리 카메라 ID라고 바로 사용하면 안 된다.

## 5. 카메라 중복·경계선·비이벤트 구간

**중복:** E01_013/039/045는 황색 노면 표시·출입문·현수막·맞은편 건물 위치가 매우 유사해 같은 시점/카메라 그룹 후보로 묶는다. 나머지 5개는 구도상 별도 그룹 후보로 볼 수 있지만 서로 다른 학교/장소인지 확인하지 못했다. 총 **6개 시각 구도 후보**, 확정된 6개 독립 장소가 아니다. 샘플의 파일 해시는 서로 다르지만 카메라 독립성을 의미하지 않는다.

현재 원천은 `TS_침입` 폴더뿐이다. 공식 Validation의 카메라 중복 여부도 미검사다. 한 파일의 인접 프레임을 train/test에 나누지 않고, 013/039/045를 같은 그룹으로 취급한 뒤 장소·촬영 세션까지 확인해야 한다. 파일 ID별 무작위 분할로 새 카메라 성능을 주장할 수 없다.

**경계 설정 가능성:** 출입문/펜스의 영상 좌표를 카메라별 지정할 단서는 있다. 다만 문 앞을 평행하게 걷는 사람, 문에 기대기, 들어갔다 나오기, 벽에서 내려오기, 여러 사람 가림을 구분해야 한다. 문/펜스의 이미지상 선과 지면 발 위치의 선은 다르므로 가상선 통과가 물리적 넘기와 같지 않다. E01_004의 높은 벽·차량 가림과 E01_039의 왕복 동작은 단순 2D 선 규칙의 검증 사례 후보이다. ROI를 실제 확정하거나 CV 모델을 실행하지 않았다.

**비이벤트 후보:** E01_001 0~40초, E01_007 5~40초, E01_030 105~150초는 희소 관찰 시 출입문 넘기가 보이지 않는 후보 구간이다. 경계 밖 차량/보행도 포함될 수 있다. **검수 완료 정상 구간은 0개**이며 이 시간 전체를 정상 gold로 선언하지 않는다. 5초 사이의 짧은 사건·가림을 놓칠 수 있으므로 JSON 확보 후 전체 연속 재생으로 `event / verified_non_event / unreviewed`를 나누고 오탐 평가의 분모는 검수 완료 시간만 사용한다.

**희귀 유형:** 사용자 미리보기 4번 줄 넘기·7번 공원 울타리 넘기는 별도 검수 항목이다. 실제 파일명 대응이 없어서 이번 표본에 포함됐다고 주장하지 않는다. E01_004/007 번호로 대체하지 않았다. 파일명 확인 후 총 10개 이내 범위에서 최대 2개 추가 감사할 수 있다.

- 공개 JSON 예시 파싱 중 HTML의 non-breaking space 때문에 JSONDecodeError가 발생해 일반 공백으로 정규화 후 재검증 성공. 원본 페이지는 로컬에 보존.
- `data/aihub_intrusion_audit/`에 inventory, manifest, run, access/report, page_example_mapping, previews/details 보관. 원본은 기존 `data/TS_침입/` 유지. 모든 미디어·주석 원문·웹 응답 Git 제외.
- 코드 해시는 run/supplement_run에 기록. 외부 데이터 다운로드·인증 파일 접근·모델 학습/추론·서비스 구현 없음. FPS는 영상 메타데이터이며 모델 처리 속도가 아니다.
