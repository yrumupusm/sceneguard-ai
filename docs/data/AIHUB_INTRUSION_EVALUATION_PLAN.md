# AI-Hub 평가 데이터 구성안

- 2026-10-27 / 설계안. [사용자 검수 기록](AIHUB_INTRUSION_USER_REVIEW.md), [baseline 설계](../design/CV_BASELINE.md).
- 현재 10개는 반복 관찰하며 설계에 사용한 **개발·감사 표본**이다. 미리 보지 않은 최종 테스트셋이라고 주장하지 않는다. 공식 Training/Validation 명칭만으로 카메라 독립성이 보장되지 않는다.

## 데이터의 세 층

1. **공식 라벨:** 로컬 원문·SHA256·원본 프레임 번호·인덱스 기준 불확실성 유지. 평가 입력과 물리적으로 분리하고 모델에 caption/event_frame을 제공하지 않는다.
2. **사용자 검수:** 원문 변경 없이 별도 로컬 레코드에 출처·검수자·시각·행동 의미·불확실성을 기록. Git에는 비식별 요약/스키마/구성안만 게시한다.
3. **평가 manifest:** 승인된 검수 버전의 일부를 고정해 포함/제외 사유·분할 그룹·시간 마스크·해시를 저장. 후보/미검수 구간은 정답으로 사용하지 않는다.

별도 검수 레코드 필드 제안: `video_id, video_sha256, official_label_sha256, review_version, reviewer, reviewed_at, timebase=original_pts_seconds, boundary_id, subject_local_id, first_visible, boundary_contact, climb_start, crossing_complete, completion_status, censored_at, reviewed_windows, non_event_windows, uncertain_windows, evidence_scope, camera_group, site_group, split_role`.

시각은 확정값 또는 `[earliest,latest]` 불확실 범위, 모르면 null. `subject_local_id`는 영상 내부 임시 번호이며 실제 신원을 뜻하지 않는다. 완료 상태는 completed/incomplete_at_clip_end/occluded_unknown으로 구분. 레코드 검수 범위 밖은 기본 unreviewed다.

## 현재 표본의 역할

| 표본 | 구성 역할 | 정량 평가에 넣기 전 조건 |
| --- | --- | --- |
| 001/007/030 | 등장→접근→넘기 구분 및 지연 정의 개발 | 사건 주체별 시작·통과 시각 확정 |
| 004 | 낮은 줄 통과의 별도 사례 | 물리적 울타리 넘기와 다른 유형으로 유지; 단독 사례 일반화 금지 |
| 013/021/039/045 | 가림·복수 사람·나가기/들어가기 사례 | 관측 가능한 사건 단위/완료·불확실 구간 분리 |
| 031 | 접촉·시도·종료 미완료 사례 | 미완료 사람은 완료 recall/종료 오차 분모 제외; 시도 검토 사례로 별도 보고 |
| 006 약 119~132초 | 경계 근처 보행 hard-negative 후보 | 사용자 범위 승인 후 해당 구간만 음성 정답. 현재 후보 1구간/약 13초, verified_non_event 0초 |
| 006 공식 사건 구간 | 프레임 수 불일치 회귀 사례 | 인덱스 대응 해결 전 정밀 공식 시간 지표 제외 |

031 전체를 음성으로 취급하지 않는다. 완료한 사람이 별도 검수되면 그 사건만 양성으로 포함 가능하다. 라벨 밖 모든 구간을 음성으로 생성하지 않는다. 시간당 오탐은 검수된 음성 시간만 분모로 쓰며 13초에서 FP 1개면 약 277회/시간으로 환산돼 불안정하므로 원시 FP/초를 우선 보고한다. 0 FP도 운영 안전성의 근거가 아니다.

## 카메라·장소 누수 방지

시각 근거에 따른 **보수적 묶음 후보**:

| 그룹 | 영상 | 근거 / 제약 |
| --- | --- | --- |
| C1 | 001 | 높은 시점·청록 출입문; 다른 학교 구도와 같은 장소 가능성 미해결 |
| C2 | 004 | 주택가 차량·낮은 줄 경계 |
| C3 | **006,007** | 도로 모서리, 같은 문·기둥·경사 노면·안내판 배치. 이번 신규 중복 후보 |
| C4 | **013,039,045** | 같은 노란 노면·현수막·문·맞은편 배경 |
| C5 | 021 | 내려다보는 그늘진 도로·문 구도 |
| C6 | 030 | 정면 접이식 출입문·나뭇가지 가림 |
| C7 | 031 | 도로 옆 울타리·나무·주차 차량 |

7개 구도 후보는 독립 장소 7개가 아니다. `cctv_distribution`은 파일별 값이므로 독립성 근거로 쓰지 않는다. 장소 연결이 불명확한 학교 구도는 `site_unknown_school` 상위 그룹으로 보수적으로 묶거나 새 카메라 평가에서 제외한다. 향후 같은 장소로 확인되면 **연결된 그룹 전체**를 합친다.

- 동일 파일의 원본·크롭·프레임·전후 구간·같은 사건/촬영 세션은 같은 분할에 귀속. 006 음성과 007 양성을 서로 다른 분할에 넣지 않는다. 013/039/045도 함께 이동한다.
- 현재는 전부 development. 그룹 확인 후 개발 내부에서 group-holdout 진단을 할 수 있지만 최종 blind test로 부르지 않는다. 소량 자료에서 80/20 프레임 랜덤 분할 금지.
- 최종 새 카메라 평가는 추가 확보를 별도 결정한 뒤 미검토 camera/site/session을 잠근다. 공식 Validation도 먼저 중복 검사. 독립 그룹 확보 실패 시 같은 카메라 적용 실험으로 주장 범위를 제한한다.
- 새 카메라의 정적 배경으로 경계 설정은 허용하되 라벨·사건 동작을 보며 선/임계값을 조정하지 않는다. 설정용 배경 구간과 평가 시간은 분리. 공통 임계값은 개발에서 고정, 평가 후 튜닝하면 새 버전/새 테스트 필요.
- 분할 manifest에는 파일/그룹/역할/설정 구간/검수 버전/해시/제외 사유를 기록하고 자동으로 그룹 교집합·시간 중복을 검사하는 것을 다음 구현 전 검증 과제로 둔다. 이번에 평가 파이프라인은 구현하지 않았다.

## 승인 순서

정밀 의미 검수 → 006 후보 범위 확정·추가 음성 시간 필요량 결정 → camera/site 그룹 확정 → 평가 manifest/매칭 규칙 동결 → 모델/라이선스/환경 선택 → 최소 baseline 구현 승인. 현재 문서는 설계 완료이며 데이터 최종 승인·모델 성능 검증은 아니다.
