# AI-Hub 침입 사용자 검수 기록 — 공식 라벨과 분리

- 날짜: 2026-10-27. 기준 커밋 `282b1ddb4fb9ac98b45a5a0f1b062fa193919f46`.
- 근거: 사용자의 이번 영상 검수 메시지 + 로컬 원본/JSON 대조. [기존 감사](AIHUB_INTRUSION_SAMPLE_AUDIT.md).
- 상태: 사용자 관찰 반영 완료, 정확한 사람별 시작 프레임·평가 정답 확정은 일부 미완료. 공식 JSON은 수정하지 않았다.
- **출처 구분:** 아래 사용자 관찰은 사용자 검수 결과다. Codex의 약 1초 간격 추출 프레임 확인은 연속 재생 검수를 대체하지 않는다. 숫자로 주어지지 않은 사용자 시점을 임의로 정밀 정답화하지 않는다.

## 1. 등장·접촉·넘기 시작·완료를 구분

`first_visible`는 해당 사람이 처음 식별 가능한 시각, `boundary_contact`는 경계 접촉, `climb_start`는 몸을 올리거나 다리를 걸쳐 넘기를 시작하는 관찰 시각, `crossing_complete`는 반대편 이동/착지가 확인된 시각이다. 단순 접근·서 있기·접촉은 넘기 시작과 같지 않다. 사람별 식별이 불가능하면 null/uncertain으로 남기며 공식 이벤트 시작으로 채우지 않는다.

| 영상 | 사용자 검수 반영 | Codex 로컬 관찰 | 공식 구간과의 관계 / 평가 처리 |
| --- | --- | --- | --- |
| E01_001 | 첫 등장과 실제 넘기 시작을 분리 | 45~50초 부근 접근 인물이 보이고 50초에는 문 앞 사람을 확인. 61~65초에는 몸을 문 위로 올리는 자세 변화. 최초 등장 프레임과 사람별 시작은 미확정 | 공식 시작 60.867초(0-based 가정). 등장 시각을 사건 시작으로 사용하지 않는다. `first_visible`, `climb_start`는 별도 필드로 보관하고 정밀값은 사용자 추가 검수 후 확정 |
| E01_007 | 첫 등장과 실제 넘기 시작을 분리 | 49초 화면 아래에 인물 일부, 50초 두 사람이 보행. 이후 문 앞 접근/대기, 64~66초 들어 올리는 자세 변화 | 공식 시작 63.100초. 첫 등장은 희소 관찰상 48~50초 재검수 범위이며 공식 시작과 약 14초 차이. 이 차이를 곧 라벨 오류나 탐지 지연으로 해석하지 않음 |
| E01_030 | 첫 등장과 실제 넘기 시작을 분리 | 기본 미리보기 15초에 전경 보행자가 보임. 50~85초 문 주변 접근/대기, 88~90초 문에 몸을 올리는 변화 | 공식 시작 88.933초. 초반 보행자와 후반 사건 주체의 동일성은 미확정. 전체 화면의 첫 사람 등장과 사건 주체의 first_visible도 구분 |
| E01_031 | 약 33초 울타리 접촉과 공식 이벤트 시작을 분리. **영상 종료까지 모든 사람의 넘기가 완료되지 않음** | 30~46초 인물의 울타리 근처 동작은 확인되나 원거리·차량 가림으로 손 접촉의 정밀 프레임 확정은 어려움. 115~120초에도 경계 근처 사람이 보임. 기존 120.167초 추출은 검정 | 사용자 접촉 약 33초 vs 공식 시작 43.600초: 약 10.6초 차이. 접촉을 공식 시작으로 덮어쓰지 않음. 집단 전체 `all_completed=false`; 미완료 주체는 종료 시점 관측 중단(right-censored), 실제 완료 시각 null. 일부 사람의 완료까지 부정하지 않음 |

001/007/030의 공식 시각은 실제 PTS에 연결됐지만 0/1-based 기준은 미확정이다. 위 자세 변화 관찰 범위는 정밀 ground truth가 아니다. 031의 사용자 관찰은 공식 종료가 **모든 사람의 행동 완료**를 뜻하지 않는다는 근거다. 미완료·가림·완료를 분리하고 검은 프레임/컨테이너 종료를 완료 정답으로 쓰지 않는다.

## 2. E01_006 비이벤트 후보 검증

**사용자 관찰:** 약 119~132초에 경계 가까이를 통행하지만 넘지 않는다. 범위는 사용자가 제안한 비이벤트 **후보**로 유지한다.

**로컬 실측:** 새로 감사한 원본은 1920×1080, 표시 FPS 29.97, 컨테이너 133.67초, 전체 디코딩 4,006프레임(FFmpeg -xerror 성공). 기존 9개에 추가해 감사 표본 총 10개이며 전체 원본 프레임 합계 40,524개, 컨테이너 길이 합계 1,351.02초다. 신규 다운로드 없음.

- JSON `file_name`·해상도는 일치하지만 `frame_count=4011`과 실제 4006이 **5프레임 다름**. 디코딩 PTS에는 82.015267→82.082000초의 약 0.066733초 간격도 있다. 이 간격 하나로 5프레임 차이의 원인을 단정하지 않는다. 30fps 일괄 나눗셈은 부적절하다.
- 공식 이벤트는 프레임 1978~2157. 디코딩 인덱스에 잠정 연결하면 0-based **65.999~71.972초**, 1-based **65.966~71.939초**. 프레임 수 불일치로 정확한 대응 보증은 보류한다. 원 JSON 보존, 자동 보정 금지.
- 64~74초 근거 프레임에서는 가까운 출입구의 넘기 동작 후보가 보인다. 117~133.67초 추출에서는 먼 쪽 경계 인근의 보행이 보이며, **추출 시점에서 넘기는 관찰되지 않음**. 사용자가 제시한 후기 비이벤트와 초반 공식 사건이 다른 구간이라는 해석을 뒷받침한다.
- 검수 요청 범위를 평가 설계상 `[119,132)`초로 표현하면 원본 PTS에 속하는 프레임은 **390개**, 디코딩 0-based index **3566~3955**, 실제 첫/끝 PTS **119.018900~131.998533초**다. 이는 사용자 대략 범위의 기계적 매핑이며 정확한 음성 정답 경계 승인이 아니다. 다음 프레임 PTS는 132.031900초.
- 전체 13초를 자동 정상화하지 않는다. 상태는 `user_reviewed_non_event_candidate`, 근거는 사용자 관찰 + 희소 프레임 대조. 정확한 범위·감시 경계·모든 보이는 사람의 검수 범위가 확정돼야 `verified_non_event`로 승격한다. 앞뒤를 포함한 006 전체를 정상으로 지정하지 않는다.

## 3. 재현과 무결성

```bash
uv run --no-project --with imageio-ffmpeg==0.6.0 --with pillow==12.3.0 python scripts/audit_aihub_intrusion.py --ids 006 --append
uv run --no-project --with imageio-ffmpeg==0.6.0 --with pillow==12.3.0 python scripts/review_aihub_intrusion_windows.py
```

Python 3.10.12, FFmpeg 7.0.2, WSL2 Linux 6.6.87.2, 기존 imageio-ffmpeg 0.6.0/Pillow 12.3.0 재사용. 모델·GPU 추론·학습·가중치 다운로드 없음.

- 5개 영상의 지정 창에서 **112개** 근거 프레임을 추출하고 개수·원본 PTS 일치를 검사했다. 모든 추출 프레임을 연속 동영상으로 봤다는 뜻은 아니다.
- JSON 45개 검사 전후 SHA256 동일, 표본 원본 10개 SHA256 기존 manifest와 동일. 원본 및 공식 라벨 무변경 확인.
- 원본·정답·근거 이미지는 `data/`에만 보관. `data/aihub_intrusion_audit/user_review/run.json`에 코드 SHA·기준 커밋·선택 시각·잠정 라벨 연결·불일치 상태 기록.
- 기존 `audit_aihub_intrusion_labels.py`는 프레임 수 불일치 시 중단하는 엄격 검사다. 이번 006은 별도 검수 스크립트에서 불일치 상태를 명시해 근거를 추출했다. 기존 9개 라벨 검사 결과를 10개 모두 성공으로 바꾸지 않는다.

## 4. 다음 검수

3. 006의 `[119,132)` 범위·해당 경계를 확인하고, 실제 FPS/프레임 수가 원 배포 영상과 다른 이유를 조사한다. 비이벤트 범위는 PTS로 검수 가능하지만 공식 사건 프레임 대응과 별개의 승인 사항이다.
