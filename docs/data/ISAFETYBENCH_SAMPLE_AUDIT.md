# Phase 1B — iSafetyBench 사고 영상 검토 지원 적합성 감사

- 날짜 / 담당: 2026-10-27 / Codex. **사용자 영상 의미 검수·G1B 승인은 대기 중**.
- 작업: [Issue #1](https://github.com/yrumupusm/sceneguard-ai/issues/1), [CODEX_NEXT_TASK](../CODEX_NEXT_TASK.md), [ADR-0003](../decisions/ADR-0003-incident-review-product-direction.md).
- 상태: 공식 어노테이션 1,100개 구조 검사, 영상 **8개만 다운로드·전체 디코딩**, 추출 프레임 시각 감사 완료. 모델 선정·구현·추론·학습은 수행하지 않았다.
- **추천: Conditional Go — 비상업 로컬 연구에서, 사람이 주석·근거 구간을 보정하는 사고 클립 검토 과제로 한정.** 미검수 정답을 그대로 사용한 사고 여부 판정, 상용 활용·미디어 재배포, 실시간 예방 검증은 현재 근거로 진행할 수 없다. 메인 데이터 최종 채택은 사용자 결정 사항이다.

**논문 보고:** 사람이 caption을 작성하고 Gemini 2.5 Pro가 제안한 태그를 사람이 검토·수정했다. 따라서 배포 주석은 연구팀 검수 라벨이지만, 모든 시각적 의미가 오류 없이 보장된다고 가정하지 않는다. 이 설명은 논문 저자의 보고이며 SceneGuard 자체 주석 작업이 아니다.

**배포 조건:** 출처 표시·비상업·동일조건변경허락이 명시되어 있다. 배포자는 YouTube 소유권을 주장하지 않고 공정 이용 목적을 설명한다. 이는 원저작권자의 개별 허가나 법적 판단이 아니다. 이번 작업은 로컬 비상업 연구 감사이며 원본 다운로드 경로·주석 원문·미디어는 `data/`에만 보관했다. 이 문서의 데이터 주석 요약은 위 연구팀 자료를 출처로 하며, 번역·축약 및 Codex 관찰을 추가한 것이다. 데이터 주석에 기초한 부분은 해당 CC BY-NC-SA 4.0 조건을 따른다. 영상은 공개하지 않는다.

**미확인 권리:** 샘플별 원 업로더 라이선스·동의·상업 사용 허가·재게시 권리는 검증하지 못했다. 특히 N4의 미리보기 워터마크는 공개 데모 전 별도 확인이 필요한 구체적 단서다. 향후 유료/상업 서비스나 포트폴리오 미디어 게시에는 권리 확보된 별도 영상 또는 권리자 확인이 필요하다.

CVF 원문 URL은 이번 웹 접근에서 HTTP 403으로 실패했다. 공식 HF 카드가 연결한 arXiv v1 HTML로 연구 방법을 확인했다. 영상 및 주석은 인증 없이 개별 접근 가능했다. YouTube 원본 자체는 내려받지 않았다.

## 3. 실제 어노테이션 구조·평가 단위

`annotations_*.json`은 리스트이며 **모든 1,100개 레코드의 키는 정확히 `video_name`, `caption`, `gt_actions` 세 개**다. 영상명은 각 그룹 내 유일하며 빈 caption/행동 목록, 미등록 taxonomy 태그, HF 영상 목록과의 불일치는 없었다.

| 필드/정보 | 실제 제공 형태 | 해석 제한 |
| --- | --- | --- |
| 영상 ID | `video_name` 문자열과 HF `{normal,hazard}/<video_name>` | 파일명 전체와 그룹으로 연결. `_trim_N`의 N을 시간으로 쓰지 않음 |
| 정상/위험 | JSON 파일·HF 폴더 구분 | 레코드의 별도 `label` 필드는 없음. 안전 등급/사고 발생 정답과 동일하지 않음 |
| 복수 행동 | `gt_actions` 문자열 리스트 | 대상 사람/물체 및 행동별 구간을 구분하지 않음 |
| 설명 | 영상별 자유 문장 `caption` | 관찰·의도·원인 추론이 섞일 수 있음. 검토용 참조이지 자동 보고서 정답 아님 |
| train/validation/test | **검사한 공식 파일·tree에 없음** | Hub 자동 뷰어의 단일 `train` 표시는 독립 평가 split 보장이 아님. 논문은 zero-shot 평가를 설명 |
| 원 출처·촬영일·세션 | **명시적 필드 없음** | 파일명에서 추정하는 YouTube ID 후보만 존재. 화면 타임스탬프의 정확성 미확인 |
| 사건 시작/종료·근거 프레임 | **없음** | 이 문서의 시점은 관찰 후보이며 새 정답으로 승인되지 않음 |
| 객체 박스·추적 ID·책임·부상 정도 | **없음** | 영상 태그를 객체 정답·법적 판단으로 확장하지 않음 |

| 그룹 | 영상 | 태그 종류 | 태그 부여 횟수 | 복수 태그 영상 | 1회만 등장하는 태그 |
| --- | ---: | ---: | ---: | ---: | ---: |
| normal | 680 | 98 | 1,468 | 489 | 13 |
| hazard | 420 | 67 | 888 | 320 | 5 |

`actions.txt`는 JSON이 아니라 두 Python 딕셔너리 할당문이다. 외부 코드를 실행하지 않고 `ast.literal_eval`로 정상 8분류/98태그, 위험 10분류/67태그를 확인했다.

### MCQ 정답과 전체 행동 정답은 다르다

- single: normal 1,468문항 / hazard 888문항. 키는 `video_name`, `chosen_gt_action`, `other_gt_actions`, `choices`, `answer_index`.
- multi: normal 680문항 / hazard 420문항. 키는 `video_name`, `chosen_gt_actions`, `other_gt_actions`, `choices`, `answer_indices`.
- 전 문항의 선택지는 16개. 답 인덱스 범위, 정답 태그 개수, `chosen`과 `other`의 합집합이 주석의 전체 `gt_actions`와 일치하는지 검사했고 구조 오류는 없었다. **선택지 문장의 의미 정확성을 전수 검수한 것은 아니다.**
- multi 90문항에는 선택되지 않은 정답 행동이 별도로 존재한다. 따라서 MCQ 재현 평가는 `chosen_gt_actions`/답 인덱스 기준, 제품의 영상 전체 행동 추출 평가는 별도 검수한 전체 태그 기준으로 설계해야 한다. 두 지표를 직접 같은 성능이라고 비교하지 않는다.

## 4. 소량 샘플 선정·실측

**선정 방식:** 주석을 먼저 읽고 붕괴·선반 낙하·넘어짐·화재 4개, 정상 차량 운용·조립 2개, 정상 그룹에서 의미가 의심스러운 낙상/낙하 2개를 골랐다. 서로 다른 원 출처 후보 8개다. 일부러 모호한 사례를 포함한 목적 표본이므로 데이터 전체 오류율·사고 빈도를 추정할 수 없다. 선정 목록은 스크립트 상수에 고정했다.

**로컬 실측:** MP4 8개 합계 **6,437,874 bytes (6.44 MB)**, 표시 길이 합계 **약 47.02초**, 전체 디코딩 **1,469프레임**. 모두 H.264, FFmpeg 오류 로그 없음. 파일 크기 및 SHA256을 HF LFS 정보와 대조해 모두 일치했다. 영상 전체 1.29GB는 받지 않았다.

기본 약 0.5초 간격+마지막 프레임 **103장**, 모호한 5개 구간에서 약 0.08~0.12초 간격 **62장**을 추출했다(중복 시점 포함). 접촉표와 일부 원해상도 이미지를 Codex가 검토했다. **전체 영상의 모든 프레임을 사람이 연속 재생 검수한 것은 아니다.** 시점은 FFmpeg `showinfo`의 실제 PTS를 저장했으며 아래 시간은 소수 셋째 자리로 반올림한 관찰 근거다. 정확한 사건 경계는 사용자 검수 전 미확정이다.

## 5. 샘플별 공식 라벨 대조와 검토용 기록

아래 설명은 **Codex의 관찰 초안**이며 공식 caption을 무조건 번역한 것이나 사람이 승인한 정답이 아니다. 모든 샘플은 시간 흐름으로 행동을 확인해야 한다. 사고 후 검토·기록용이며 사고 전 예측 성능을 입증하지 않는다. 공식 태그는 그대로 보존하고, 관찰·불확실성은 별도로 기록했다.

### H1 — 구조물 변형·붕괴 시작

- **공식 태그:** `structural collapse`. Caption은 건설 중인 건물 위 작업자들과 붕괴 시작을 설명한다.
- **관찰 초안:** 0~5.377초에 상부 바닥 위 작업자들과 지지대가 보인다. 5.496~5.974초에 왼쪽 지지대가 기울고 상부 바닥이 변형·하강하는 모습이 보인다. 붕괴 시작 태그를 뒷받침하지만 전체 붕괴와 피해 결과는 클립 끝에서 잘린다.
- **근거 후보:** 5.377초의 이전 상태와 5.616/5.974초 비교. 지지 불량·과적 등 원인이나 사상자 수는 알 수 없다.
- **검수:** 어떤 시점을 붕괴 시작으로 삼을지 확인. 초반 약 5초 전체를 붕괴 프레임으로 취급하면 안 된다. 태그·설명은 조건부 활용 가능, 시점은 추가 사람 검수 필요.

### H2 — 지게차 주변 선반·적재물 붕괴

- **공식 태그:** `operating forklift`, `warehouse shelves toppling`, `falling load`, `escaping from danger`.
- **관찰 초안:** 0~4.800초에 창고 통로에서 차량이 이동한다. 4.960~5.960초에는 오른쪽 선반이 기울고 적재물이 떨어지며 먼지가 늘어난다. 차량 운용·선반 붕괴·낙하 근거는 있으나 저해상도와 가림으로 사람이 도망가는 동작은 명확히 확인하지 못했다.
- **근거 후보:** 4.800초와 5.280/5.920초. 누구의 책임인지, 적재량과 붕괴 원인이 무엇인지는 판단할 수 없다.
- **검수:** Caption의 차량/적재물이 원인이라는 인과 서술과 `escaping from danger`의 주체·시점을 보류한다. 도망 장면을 확인하지 못했다는 이유만으로 오라벨이라고 확정하지도 않는다.

### H3 — 상자를 든 사람의 추락과 주변 반응

- **공식 태그:** `carrying object and slipping`, `person falling down`, `rescue effort`, `watching incident passively`, `escaping from danger`.
- **관찰 초안:** 0~3.000초에 사람이 높은 바닥에서 상자를 들고, 3.500~4.000초에 아래 바닥으로 넘어져 떨어진다. 4.600~4.967초에 다른 사람이 오른쪽에서 접근하며 가까이에 작은 체구의 인물도 보인다.
- **근거 후보:** 3.000초의 전 상태, 3.500/4.000초의 추락, 4.800/4.967초의 접근.
- **검수:** 추락은 명확하다. 다가오는 행동을 구조 완료로 해석하지 않는다. 미끄러진 원인·부상 부위는 불명확하다. `escaping from danger`의 주체가 명확하지 않으며, `watching incident passively`도 태도를 단정하지 않고 가까이 서 있는 사람으로 기술한다. 전체 5개 태그가 모두 일치한다고 판단하지 않았다.

### H4 — 화재 반응과 무관한 장면 혼입

- **공식 태그:** `extinguishing fire`, `fire incident`, `escaping from danger`.
- **관찰 초안:** 0~0.501초에 두 사람이 의자 부근에서 급히 벗어난다. 1.001~3.003초에 바닥 불꽃이 보인다. 3.504~6.006초에 한 사람이 불꽃 쪽으로 발을 움직인다. **6.006초는 실내이고 6.507초에는 실외 차량·보행자 장면으로 전환된다.**
- **근거 후보:** 0.501, 1.001, 4.004초. 진화는 시도로 관찰하며 성공·원인은 확정하지 않는다.
- **검수:** 컷 경계를 사람이 확인하고 차량 장면에 화재 태그를 붙이지 않는다. 영상 단위 태그는 일부 구간에 대응하지만 전체 길이를 하나의 사건 설명으로 합치면 부정확하다. 공장 CCTV만으로 구성된 데이터도 아니다.

### N1 — 차량 운용과 화면 확인

- **공식 태그:** `operating industrial vehicle`, `monitoring onboard camera`, `looking at screen`.
- **관찰 초안:** 0~3.500초에 차량 운용·이동, 4.000~5.500초에 운전자와 차내 화면이 보인다. 마지막 5.980초에는 장치 부품 확대 화면으로 바뀐다. 여러 쇼트로 편집된 영상이다.
- **근거 후보:** 1.000, 3.000, 4.500초. 세 태그에 대응하는 시각적 단서가 있다. 화면을 정확히 이해했는지, 올바르게 운전하는지는 판단할 수 없다.
- **검수:** 일반 작업 대조 사례로 활용 가능하나 광고 형태의 구도와 고정 CCTV의 차이를 기록한다. 한 프레임으로 모든 태그를 검증할 수 없다.

### N2 — 소형 부품 조립

- **공식 태그:** `cleaning object`, `assembling electronic components`.
- **관찰 초안:** 0~2.500초에 작업대 위 흰 부품·배선을 손으로 다루고, 4.500~5.967초에 작은 기판/부품을 다룬다. 세로 영상·낮은 해상도에 큰 홍보 문구가 겹친다.
- **근거 후보:** 0.500, 4.500, 5.967초. 조립 단서는 있지만 닦기/청소를 독립된 동작으로 확정하기에는 불명확하다.
- **검수:** 청소 태그의 동작·대상과 caption의 인원수를 확인한다. 두 태그를 모두 맞다고 처리하지 않는다. 일반 작업 설명 검토에는 쓸 수 있으나 CCTV 일반화는 미검증이다.

### N3 — normal 그룹의 실제 넘어짐

- **공식 태그:** `holding object`, `falling down`, `placing object`. Caption에도 통나무를 운반하는 사람의 넘어짐을 기술한다.
- **관찰 초안:** 0.400~0.600초에 파란 옷을 입은 사람이 통나무를 들고, 0.700~1.100초에 몸이 아래로 무너지며, 1.200~1.800초에 바닥 부근에 있다. 주변에서는 통나무를 장치 위에 놓는 동작이 이어진다.
- **근거 후보:** 0.500, 0.900, 1.300초. 실제 태그와 보이는 넘어짐은 부합하지만 그룹명 normal은 사고가 없는 안전 영상이라는 뜻이 아니다.
- **검수:** 넘어지는 사람과 구간을 확인한다. 부상 정도·톱날 접촉·연출인지 실제 사고인지는 알 수 없다. 배포 그룹을 임의로 변경하지 않는다.

### N4 — 사람 넘어짐과 물체 낙하의 의미 차이

- **공식 태그:** `holding object`, `falling down`. Caption은 들고 있던 천 형태의 물체가 손에서 떨어지는 내용을 기술한다. 같은 영상의 single MCQ에서 `falling down` 정답 선택지는 명시적으로 사람이 넘어지는 문장이다. 따라서 단순 번역 차이만이 아니라 caption·화면·MCQ 의미 사이의 불일치 후보다.
- **관찰 초안:** 0~1.000초에 노란 물체를 들고, 1.100~1.600초에 물체가 아래로 떨어진다. 사람은 서서 몸을 굽힌다. 마지막 추출 4.967초에도 서 있다.
- **근거 후보:** 0.900, 1.300, 1.600, 2.000초. 들고 있는 행동은 부합하지만 사람이 넘어졌다는 설명은 관찰과 맞지 않는다.
- **검수:** `falling down`을 사람 동작으로 정의한 평가라면 불일치 후보로 보류해야 한다. 물체 낙하로 표현한 설명 초안을 사람이 승인해야 한다. 큰 미리보기 전용 워터마크가 있어 미디어 권리 추가 확인 대상이다.

## 6. 원 출처 중복·평가 누수

파일명의 `(?:_clip\d+)?_trim_\d+\.mp4`를 제거한 앞부분을 **원 출처 후보**로 집계했다. YouTube API나 실제 원본 영상으로 대조한 것은 아니다.

| 그룹 | 원 출처 후보 | 복수 클립이 있는 후보 | 해당 후보 소속 클립 |
| --- | ---: | ---: | ---: |
| hazard | 76 | 64 | 408 / 420 |
| normal | 75 | 64 | 669 / 680 |

- 합계 151후보 중 `VFCTDVt5B8` 하나는 10글자로 보통의 11글자 ID 형식과 맞지 않는다. 자동 복구하지 않고 미해결로 기록했다.
- `3UVQRVJy9g0_clip0`와 `..._clip1`을 같은 출처 후보로 묶었다. `_trim`만 제거하면 서로 다른 그룹으로 잘못 분리된다.
- normal/hazard 사이 같은 후보 문자열은 없었다. 다만 재게시·편집 영상·다른 ID의 같은 사건은 남아 있을 수 있다.
- 전체 1,100파일의 **공개 LFS SHA256상 완전 동일 파일은 없었다**. 전체 영상을 로컬에 받아 비교한 결과가 아니다. 시간적 중복이나 재인코딩된 유사 영상은 검증하지 못했다.
- H1과 같은 출처 후보의 trim_0/1, trim_2/3은 각각 동일 caption을 갖는다. 이는 메타데이터 반복이며 인접 클립의 픽셀 중복은 미확인이다. H4처럼 한 원본 후보에도 서로 다른 사건이 섞일 수 있다.

**분할 제안(미구현):** 원 출처 후보별로 분리하고, 같은 사건/재게시가 확인된 후보는 더 큰 그룹으로 묶는다. 이번 8개와 같은 출처는 개발·감사용으로 취급해 향후 블라인드 평가와 구분한다. 영상 무작위 분할만으로 독립성을 주장하지 않는다. 공개 웹 영상이므로 모델 사전학습에 포함되었을 가능성도 부정할 수 없다.

### 미래 모델 입력과 정답 분리 설계(미구현)

- **입력:** 라벨과 무관한 불투명 ID, 로컬 영상 참조, 필요한 PTS/해상도만 허용한다. normal/hazard 폴더명·원본 파일명도 프롬프트에 전달하지 않는다.
- **평가:** `gt_actions`, `caption`, normal/hazard, MCQ `answer_index/indices`, `chosen_gt_action(s)`, `other_gt_actions`는 별도 정답 테이블에 격리한다. 추론 로더는 읽지 않는다.
- **MCQ 재현을 별도로 선택할 때:** 공식 문제 선택지만 입력하고 답·정답 유래 메타데이터는 제외한다. 자유서술 사건 분석과 별도 평가 프로토콜로 다룬다.
- **사람 검수:** 제안 태그·근거 후보·불명확한 항목·수정 이력을 저장한다. 이 문서의 Codex 관찰을 자동으로 검수 완료 gold로 승격하지 않는다.
- 이후 구현 시 입력 키 허용 목록, 동일 출처의 평가 경계 침범 여부, 예측 저장 후 정답 접근을 검증한다. 이번에는 설계 문서만 작성했다.
