# 최신 승인 — SceneGuard MVP 1.0 마무리

사용자는 EXP-0049의 007·030 비교 영상을 직접 제공한 뒤 현재 사건 관리 방식을 최종 후보로 선택했고, **“좋아. 마무리까지 가보자”**라고 승인했다. [CODEX_MVP_FINISH.md](CODEX_MVP_FINISH.md)를 따라 통합·검증·기본 시연·문서까지 마무리한다. 더 많은 침입 알고리즘 실험을 만드는 작업이 아니다. 이전 기본 적용 보류/추론 금지 문구는 과거 실험 범위다.

준비된 것은 `sceneguard/mvp_pipeline.py`와 연결·입출력·모의 백엔드 시험41개다. 문법 검사/41시험은 통과했지만 실제 전체 저장소 RuleBackend/CCTV/등록/UI는 아직 로컬 검증 전이다. 새 실행기는 원본+검출 결과에서 현재 판정을 생성하며 과거 EXP 실행 결과를 입력으로 필요로 하지 않는다. 소스/설정이 같을 때의 stage 재사용과 과거 결과 재생은 구분한다.

1. 실제 함수 계약을 연결하고 007/030을 단일 CLI로 분석한다. 기존 CPU 특징 계산 및 필요한 기존 큐 FCOS만 사용한다. 모델/학습/문 구역/방향·소실 기준 탐색은 하지 않는다.
2. 새 `viewer-manifest`를 기존 서비스에 등록하는 최소 어댑터/CLI 등록 옵션을 **구현**한다. 검증 뒤 최신 결과를 기본 시연으로 연결하고 이전 보기로 되돌릴 수 있게 한다. 원본/DB/수동 검토/영수증/기존 실험을 보존한다.
3. 경보0의 정상 입력, 실제 시간순 상태, 원본근거 재생·되감기·폴링·재시작·재실행을 확인한다. 기존 보유 자료의 미사용 구간/실제 바깥 이탈이 있으면 고정 설정으로 검증하고 없으면 미검증 제한으로 명시한다. 사례가 없다는 이유로 마무리를 무기한 유보하지 않는다.
4. README·실행 안내·시연 화면·`docs/MVP_V1_RELEASE.md`를 실제 완료 범위에 맞춰 정리한다. 코드/합성시험/API 성공만으로 전체 완료를 선언하지 않는다. 최신 경로 연결이 확인되면 제한된 오프라인 MVP의 1차 완료로 보고한다.
