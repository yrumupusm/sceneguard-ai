# EXP-0032 — 기존 출력의 한계 확인만 (실행 대기 / GPU 확장 중단)

2026-10-30 사용자 최신 지적: **SceneGuard는 기존 사전학습 사람 검출·추적·ReID만으로 '문을 넘는 행동'을 안정적으로 판정하지 못했다.** EXP-0026의 소규모 사람 검출 fine-tuning도 실제 월장 프레임을 복원하지 못했다. 이 사실은 모든 추가 학습이 불가능하거나 반드시 필요하다고 증명한 것은 아니지만, **같은 FCOS 모델로 새 영상만 더 돌리는 것이 행동 판별 개선 실험은 아니다.**

따라서 이전 지시서의 **E01_001 신규 FCOS 추론, C1 ROI 신규 설정, GPU 큐 작업, E01_006/031 신규 replay, 평가용 영상 범위 확대를 모두 취소**한다. 새 모델 학습도 자동 시작하지 않는다. 이전 문서는 Git 이력으로만 보존하고 본문이 최신 명령이다.

## 현재 GitHub 코드의 상태

- `sceneguard/incident_evaluation.py`와 `tests/test_incident_evaluation.py`는 **평가기와 합성 테스트 소스**이며, 실제 로컬 평가 실행·행동 성능 개선의 완료 근거가 아니다.
- `configs/exp0032_incident_windows.json`은 기존 EXP-0030 결과가 존재하는 **E01_007 48~105초, E01_030 84~100초**만 남긴 범위다. 기존 gap event 파일을 읽는 것으로 한정한다. 원본/기존 결과/영역 모두 변경하지 않는다.
- 사용자 확인한 007 [48,52.5) 정상 접근, [52.5,57.5) 정상 접근, [62.5,67.5) 넘기 시도/진행 창만 제한적 정량 분모에 넣는다. 그 뒤 70.133초 후보는 **확인된 62.5~67.5초 창 밖의 나중 후보**라서 사건 전체를 검출했다고 말하거나 반대로 전체 월장을 놓쳤다고 단정하면 안 된다.
- 030의 공식 참고 월장 [88.933,96.933)과 007의 후기 계속되는 월장 추정 창은 정밀 검수되지 않은 provisional 자료로 유지한다.

## 현재 승인 범위와 의사결정

이번 사용자 메시지는 **평가를 같은 검출기로 확대하는 방향에 대한 정당한 지적**이다. 새 GPU 추론·다른 카메라 확대·지속적인 임계값 실험을 시작하지 않는다. 필요하면 *이미 있는 출력만* 대상으로 평가기를 한 번 실행해 한계를 기록할 수 있지만, 이것이 행동 학습 개선이 아님을 분명히 하고 별도 승인 없이 새 Orca Run/큐 작업을 만들지 않는다.

**성능 개선을 다시 추진하려면 기술 방향을 바꿔야 한다.** 기존 FCOS 사람 bbox+ReID의 파라미터만 바꾸지 말고, **고정 카메라의 경계 주변 원본 짧은 영상(사람을 먼저 검출하지 않아도 됨)을 입력으로 '접근만 / 경계 접촉 / 실제 몸·다리 올림 또는 월장 시도 / 완료 불명'을 구분하는 동작 중심 접근**을 연구한다. 기존 45개 AI-Hub 영상과 원본 사용자 검수·공식 라벨에서, *사건 시작과 접근*을 구분한 짧은 클립 라벨부터 마련해야 한다. 공식 이벤트 범위는 정확한 행동 발생 시각 정답이 아니며, 같은 카메라 분할 누수(006/007 등)를 피한다. 완전한 물리 통과·정체 재식별과 시도 감지는 별도 목표다.

과거 EXP-0026의 Roboflow 소량 사람 검출 재학습을 되풀이하지 않는다. 이후 사용자 명시적 승인 없이 새로운 비디오 인식 모델·학습을 자동 시작하거나 0032 완료를 주장하지 않는다.
