# EXP-0043 — 누락 원인을 분리하고, 근거 있는 한 가지 수정까지 비교

2026-11-01 최신 사용자 승인: 실제로 쓸 수 있는 침입 의심을 개선한다. 새 기법을 또 나열하지 말고 **007 64–74초에서 필요한 움직임을 못 얻었는지, 얻고도 판단하지 못했는지** 확인한 뒤 그 원인에 맞는 제한된 수정을 비교한다. 이 승인은 이전 실험의 종료 문구보다 최신 작업 범위다.

## 이번에 준비된 코드와 실제 완료 범위

- `sceneguard/transition_diagnostics.py`: EXP-0042 저장 근거 전체를 읽어 모든 시작창의 점수 두 경로를 독립 산술로 재현하고, 기존 누적/쿨다운의 후보 시각을 대조한다. 원본 점의 영구 ID·참조시각과 현재 검출 겹침도 보여준다. 검출 박스 겹침은 사람 정답이 아니다.
- `tests/test_transition_diagnostics.py`: 작성 환경에서 표준 라이브러리 합성/파일 입출력 시험 36개 통과. 실제 CCTV 저장 파일, 전체 저장소 회귀, 웹, 원본 영상 의미 검수는 아직 미수행이다.
- 이번 커밋은 **진단 실행기와 후속 수정 절차**다. 검출 성능을 바꾼 코드, 실제 CCTV 결과, 새 침입 후보가 이미 만들어졌다고 보고하지 않는다. 현재 MVP와 EXP-0042는 그대로다.

## 이미 확인한 수식상의 단서

기존 `cue_metrics()`의 국소 변화 경로는 다음과 같다.

`proximity * upward * (.55*deformation + .25*change + .20*progress) * quality`

EXP-0042 보고서의 65.066667초 대표값(반올림값)에서 proximity=.6173, upward=.7778이므로, 두 값만 곱해도 약 .480이다. 나머지 항의 합이 최대 1이어도 이 **국소 변화 경로**는 .55에 닿지 않는다. 다른 선 통과 경로까지 불가능하다는 뜻이 아니며, 점이 실제 침입 인물을 잘 따라갔다는 뜻도 아니다. `local_ceiling`은 설명용 수학적 상한이지 새 점수/후보가 아니다.

반대로 접근 문맥의 기존 점수는 더 높았다. 곱셈을 합으로 바꾸거나 기준만 낮추면 해결된다고 결론 내리지 않는다. 관측 대상·거리 기준·점수 의미를 먼저 대조한다.

## 1. 기존 저장 자료로 진단 (새 흐름 계산 없음)

로컬 변경을 보존해 최신 main을 반영한다. 기존 Python 환경을 사용한다. 전체 환경을 업그레이드하거나 새 모델을 받지 않는다.

```bash
python3 -m unittest discover -s tests -p 'test_transition_diagnostics.py' -v
python3 -m sceneguard.transition_diagnostics \
  --directory outputs/exp0042/007-v1 --output outputs/exp0043/007-audit-v1 \
  --range approach=52.5:58 --range waiting=58:64 --range missed=64:74
python3 -m sceneguard.transition_diagnostics \
  --directory outputs/exp0042/030-v1 --output outputs/exp0043/030-audit-v1 \
  --range approach=84:89 --range intrusion_context=90:94
```

각 입력은 전체 저장 프레임을 읽고, `--range`는 사후 요약만 제한한다. 시간/ID가 후보 생성 조건에 들어가지 않는다. 경로가 다르면 실제 저장 자료를 찾아 지정한다. 저장 포맷/산술이 안 맞으면 원인을 고쳐 대조하되, 실패를 사람 미탐이나 0개 후보 성공으로 처리하지 않는다.

산출물: `frame-diagnostics.jsonl`, `signals.csv`, `summary.json`, `inspection-plan.json`. 기존 `frame-evidence.jsonl`과 요청/요약/후보·scene의 바이트를 보존한다. 관련 파일만 검증하면 되며, 실험과 무관한 전체 환경/수만 개 파일 재해시를 이번 핵심 작업으로 늘리지 않는다.

## 2. 핵심 누락 구간의 실제 경로를 먼저 읽는다

기존 `outputs/exp0042/007-v1/evidence/core-64-74.mp4`와 원본을 재사용한다. 새 표시가 필요하면 저장 점/원본 픽셀만 재렌더한다. 다음 세 패널을 비교할 수 있게 한다.

- 같은 시각의 원본 문 주변 확대(실제 픽셀, 보간 확대를 새 정보라 하지 않음).
- 모든 살아 있는 시작창의 **현재점과 짧은 과거 경로**, 기존 실제 검출.
- 선택한 시작창 하나의 경로·참조시각·두 점수 경로와 구성값. 최고점 창뿐 아니라 필요한 대상에 붙은 다른 창도 선택 가능하게 한다.

현재 점은 표시하고 궤적은 최근 0.3초 정도로 제한해 오래된 선과 현재 배경점을 구분한다. 색은 사람 신원이 아니라 시작창 구분이다. 특히 65초대에서 필요한 사람 대신 문/다른 사람만 남았는지, 몸 일부의 유효한 움직임이 있는데 최고창 선택/근접도/점수에서 묻혔는지 확인한다. 16창 상한에 닿았다는 사실만으로 해당 사람이 배제됐다고 단정하지 않는다.

007 54/63초와03087/92초의 이미 받은 검수는 재사용한다. 00765초대는 아직 점 경로 품질을 직접 검수하지 않았다는 점을 유지하되, 사용자에게 모든 점의 정체/정확한 시작 프레임/새 박스를 요구하지 않는다. 코드·산술 검토와 영상 의미 판단을 구분하고, 새 사용자 답변 없이 Codex 판독을 사용자 정답이라고 쓰지 않는다.

## 3. 원인 하나에 맞춰 제한된 수정 및 A/B 실행

**진단 표만 생성하고 완료하지 말고**, 아래 중 근거가 있는 원인을 선택해 수정 후보 하나를 구현하고 같은 전체 구간에서 비교한다. 단, 영상 근거가 없는데 새 규칙을 지어내지는 않는다.

A. 관심 대상의 경로가 없거나 배경으로 넘어감: 시작창 배분/중복창/참조 이력 중 실제 원인을 수정한다. 최대창을 무작정 늘리거나 보이는 사람을 수동 지정해 성공으로 만들지 않는다.

B. 관심 대상의 변화가 경로에 있는데 점수 경로에서 놓침: 기하·참조·점수의 어떤 항이 대기/접근과 침입을 거꾸로 취급하는지 설명하고 그 부분만 수정한다. 단순 `0.55→더 낮게`, 특정 영상/시각/ID 예외, ‘선 넘는 픽셀=실제 사람 침입’ 가정은 금지한다. 최소 반례(접근·평행 보행·대기·부분 신체·침입 변화) 시험을 먼저 작성한다. 사람을 잘 추적했다는 사실만으로 침입을 확정하지 않는다.

C. 현재 정보로 두 상황이 구분되지 않음: 어떤 입력/성분이 비슷해서 구분이 안 되는지 실제 경로로 제시한다. 부족한 근거를 수치로 꾸미거나 추가 모델/학습으로 확대하지 않는다. 결과는 ‘수정 근거 부족’이지 ‘개선 성공’이 아니다.

수정은 새 모듈/명시적 비교 모드로 분리하고 기존 EXP-0042·MVP 출력은 덮어쓰지 않는다. 필요한 CPU 원본 특징 재계산과 실패 원인 보정은 허용한다. 새 검출기·ByteTrack·VLM·GPU 학습·자료 수집·수동 박스·사용자 영역 재설정은 하지 않는다. 수정 후 두 기존 선택 구간 **전부**를 같은 규칙으로 실행한다. 새롭고 호환되는 보유 검증 구간이 있으면 설정을 고정한 뒤 확인하되, 없으면 독립 검증 부족을 명시한다.

## 4. 실제 성능을 판단할 표

수정 전/후를 사건 문맥으로 비교한다. 프레임 수나 테스트 수를 정확도 분모로 삼지 않는다.

| 문맥 | 실제로 확인할 것 |
|---|---|
|007 접근·대기|불필요한 새로운 의심과 사건 경보가 늘었는가/줄었는가|
|00764–74초, 특히 침입 시작을 포함한65초대|실제로 필요한 대상의 변화 때문에 새 의심이 생겼는가, 원래70.133초보다 앞선 유효 근거가 있는가|
|030 접근 및90–94초|같은 규칙의 오탐/필요한 의심 유지·조기 근거 여부|
|보유 독립 구간(있을 때)|설정 선택에 쓰지 않은 장면에서도 같은 효과가 있는가|

정확한 시작 프레임은 아직 지정되지 않았다. 후보 PTS의 차이는 저장 영상 시각 비교이며 실제 경보 처리 지연이 아니다. 필요한 장면에서 후보가 늘었어도 접근 후보가 더 늘면 성능 향상으로 단정하지 않는다. 장면 수준 ‘경보가 필요했는가’로 검토하고, 모든 사람의 완벽한 ID 복원을 성공 조건으로 되돌리지 않는다.

후보 생성과 통지 표시를 분리해 보고한다. 새 후보 때문에 기존 90.4초 의심이 앞의 접근 카드에 흡수된 것을 ‘유지 성공’으로 표현하지 않는다. 이번 알고리즘 비교에서는 기존 경보를 보존한 채 새 근거 타임라인을 별도로 보여주고, 제품 통합은 실제 경보 효과 확인 뒤 결정한다. 통지 제외 정책은 사용하지 않는다.

## 전달

기존 담당3에 핵심 누락 구간/점수 설명/수정 전후 결과를 연결한다. 새 서버/대시보드는 만들지 않는다. 모델 추론 성공·저장 점수 재현·영상 의미·웹 재생은 별개로 기록한다. 브라우저가 차단되면 API 확인을 화면 검증으로 대체하지 말고 구분한다. 이미 답한 장면을 반복 질문하지 않는다.

실제 실행 결과·수정 이유·남은 실패를 `docs/experiments/EXP-0043-results.md`에, 전달 사실은 별도 문서에 남기고 코드/비식별 수치만 GitHub에 게시한다. 원본·좌표·경로·DB·인증정보는 로컬 전용이다. 사용자에게는 **어떤 오류를 실제로 고쳤고 경보가 어떻게 달라졌는지** 먼저 보고한다. 개선 근거가 없으면 그대로 밝힌다.
