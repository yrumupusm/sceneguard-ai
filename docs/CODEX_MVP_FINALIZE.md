# SceneGuard 1차 MVP 마무리 작업서

작성 기준: 2026-11-01, `yrumupusm/sceneguard-ai`의 `00dd16ab579bef1c397aa5ab8799ea370ec01a20`.

**이 파일은 최종 통합을 위한 실행 지시서다. 아직 구현·실행·게시 완료 보고서가 아니다.**
사용자는 EXP-0049의 007·030 비교 영상을 확인한 뒤, 현재 방식을 최종 후보로 고정하고 **통합·추가 검증·시연 화면·문서까지 1차 MVP를 마무리**하도록 승인했다.

## 1. 이번 완료 목표

기존 로컬 환경에서 원본 영상과 카메라 설정을 선택하고 한 번 실행하면 다음 흐름이 이어져야 한다.

```text
원본 영상 + 명시적인 카메라/분석 구간
  → 입력과 일치하는 기존 검출 캐시 사용, 없으면 기존 검출 경로
  → 기존 추적·문 주변 관측·영상 특징 이동
  → 침입 의심 / 방향·소실에 따른 자동 확인 또는 의심 해제
  → 현재 문 관측으로 같은 출입구 사건 유지
  → 첫 의심·첫 확인 알림, 근거 영상, 관찰 종료 이력
  → 기존 웹의 기본 MVP 결과에 표시
```

이번에는 실험 번호를 하나 더 늘려 저장 결과 재생 화면만 추가하는 것으로 끝내지 않는다. **최신 규칙이 새 입력에 적용되는 실행 경로**를 만들고, 실제 명령·결과·화면을 확인한다. 새 서버나 프로젝트를 만들지 않고 기존 코드·환경·서비스를 활용한다.

완료 범위는 **고정 카메라의 녹화 영상을 분석하는 로컬 미니 프로젝트**다. 실시간 CCTV 운영, 완벽한 개인 식별, 인원수 계산, 출입 권한·법적 무단침입 판정은 이번 범위가 아니다.

## 2. 유지할 판단과 사용자 요구

- 문 주변에서 먼저 넓게 **침입 의심**을 만들고 이후 관측으로 갱신한다. 초기 단계부터 접근·대기와 침입을 완벽히 분리하려고 조건을 다시 늘리지 않는다.
- **문 근처의 앞선 관측 → 안쪽 이동 → 소실**은 `침입 확인 · 자동`의 근거다. 마지막 부분 박스가 작아지거나 선에서 멀어졌다는 이유로 앞선 문 관측을 버리지 않는다.
- 문 주변의 새 관측은 의심 근거다. 문 구역과 겹치는 첫 박스 하나를 자동 확인으로 만들지 않는다. ‘새 관측’과 ‘다른 새 사람’을 혼동하지 않는다.
- **문·안쪽과 반대되는 방향으로 이동한 뒤 관측이 끊긴 경우**, 연결된 미결 의심을 해제한다. 다른 사람의 이탈로 모든 의심을 지우지 않는다. 이미 확인된 침입은 나중에 밖으로 나갔다고 취소하지 않는다.
- 개인별 신원을 완벽하게 복원하거나 같은 ID를 끝까지 유지하는 것을 사건 판단의 필수 조건으로 만들지 않는다. 동시에 불확실한 연결로 과거 별도 사건까지 확인·해제하지 않는다.
- 한 출입구의 현재 문 관측이 이어지는 동안 사건 하나를 유지한다. 후보 간격이나 기존 10초 제한만으로 쪼개지 않는다.
- 현재 문 관측이 **3초간 없는 경우 관찰만 종료**한다. 이는 의심 해제나 안전 판정이 아니다. 영상 종료·소스 공백을 가짜 빈 프레임으로 채우지 않는다.
- 첫 의심과 첫 확인은 같은 사건에서 각각 한 번만 알린다. 확인 뒤의 후속 관측은 같은 카드에 붙이고 새 의심 카드·반복 확인 경보를 만들지 않는다.
- 사건이 확인됐다고 미결인 개별 근거까지 전부 확인으로 바꾸지 않는다. 자동 상태와 사용자 수동 검토를 분리한다.
- 표시는 `침입 의심 / 침입 확인 / 의심 해제`, 관찰 상태는 `문 주변 관찰 중 / 문 주변 관찰 종료`로 간결하게 한다. `월장`, 세부 신체 동작 분류는 추가하지 않는다.

### 반드시 해소할 실험 경로 의존성

`exp0042/0044/0045/0046/0048/0049`의 실행 래퍼에는 특정 실험 출력, 영상 ID, 로컬 경로, 해시 계약을 전제하는 부분이 있다. **실험 CLI들을 순서대로 수동 실행하거나, 007/030의 과거 결과를 새 입력 결과처럼 읽는 통합은 금지**한다.

기존 순수 처리 함수를 공용 런타임으로 묶고 실험용 입력 검사와 실제 입력 검사를 분리한다. 과거 실험의 불변 검증은 원래 재현용으로 보존한다. 새 입력에 필요한 원본·시간·설정 검증을 삭제하는 것으로 우회하지 않는다.

`replay_scoped()`와 `frozen_schedule()` 등은 현재 비어 있지 않은 후보를 전제하고, 일부 함수는 `events[0]`에서 카메라를 읽는다. **정상 영상/후보 0건도 성공 결과로 반환**하도록 명시적 session/camera/gate 정보를 별도로 전달한다. 후보가 없다고 가짜 의심을 만들거나 실패 처리하지 않는다. 기본 후보는 0건이지만 문 구역 후보는 있는 경우도 처리한다.

실제 새 입력을 처리하면서 중간 산출물에 과거 실험의 출처명을 그대로 붙여 ‘동결된 기존 결과’인 것처럼 표시하지 않는다. 알고리즘 유래와 이번 실행의 입력·출처를 구분한다.

## 4. 구현 범위

### 4.1 하나의 실행 명령과 실행 모드

기존 `video_cards` 진입점을 확장하거나 얇은 최종 진입점 하나로 묶는다. 이미 동작하는 코드를 통째로 다시 쓰지 않는다. 실제 구현된 명령 하나를 README와 완료 보고서에 남긴다.

입력은 원본 영상, 명시적 카메라 설정, 분석 구간 또는 전체 영상, 출력 위치다. 최신 scene/portal 설정은 카메라별 로컬 설정으로 관리한다. 007의 승인된 inside 수정본과 두 카메라의 최종 문 구역을 가져오되 출처를 기록하고, 과거 실험 설정은 덮어쓰지 않는다.

실행 모드를 결과에 구분해서 기록한다.

1. **저장 결과 재생:** 이미 완료된 분석을 화면에 표시한다.
2. **저장 검출 사용 분석:** 입력과 일치하는 검출만 재사용하고 필요한 최신 후처리를 실행한다.
3. **원본 분석:** 캐시가 없으면 기존 검출 모델·추적·영상 특징 계산부터 실행한다.

같은 모델·알고리즘으로 새로운 입력을 처리하는 데 필요한 검출/추적/CPU 특징 계산은 이번 통합 범위에 포함된다. 과거 비교의 ‘새 flow/검출 금지’를 이번 승인에 기계적으로 적용해 새 입력 처리를 막지 않는다. **새 모델 도입·가중치 변경·파인튜닝·새 데이터 수집은 하지 않는다.** 기존 GPU 큐, 리소스 제한과 실행 정책을 그대로 따른다.

동일한 검출/특징 자료가 있으면 source hash·해상도·카메라 설정·모델/전처리·native PTS·선택 범위·관련 코드/정책을 확인해 재사용한다. 관계없는 007/030 캐시로 대체하거나 파일명에서 카메라를 추정하지 않는다. 재실행은 동일 입력·설정·버전에서 완료 단계를 재사용하며, 변경된 실행은 새 출력으로 분리한다.

기존 30fps/C3·C6 등 확인된 지원 범위는 유지해도 된다. 미지원 영상/미설정 카메라는 명확히 안내하고 잘못된 설정으로 실행하지 않는다. 다른 카메라의 영역을 그대로 가져와 지원 범위를 부풀리지 않는다.

### 4.2 근거·화면 연결

현재의 담당3 서비스에 **기본 MVP 보기**를 둔다. 과거 EXP 결과는 비교/개발 메뉴에 남기고, 사용자가 실험 번호를 골라야만 최신 동작을 볼 수 있는 구성을 끝낸다.

최소 화면에는 분석 대상, 진행/완료/실패, 사건 상태, 첫 의심·확인 시각, 원본 근거 재생, 관찰 진행/종료, 수동 검토를 제공한다. 영상 입력은 기존 UI 또는 안내된 단일 CLI로 충분하며 새로운 업로드 시스템을 만들 필요는 없다.

원본·현재 실제 박스·과거 LAST를 명확히 구분한다. 상세 디버그 값은 접어두고 `pending=17` 같은 숫자를 사람 수나 사건 수처럼 보이지 않게 한다. 같은 카드에는 여러 사람의 관측이 들어갈 수 있다.

근거 영상은 최신 사건의 확인과 후속 관찰이 포함되도록 생성한다. 예전 카드 구간의 클립을 그대로 붙여 중요한 장면을 잘라내지 않는다. 원본 PTS와 재생 시간의 연결을 유지한다.

확인·해제·관찰 종료는 해당 시각 이후에만 표시한다. 되감기와 새로고침 시 과거 상태를 복원한다. 반복 로드·서비스 재시작에서 알림 키와 검토 이력을 보존한다. 이번 MVP는 로컬 표시와 알림 의도까지만 확인하고 실제 외부 발송은 활성화하지 않는다.

### 4.3 문서와 시연

README의 기본 실행·기능 설명을 최신 구현으로 바꾸고 이전 EXP-0037 기준 안내는 이력으로 분리한다. 기능을 삭제하지 않고 구버전과 새 기본 실행을 구분한다.

최소 문서는 다음 세 가지면 충분하다. 이미 맞는 문서가 있으면 갱신한다.

- `docs/MVP_QUICKSTART.md`: 실제 실행·중지·재시작·결과 확인·캐시/실행 모드·지원 조건.
- `docs/MVP_VALIDATION.md`: 개발 구간 회귀와 추가 구간을 분리한 결과, 실측 수치와 미검증 항목.
- `docs/MVP_RELEASE.md`: 채택 기능, 변경 파일, 실제 실행 명령, 커밋, 기본 보기, 남은 한계와 복귀 방법.

시연은 ‘문 앞 의심 → 안쪽 이동·소실로 확인 → 반복 관측을 한 사건으로 유지 → 문 관찰 종료 → 일반 보행에는 새 경보 없음’을 중심으로 구성한다. 의심 해제 실사례가 없으면 시연한 것처럼 꾸미지 않는다.

## 5. 실제 검증

### 5.1 개발 구간 회귀

007의 48–105초, 030의 84–100초는 **개발/회귀 구간**이다. 이 구간을 새 출력 경로에서 최종 실행 경로로 처리한다. 입력에 맞는 검출/특징 캐시 재사용은 가능하지만 최종 판단은 현재 입력 흐름에서 이어져야 한다.

EXP-0049의 비교 기준:

| 구간 | 기준 결과 |
|---|---|
| 007 | 사건 1개, 첫 의심 약55.633초, 확인 약72.133초, 관찰 종료 약74.567초. 후반84–104초 일반 통행은 새 의심·사건 재개 없음. |
| 030 | 사건 1개, 첫 의심 약86.033초, 확인 약92.733초. 97초대 후속 관측은 같은 확인 사건에 포함. 약99.967초의 선택 구간 끝에는 관찰 종료 유예 미충족으로 open. |

이 시각들은 **회귀 기대값**이며 판정 코드의 정답·예외 조건으로 넣지 않는다. 원본 프레임/PTS 기준으로 비교한다. 새 session ID 때문에 이벤트 ID가 달라지는 것은 같은 입력 재실행의 안정성과 별도로 설명한다.

두 구간의 최종 파일을 표시하는 것만으로 통합을 검증했다고 쓰지 않는다. 원본 선택부터 최신 결과 등록까지 실제 한 번 연결하고, 같은 명령 재실행의 재사용·중복 방지도 확인한다.

### 5.2 최소 추가 검증

이미 보유한 원본/라벨/기존 목록에서 **규칙 조정에 쓰지 않은 구간**을 먼저 찾는다. 새로운 다운로드·수집·학습용 박스 작업은 요구하지 않는다. 같은 카메라의 미사용 구간도 가능하나 다른 카메라 일반화로 표현하지 않는다.

가능한 범위에서 다음을 각각 확인한다.

- 정상 통행: 불필요한 사건/확인이 생기는지.
- 문에 접근했다가 바깥으로 떠남: 의심이 실제 생겼다면 후속 해제가 적절한지. 처음부터 의심 없는 통행은 해제 성공이 아니다.
- 추가 침입 또는 새 접근: 필요한 의심/확인이 유지되는지, 앞선 종료 사건에 잘못 붙는지.

조건에 맞는 보유 실영상이 없으면 **실제 의심 해제 미검증**으로 명시하고 합성 시험만 별도로 남긴다. 해당 사례를 찾느라 MVP 완료를 무기한 미루거나 007/030에서 해제가 나오도록 규칙을 바꾸지 않는다.

이미 답한 장면은 다시 묻지 않는다. 새 결과가 실제 장면과 어긋나 해석이 필요하면 필요한 짧은 영상만 제시한다. 사용자에게 정밀 ID·사람별 박스 정답을 요구하지 않는다.

사건 정답을 가진 구간은 잡음/놓침/중복/알림 시점을 보고한다. 소수 개발 구간, 반복 프레임, 테스트 개수로 정확도·F1·해제 성공률을 만들어내지 않는다. 처리 시간은 실제 단계별 경과시간과 분석 영상 길이로 제시하되 실시간 운영 성능으로 확대하지 않는다.

### 5.3 소프트웨어·화면 완료 확인

- 후보0건, 검출0건, 기본후보0건+문후보있음, 부분박스, 짧은누락, 소스공백, 영상끝을 처리한다.
- 동일 사건의 의심/확인 알림 각1회, 이후 미결 추가 근거로 재알림 없음, 확인 상태 취소 없음.
- 관찰 종료≠의심 해제. LAST/예측 박스가 관찰 시계를 연장하지 않음.
- 개별 근거 상태를 사건의 확인으로 일괄 덮어쓰지 않음. 미래 근거를 이전 시각에 표시하지 않음.
- 실제 등록 목록에서 기본 보기를 선택해 재생·앞뒤 이동·되감기·자동 갱신·새로고침을 확인한다.
- 서비스 재시작 전후 알림 키·수동 검토/메모·이력·등록을 보존한다.
- 일부 화면 자동화가 시간초과면 API 성공으로 대체하지 말고 미완료 항목을 명시한다. 보기별 짧은 호출로 확인하고 무제한 재시도하지 않는다.

## 6. 완료 기준과 멈출 기준

**1차 MVP 완료에 필요한 항목**

- 최신 방식이 영상 입력에서 결과 화면까지 한 실행 경로로 연결됨.
- 007/030 개발 회귀의 핵심 사건 흐름과 확인 시각을 보존하거나 차이를 원인과 함께 설명함.
- 정상 입력/후보0건 처리, 상태·알림·관찰 종료, 실제 기본 보기 재생이 확인됨.
- 재실행/재시작에서 기존 자료와 수동 검토를 손상하지 않음.
- 실제 실행법·시연 방법·지원 범위·한계가 최신 문서와 일치함.

**미검증으로 남겨도 되는 항목**

별도 보유 실사례가 없는 의심 해제, 다양한 새 카메라/조명에 대한 일반화, 정밀 신원·인원수, 실시간 운영·외부 경보 전달. 미검증을 성공으로 쓰지 않는다. 의심 해제는 실사례 검증 전에는 실험적 자동 판정이라는 상태를 명시한다.

**완료를 막는 문제**

새 입력인데 과거 실험 결과를 대신 보여줌, 후보0건 실패, 필요한 기존 침입 확인 소실, 후보가 미결이라는 이유로 확인 카드가 다시 의심으로 내려감, 같은 사건의 반복 경보, 수동 검토/원본 손상, 기본 결과가 실제 화면에서 열리지 않음. 이런 경우 기능 완료로 포장하지 말고 재현 가능한 결함을 수정한다.

기존 규칙을 또 연구하는 작업으로 확대하지 않는다. 통합 오류는 수정하되 모호한 장면 하나 때문에 새 모델·세부 동작 점수·추가 의무 조건을 도입하지 않는다. 효과가 확인된 현재 규칙을 마무리하는 것이 목적이다.

## 7. 코드·설정·데이터 보존과 게시

로컬 미커밋 변경을 먼저 확인하고 보존한다. 최신 main이 기준보다 앞서 있으면 관련 차이를 읽고 현재 개선을 덮어쓰지 않는다. 과거 ‘기본 MVP 교체 금지/실험 종료’는 당시 범위이며, **이번 승인은 검증 후 최신 기능을 기본 MVP로 채택하는 작업을 포함**한다. 파괴적 초기화, 강제 푸시, 기존 실험/검토 기록 삭제는 승인되지 않았다.

기존 서비스·GPU 큐·검토DB·영수증은 그대로 사용한다. 필요한 설정은 별도 최종 프로필로 두고 기존 버전으로 돌아갈 수 있게 한다. 새 서버/큐/대규모 재감사는 만들지 않는다.

Git에는 코드·문서·공개 가능한 집계만 올린다. 원본 CCTV, 얼굴/개인 식별 가능 캡처, 원시 관측·검토 메모, 모델 파일·캐시·DB·인증정보는 기존 제외 정책을 유지한다. 발표용 실제 이미지를 외부 공개하려면 별도 비식별 검토가 필요하다.

구현·시험·실행·실제 화면·문서가 맞으면 커밋하고 원격 게시를 확인한다. 단순 기능 시험 수와 영상 정확도를 구분한다. 완료 보고에는 **실제로 실행한 명령, 최종 커밋, 기본 화면, 회귀/추가검증 결과, 남은 미검증 항목**만 명확히 남긴다. 이번 승인 범위는 구현부터 게시까지이므로 중간 단계마다 재승인을 묻지 않는다.

## 8. 작업자에게 전달할 마지막 요약

> 새 실험을 늘리지 말고 현재 검증한 규칙을 기본 MVP로 완성한다. 실험 결과 파일 재생이 아니라 영상 입력에서 최신 판정과 사건 관리가 이어져야 한다. 첫 의심/첫 확인은 각1회, 문 관측이 이어지면 사건1개, 3초간 문 관측이 없으면 확인 이력을 유지하며 관찰 종료한다. 기본후보0건과 새 입력도 처리한다. 기존 자료로 가능한 추가 검증을 수행하고 실사례가 없는 해제는 미검증 한계로 남긴다. 기존 화면의 기본 보기·실제 재생·실행법·한계를 정리하고, 실제 실행과 게시까지 완료한다.
