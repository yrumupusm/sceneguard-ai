# EXP-0041 — 사건은 유지하고 불필요한 통지만 줄이기

2026-10-31 최신 사용자 승인. 목표는 **문 앞 접근·대기 경보는 줄이고, 필요한 침입 의심은 유지하는 실제 사용성 개선**이다. 이번에는 새로운 시각 모델이나 특징을 만들지 않고 EXP-0040 저장 점수를 활용한다. 이전 실험 종료 문구보다 이번 사용자 지시가 우선한다.

## 준비와 실행의 구분

기준 main은 `7ab5494321abea56abb69d8fce899af61ecae117`이다. 원격 작성 환경에서 다음 코드를 구현했다.

- `sceneguard/incident_notifications.py`: 전체 후보로 사건을 먼저 묶고, 사건 안에서 통지 대상과 검토 전용 항목을 분리한다.
- `sceneguard/exp0041_application.py`: 저장된 EXP-0040 baseline/감사/점수를 읽어 0.55·0.65·0.70을 비교한다.
- `tests/test_incident_notifications.py`: **CPU 합성 시험 46개 통과**. 원본 사건 모듈과 기존 판정 helper는 기준 main과 동일한 바이트를 사용해 시험했다. 실제 로컬 CCTV 점수파일 적용, 원본 의미 검수, 기존 웹 연결은 아직 실행 전이다. 이 시험 수는 침입 정확도가 아니다.

기존 검출·추적·사용자 영역·의심 생성·점수 가중치·시작점 경로는 그대로다. 기존 모듈/동결 보고서/원본/검토 DB/알림 영수증은 덮어쓰지 않는다. 신규 GPU·VLM·학습·박스/데이터 제작은 없다. VLM은 계속 선택적인 참고 수단이다.

## 핵심 동작

기존 EXP-0040은 통지에서 일부 후보를 제외한 뒤 나머지만 재묶어 카드가 분리됐다. 이번에는 **전체 후보 → 원래 사건 묶음 → 사건 내 통지 여부** 순서다.

- 같은 녹화 세션·카메라·출입구의 직전 후보 간격 3초 / 첫 후보부터 최대 10초는 그대로다. 검토 전용 후보도 사건의 시간 흐름에는 남기므로 중간 항목을 제외해도 사건 ID나 소속이 바뀌지 않는다.
- 첫 후보가 통지 대상이면 그 시각에 바로 알린다. 첫 후보가 검토 전용이고 뒤 후보가 통지 대상이면 **뒤 후보의 실제 판단 시각**에 처음 알린다. 첫 후보 시각으로 소급하지 않는다.
- 모든 후보가 검토 전용이면 경보는 없지만 사건 이력과 원본 근거는 남는다. 이미 통지한 사건은 후속 후보가 검토 전용이어도 경보 이력을 취소하거나 새로운 팝업을 만들지 않는다.
- 한 인물의 관측 연속성으로 다른 인물 또는 별도 경계 근거의 의심을 취소하지 않는다. 기존 `seed_decision`의 경로 충돌 및 `notification_partition`의 별도 경계 근거 보존을 재사용하며 더 엄격한 가림/정지/겹침 차단 조건을 추가하지 않는다.
- 상태는 기존 `침입 의심`을 유지한다. 검토 전용은 통지 정책이지 `침입 아님` 확정이 아니다. 자동 ID 병합/침입 확인은 없다.

사건 묶음은 정답 사건이나 동일인 수가 아니라 검토 단위다. 검토 전용 후보도 묶음을 이어주므로 가까운 다른 상황을 묶을 가능성은 남는다. 기존 최대 10초 범위를 유지하고 이 한계를 결과에 명시한다.

## 세 기준을 비교한다

**0.55를 우선 검토할 실용 후보, 0.65를 중간 비교, 0.70을 기존 기준**으로 둔다. 0.55는 이번 비교 대상이지 자동 채택한 기본값이 아니다. 점수는 관측 연속성의 휴리스틱이며 침입 확률이 아니다.

007/030의 기존 소실 14건 전체와 보존 경계 후보를 대상으로 한다. 유리한 사례만 고르지 않으며 새 흐름/새 검출 없이 같은 저장값과 판정 helper로 비교한다. 원래 event ID/source pointer/시각/payload를 보존한다. 경보 시각 이후의 재등장을 과거 판정 입력으로 사용하지 않는다.

실제 0.55에서 제외되는 모든 **추가 구간**을 원본과 비교하되 완벽한 사람 ID 정답이나 수동 박스를 요구하지 않는다. 이미 사용자가 확인한 007의 59.666667초 문 앞 대기 장면은 [EXP-0040-user-review](experiments/EXP-0040-user-review.md)를 재사용하고 다시 질문하지 않는다. 장면 판단으로 충분한 경우 특징점 하나하나의 동일성 검수 때문에 작업을 중단하지 않는다. 애매한 제외 사례만 한 번에 묶어 구체적으로 묻는다.

## 로컬 실행

로컬 변경을 보존하며 최신 main을 반영한다. 기존 CV 환경과 기존 Orca Run/담당자를 재사용하며 별도 서버나 GPU 큐를 만들지 않는다.

```bash
.venv-cv-batch02/bin/python -m unittest discover -s tests -p test_incident_notifications.py -v

.venv-cv-batch02/bin/python -m sceneguard.exp0041_application \
  --saved-results outputs/exp0040/007-v1 --output outputs/exp0041/007-v1
.venv-cv-batch02/bin/python -m sceneguard.exp0041_application \
  --saved-results outputs/exp0040/030-v1 --output outputs/exp0041/030-v1
```

실제 저장 입력에 대한 코드/경로 호환 오류는 원인을 기록하고 수정한다. 과거 실험을 다시 실행하거나 입력 점수를 바꾸어 통과시키지는 않는다. 실행기는 새로운 outputs 디렉터리만 허용한다.

각 출력에는 `baseline-cards.json`, `threshold-055.json`, `threshold-065.json`, `threshold-070.json`, `review-plan.json`, `summary.json`이 생긴다. 원본 JSON의 해시와 사용한 코드 해시를 기록한다. 0.55의 실제 알림 감소·장면 적합성은 실행 후 결과이며 준비 코드만으로 성공이라고 쓰지 않는다.

## 기존 화면 연결 — 새 스키마의 의미를 지킬 것

`contract=group_all_then_notify_v1`은 EXP-0036/0040과 의미가 다르므로 기존 포맷인 척 필드만 바꾸지 않는다. 기존 서비스에 최소 어댑터를 추가한다.

| 필드 | 의미 |
|---|---|
| `events` | 전체 원래 후보. 통지 제외도 포함 |
| `active_events` / `review_only_events` | 기존 payload를 보존한 완전한 분할 |
| `cards` | 전체 사건 이력. 비통지 사건도 포함 |
| `alert_cards` | 최종적으로 통지 대상이 생긴 사건 |
| `review_only_cards` | 끝까지 통지 대상이 없었던 사건 |
| `timeline` | 그 시점까지의 원래 후보/통지 상태 snapshot |
| `first_alert_pts` | 사건의 첫 원래 후보 시각 |
| `first_notification_pts` | 첫 실제 통지 대상의 논리 시각. 아직 없으면 null |
| `counts.candidate_cards` / `alert_cards` | 전체 사건 묶음 수 / 통지할 사건 수. 구분해 표시 |

**`action=created`만 보고 알리지 않는다.** 사건이 이미 생성된 뒤 `action=updated, notify=true`가 될 수 있다. 처음의 검토 전용 후보에서는 `created, notify=false`다. 알림 조건은 `notify` 또는 `notification_action=first_notify`다. 사건 묶음 생성과 알림 발생을 분리한다.

재생에는 최종 `alert_cards` 전체를 앞 시각부터 보여주지 말고 `notification_cards_at()`와 같은 시각별 snapshot을 사용한다. 원본 ID/통지 제외 이력은 펼쳐서 확인하게 한다. 첫 통지 전에는 기본 경보 목록에 나타나지 않고 검토 이력에서만 볼 수 있다. 뒤로 이동하면 미래 카드·ID·수·통지 결정을 제거한다.

이번은 비교 보기이므로 `live_notifications_enabled=false`를 지키고 기존 알림 영수증이나 검토 DB를 초기화하지 않는다. 세 기준은 서로 다른 등록/bundle로 명확히 구분하고 과거 메모를 다른 결과에 복사하지 않는다. 실제 운영 채택 전의 실험 화면에서 경보를 외부로 보내지 않는다.

영상은 EXP-0040의 원본/특징 경로를 재사용한다. 비교용 배지/표시만 필요한 만큼 추가할 수 있으나 흐름·검출·VLM을 재실행할 이유는 없다. 원본 구간 시간과 플레이어 0초 offset을 유지한다.

## 실제로 평가할 결과

1. 동일 0.70에서 **처리 순서만 고친 효과**: 원래 사건 membership과 ID 보존, 중간 후보 제외 뒤 추가 카드/추가 최초 통지가 없어야 한다. 5개 원래 묶음이 6개로 갈라지면 구현 결함이다.
2. 각 기준의 통지 대상 행 수뿐 아니라 **통지할 사건 수, 첫 통지 시각, 검토 전용 사건 수**를 보고한다. 최초 후보를 제외해서 첫 통지가 뒤로 이동하면 그 차이를 숨기지 않는다.
3. 007 52.5–58초 접근 및 이어지는 문 앞 대기에서 불필요한 사건 경보가 줄었는가? 007 64–74초 문맥에서 실제 침입 의심으로 다시 알리는가? 기존 70.133333초 첫 의심과 030 90.4초 첫 의심을 함께 비교한다. 시간값은 검수 대상이지 코드의 예외/정답 조건으로 넣지 않는다.
4. 030 전체84–100초에서 같은 규칙을 적용한다. 특히 0.55에서 새로 제외될 수 있는86.033333초도 검토한다. 필요한 의심이 남았다는 것과 개별 알림 제거가 항상 맞았다는 것은 별도로 기록한다.
5. 알림을 보존한 이유가 연속성 점수인지 별도 경계 근거인지 표시한다. 점수만으로 정상/침입이 분리된다고 주장하지 않는다. 특히 기존 raw8 보호 이유를 숨기지 않는다.
6. 모든 기준을 같은 조건으로 비교한다. 유리한 결과만 택한 개발 구간 수치를 독립 정확도처럼 보고하지 않는다. 결과가 실용적으로 개선되면 선정 이유와 실패 사례를 남겨 설정 후보를 고정한다.
7. 선정 후에는 설정 선택에 쓰지 않은 **이미 보유한 호환 구간/저장 관측**으로 확인을 우선한다. 실제 독립 입력이 없으면 없다고 기록하되 새 데이터 수집·라벨링·GPU 실행을 자동 시작하지 않는다. 개발용 시연 설정과 일반 성능 검증을 구분한다.

007에서 일부 알림만 줄고 첫 불필요한 사건 경보가 그대로라면 그 한계를 분명히 한다. 반대로 일부 불확실성이 남는다는 이유로 의미 있는 실용 개선까지 전부 실패 취급하지 않는다. 새로운 필수조건을 쌓아 다시 전부 유지/유보로 돌리는 것은 이번 목표가 아니다.

## 완료와 전달

기존 담당3에 baseline 및 세 기준 결과를 등록하고 실제 재생/seek/폴링/검토 전용 표시·첫 통지 시각을 확인한다. 기존 기본 MVP는 검토 전 자동 교체하지 않는다. 실제 결과가 유용하면 채택 가능한 구성과 연결 지점을 명시하고, 사용자에게 의미 있는 개선 여부를 먼저 보고한다.

결과 보고서 `docs/experiments/EXP-0041-results.md`, 독립 검토, 전달 기록을 실제 실행 후 게시한다. 합성 시험·실제 저장 JSON 재생·원본 장면 검수·웹 표시·운영 성능은 구분한다. 원본/크롭/점 경로/원시 점수/DB는 로컬에 남기고 코드·비식별 집계만 게시한다.
