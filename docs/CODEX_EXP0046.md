# EXP-0046 — 바닥 경계선과 문 주변 출현 구역 분리

2026-11-01 사용자 승인. 문 바닥 선과 상체/머리 박스 중심의 거리 비교를, **정지 화면에서 한 번 지정한 문 주변 출현 구역** 검사로 바꾼다. 사람 학습 라벨을 만들거나 문 검출 모델을 도입하는 작업이 아니다. 기존 종료 지시는 이전 실험 범위이며 이번 비교를 막지 않는다.

## 준비 상태

기준 main `60ea8b933eec4ab85098843de96e3b2b608f02a6`. 새 `portal_births.py`, `exp0046_application.py`, `test_portal_births.py`를 준비했다. 작성 환경에서 **55개 합성/순수 계약 시험**과 문법 검사를 통과했다. 테스트는 실제 EXP45 관측열 소스(기존 blob `9176734`)를 사용했다. 실제 CCTV, 전체 저장소 회귀, `prepared_inputs`/grouping/웹 통합은 로컬 실행 전이다. **007/030 문 구역의 실제 좌표는 아직 설정하지 않았다.** 구역 표시/성능 개선이 완료됐다고 보고하지 않는다.

## 변경 범위

- A: EXP45의 문 근처 이력→안쪽 이동→소실과 침입 검출 결과는 재계산/변경하지 않는다. `history-cards.json`과 `history-decisions.json`을 그대로 복사한다.
- B: 최초 실제 박스의 중심이 고정 다각형 안에 있거나, 박스 면적의 절반 이상이 그 구역과 겹치면 출현 위치 근거로 쓴다. 절반 기준은 초기 기하 규칙이며 확률이 아니다. 몸이 잘려도 문 구역 자체가 줄지 않는다.
- B에 **바닥 선 거리, 박스 높이 비례 반경, 선 투영범위, 지면 inside 중심 포함**을 다시 AND로 붙이지 않는다. 이번 다각형이 문 높이와 바로 뒤의 가시 영역을 나타내는 별도 영상 좌표 기준이다. 옛 기하 값은 `legacy_ground_test`로 비교용만 저장한다.
- 시간 지지·기존 1초 관측 이력·새 ID/짧은 재검출 처리·첫 위치 유지·중복 박스 처리 등은 EXP45 그대로다. 이후 구역에 들어온 기존 관측열을 새 출현으로 바꾸지 않는다. 최초 출현 뒤 안쪽 이동으로 구역에서 멀어져도 원래 위치 근거를 버리지 않는다.
- **B 단독은 침입 의심**이다. 문 앞 바깥사람도 영상상 문과 겹칠 수 있다. 다각형 겹침은 실제 어느 쪽에 서 있는지/침입 완료를 증명하지 않는다. 가시성을 침입 부정으로 쓰지 않고 A 확인을 B 성공에 종속시키지 않는다.

## 1. 실제 문 구역을 한 번 지정하고 원본 위에 표시

새 학습용 박스/프레임별 작업을 사용자에게 요구하지 않는다. 이미 있는 **원본 PTS 0의 정지 배경**을 로컬에서 열어 C3/C6 각각 하나의 간단한 다각형 초안을 만든다. 기본은 4~6개 꼭짓점이고 정밀 윤곽은 불필요하다.

문 양끝 사이의 본체/상단과 바로 뒤에서 머리·상체가 드러날 수 있는 좁은 범위를 포함한다. 먼 안쪽 통로, 문 옆 정상 보행로, 기둥 너머 전체 통로를 넓게 포함하지 않는다. 바닥 선을 평행 이동해 자동 생성하거나, 검출된 사람 위치·실험 성공 시각에 맞춰 영역을 역산하지 않는다. 사용자 제안에 따른 **시스템 초안**이지 사용자가 정확한 좌표를 확정한 것으로 기록하지 않는다.

007은 기존 승인 inside 수정본을 계속 쓰고 030은 현행 scene이다. 원본 선/inside/outside/가림 주석은 변경하지 않는다. 새 설정은 scene 밖에 별도 저장한다. `make_region(scene, camera_id, polygon, reference_pts=0, note=...)`를 사용하면 크기·선택 scene의 digest·출처가 결속된다.

저장 예시: `runtime/portal-regions/exp0046/C3.json`, `C6.json`. 좌표는 **원본 전체 프레임 기준 0~1**이다. 비교영상의 헤더·좌우 패널 좌표를 그대로 사용하지 않는다. 원본 정지 화면+기존 선+새 구역만의 local HTML/SVG 미리보기를 만들고, 실제 범위가 위 의미에 맞는지 먼저 확인한다. 애매하면 그 정지화면/짧은 구간만 질문한다. 이미 답한 침입 장면이나 모든 박스를 다시 검수해 달라고 하지 않는다. 설정을 고정한 뒤 비교하며 결과를 보고 여러 구역을 탐색하지 않는다.

## 2. 저장 자료로 위치 기준만 비교

로컬 변경을 보존해 main을 반영하고 기존 환경/Run/큐/뷰어를 재사용한다. 새 검출·ByteTrack·flow·VLM·모델·학습·환경 설치는 없다. 기존 EXP35/42/45 입력 검증을 재사용하며 수만 파일 전체 감사로 확대하지 않는다.

```bash
.venv-cv-batch02/bin/python -m unittest discover -s tests -p test_portal_births.py -v
.venv-cv-batch02/bin/python -m sceneguard.exp0046_application \
  --baseline outputs/exp0035/007-v1.json --paths outputs/exp0042/007-v1 \
  --history outputs/exp0045/007-v1 \
  --scene runtime/region-revisions/007-inside-20261101-v1/scene007.json \
  --portal runtime/portal-regions/exp0046/C3.json --output outputs/exp0046/007-v1
.venv-cv-batch02/bin/python -m sceneguard.exp0046_application \
  --baseline outputs/exp0035/030-v1.json --paths outputs/exp0042/030-v1 \
  --history outputs/exp0045/030-v1 \
  --portal runtime/portal-regions/exp0046/C6.json --output outputs/exp0046/030-v1
```

실제 원본 선택 전체00748–105/03084–100초에 각각 한 번 적용한다. 실행 오류/경로 계약은 고치되 실패 기록을 남긴다. 옛 결과의 scene 해시를 새 구역으로 바꾸지 않는다. 동일 관측열에서 옛 바닥 검사와 새 구역을 비교하므로 결과 차이는 위치 기준에 따른 것이다. 정지 배경 구역은 카메라별 설정이고 영상ID/정답시각 분기는 추가하지 않는다.

## 3. 결과와 표시

출력은 원래 baseline, 바이트 보존된 history, portal-only, combined다. `inside-birth-events.json`, `legacy-birth-events.json`, `birth-audits.json`, `portal-region.json`, `summary.json`도 저장한다. 실제 문 구역에 있었는데 옛 위치 검사만 탈락하던 예, 여전히 놓치는 예, 새 오탐을 구분한다. 비교 반경 숫자만으로 장면 의미를 단정하지 않는다.

새 B 후보마다 최초 원본 박스와 새 구역, 직전 실제 관측, 현재 관측, 최초 시각/후보 시각을 간단하게 보여준다. 바깥에서 걸어오던 사람·문 앞 대기·문 뒤 정상 통행·부분 신체 출현을 원본과 대조한다. **새 후보가 늘었다는 사실이나 0건이라는 사실만으로 성공을 선언하지 않는다.** 애매한 새 후보는 해당 짧은 영상만 사용자에게 제시한다. 영상 확인이 필요하면 수치 설명보다 먼저 요청한다.

A 확인00772.6/03092.733333 및 기존93.033333 근거/최초 의심 시각이 유지되는지 검사한다. B와 합칠 때 원래 경보가 이전 접근 카드의 무음 갱신으로 흡수되는 경우를 `grouping_effects`로 별도 보고하고, 그 경우 결합을 기본으로 채택하지 않는다. A/B 별도 보기와 기존 사건 이력을 남긴다. 새로운 인원수/동일인 정확도는 주장하지 않는다.

기존 담당3에 최소 표시 어댑터로 EXP46와 새 `geometry_kind`를 지원한다. 옛 `distance_pixels`가 최상위에 있다고 가정하지 말고, 새 구역 그림과 `portal_center_inside`/`portal_box_overlap`을 표시한다. 초기 구역 미리보기와 새 후보/기존 자동상태를 실제 재생·되감기·폴링에서 확인한다. 사용자 수동 검토/영수증은 보존하고 외부 통지 발송은 하지 않는다.

코드·비식별 집계·결과/검토/전달 문서만 GitHub에 게시한다. 실제 구역 좌표·원본 이미지/영상·raw·DB는 로컬에 둔다. 이번 변경의 실제 이득과 남은 오탐을 결과로 제시하고 기본 MVP 교체는 구분한다.
