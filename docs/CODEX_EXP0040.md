# EXP-0040 — 실제 통지를 줄이는 영상 연속성 후처리

2026-10-31 사용자 승인. 목표는 **불필요한 알림 감소와 필요한 침입 의심 유지**다. 겹침·부분 신체·정지를 전부 유보해 아무 결과도 바뀌지 않는 것을 성공으로 보고하지 않는다. 새 학습·라벨/박스 작성·모델 교체·VLM 재실행은 하지 않는다.

## 준비 상태와 기존 결과

기준 main: `c3258eee41606480daca6ce9ddeda9384ec286fe`. 새 코드는 `sceneguard/practical_continuation.py`, `sceneguard/exp0040_application.py`, 시험은 `tests/test_practical_continuation.py`다. 작성 환경에서 실제 OpenCV를 사용한 합성 시험 31개 통과, 두 모듈 문법 검사 통과. **실제 007/030 영상·전체 저장소 통합·로컬 화면은 아직 실행 전이다.** 기존 원본·모델·영역·의심 생성·3초/10초 묶음·검토 DB는 변경하지 않는다.

EXP-0039는 14소실 모두 시작 겹침 플래그가 있었고, 겹침 영역 제거와 최종 겹침 veto가 동시에 있었다. 9건은 시작 특징 부족(7건 0점), 3건은 연속성 미확정, 2건은 정지/배경 모호. 전체 18알림/5카드 및 정상 접근 오탐 3건 그대로다. EXP-0039-user-review.md의 ROI 장단점은 보존하되 이번에 ROI 검출을 재실행하지 않는다.

## 바뀐 방식

- 직전 3초의 실제 관측에서 영상 특징 수·박스 크기 안정성 등을 이용해 최대 3개의 시작점을 자동 선택한다. 원래 사람 ID나 미래 정답으로 시작점을 수동 선택하지 않는다.
- 비겹침 영역을 우선하되 겹친 영역의 특징도 사용한다. 다른 박스가 있다는 이유만으로 영역을 전부 지우거나 결과를 즉시 차단하지 않는다.
- 전후방 LK 검사는 점 단위로만 적용한다. 탈락한 점은 재생성하지 않는다. 전체 생존율 35% 같은 일괄 문턱은 없으며, 최소 3개의 실제 영상 대응점부터 종합 평가한다.
- 정지/부분 신체는 허용한다. 마지막 실제 관측에 연결된 영상 무늬 일치, 점들의 검출 대응·시간적 지속·이동 일관성·원래 대상 범위 안의 이력을 점수로 합친다. 가방/신체 구획을 새로 인식하는 모델은 없다.
- 겹침은 작은 감점이다. 서로 다른 점 집합을 지지하는 경쟁 대상이나 경계 반대편 이동은 감점한다. 중복 박스가 같은 특징 집합을 덮는 경우를 서로 다른 사람의 증거로 단정하지 않는다.
- 기본 점수 0.70은 **미보정 휴리스틱**이며 동일인/침입 확률이 아니다. 점수 각 항목은 새 로그에 남는다. 시작점 간 다른 공간의 연결로 결론이 갈리면 그 사례는 유지한다.
- 원래 소실 알림 중 조건에 해당하는 행은 **제안 결과의 실제 통지 대상에서 제외하고 검토 전용으로 옮긴다.** 원래 이벤트 ID·source pointer·시각은 보존한다. 단순 주석 추가로 끝내지 않는다.
- 기존 경계/양측 판정 및 다른 대상의 알림은 유지한다. 한 사람이 계속 보인다고 사건 전체를 취소하지 않는다. 연결이 없거나 보조 추적이 실패하면 기존 침입 의심을 유지한다.
- 특징 경로는 영상 대응이지 동일인 정답이 아니다. 문 무늬를 따라가는 오류, 한 박스 안에 두 사람이 섞이는 오류, 정지 배경의 잘못된 지지가 여전히 가능하다. 원본 비교로 실제 이득/부작용을 판정해야 한다.

원리 참고: OpenCV 공식 `calcOpticalFlowPyrLK` 문서 https://docs.opencv.org/4.7.0/dc/d6b/group__video__track.html . 이 API의 상태/오차 검사는 광학 흐름 대응 품질이며 사람 정체를 인증하지 않는다.

## 로컬 실행

최신 main을 로컬 변경 보존 방식으로 반영하고 기존 CV 환경을 사용한다. 이전 종료 지시보다 이번 사용자 승인이 우선이다. 새 큐/서버/총괄을 만들지 않는다.

```bash
.venv-cv-batch02/bin/python -m unittest discover -s tests -p test_practical_continuation.py -v
.venv-cv-batch02/bin/python -m sceneguard.exp0040_application \
  --baseline outputs/exp0035/007-v1.json --output outputs/exp0040/007-v1
.venv-cv-batch02/bin/python -m sceneguard.exp0040_application \
  --baseline outputs/exp0035/030-v1.json --output outputs/exp0040/030-v1
```

기존 EXP-0035 원본과 validated_inputs/native decoder를 재사용한다. 조정이 필요한 경우 경로·환경·코드 오류만 원인을 기록하며 고친다. 오래된 출력이나 테스트 실패를 덮어쓰지 않는다. 이미지 배열은 원래 알림 판단 시각까지만 사용한다. 3초의 준비 이력은 추가 경보 대기가 아니며, 기존 소실 대기 1초를 늘리지 않는다.

출력:
- `baseline-cards.json`: 같은 원래 알림의 기존 카드 보기.
- `proposed-cards.json`: 실제 통지 대상이 바뀐 제안 카드, `full_original_alerts`, `review_only_events`.
- `audits.json`, 사례별 `*-audit.json`: 선택/점수/처리 이유.
- `*-seedN.json`: 시작점별 실제 특징 경로. frame_index/PTS/영구 point ID를 보존한다.
- `summary.json`, `request.json`: 알림/카드 변화·비용·입력/코드 해시. 실제 정확도는 미평가로 둔다.

원본을 삭제한 사본을 다시 정규화해서 event ID를 바꾸지 않는다. 원래 정규화된 이벤트를 분할한 뒤 동일 group_events로 제안 카드를 만든다. 검토 저장은 기존 정답이나 메모에 덮어쓰지 않는다. baseline/proposed는 같은 원본 알림을 비교하며, 실제 외부 알림을 새로 발송하지 않는다.

## 반드시 실제로 마칠 부분

1. 두 영상의 기존 소실 14건을 모두 실행한다. 007 정상 접근 52.5–58초만 골라 유리한 결과를 남기지 않는다. 정상 접근의 3개 오탐, 007 70–73초 의심, 030 90–94초를 따로 요약한다. 007 64–74초의 문맥도 함께 검수한다.
2. 기존 EXP-0039 렌더러를 참고해 **새 포맷용 어댑터**로 시작점/점 경로/실제 박스/원래 알림/제안 알림을 나란히 표시한다. 기본 렌더러·과거 미디어는 덮어쓰지 않는다. 새 경로는 원본 픽셀 좌표, 그려진 점은 사람 bbox가 아니다.
3. 통지에서 빠진 모든 알림을 원본과 비교한다. 대상이 실제로 계속 보였는지, 다른 사람/문에 옮겨 붙어 필요한 알림을 뺐는지를 구분한다. 이미 확인된 사용자 정답과 새 자동 초안을 분리한다. 사람이 여럿이라는 이유로 완벽한 개별 정체 정답을 새로 요구하며 작업을 막지 않는다.
4. 개별 알림 수뿐 아니라 **사건 카드 수, 최초 알림 시점, 정상 구간 카드 유지/제거, 필요한 침입 의심 유지**를 비교한다. 관련 알림 일부만 줄고 첫 오탐 카드가 그대로라면 검출 개선/검토 부담 감소를 과장하지 않는다. 제안 카드 ID가 달라져도 원래 사건 시간 구간으로 대응한다.
5. 모든 점수가 0.70 미만이면 전체를 '안전하게 유보'한 성공으로 끝내지 않는다. 저장 점수로 0.55/0.65/0.70/0.75/0.85에서의 통지 변화도 진단 표로 보여준다(새 흐름 추론 불필요). 이것은 개발용 민감도 분석이며 유리한 값을 고른 독립 정확도로 보고하지 않는다. 다른 시작점 경로 충돌·별도 경계 의심 보존은 임계값 표에서도 유지한다. 기본0.70 결과와 분리한다.
6. 기존 담당3에 baseline/proposed 및 검토 전용 목록을 등록하고 재생·seek·당시 카드 snapshot·자동 갱신을 확인한다. 이전 알림 영수증/검토 DB를 초기화해서 성공 화면을 만들지 않는다. `EXP-0040` 비교 포맷 지원은 최소 어댑터로 추가하되 기존 결과를 깨지 않는다.
7. 실제 결과/독립 코드·수치 검토/화면 전달 기록을 GitHub에 게시한다. 코드·합성 시험만으로 완료 처리하지 않는다. 실제 이득이 있고 필요한 경보를 잃지 않은 제안만 기본 반영 후보로 추천하고, 기본 MVP 교체는 사용자 검토 전 별도로 둔다.

표현은 침입 의심 / 침입 확인 / 침입 아님 / 판단 불가로 한다. 통지 제외는 침입 아님 확정이 아니다. VLM은 선택적인 참고 수단이며 이번에는 호출하지 않는다. 원본/경로/미디어/좌표/DB는 로컬 전용이다.
