# 연속 관측 진입 확인 보완 및 005 방향 진단

2026-11-04. 사용자 요청으로 004처럼 계속 관측되는 바깥→안쪽 통과를 소실 없이 확인하는 경로를 추가했다. 기존 1초 소실 경로는 유지한다. 설계 근거는 [ADR-0025](decisions/ADR-0025-visible-crossing-confirmation.md).

## 변경

- `visible_gate_crossing_v1`: 기존 `observed_side_transition` 후보의 실제 관측 prefix에서 안정된 바깥/안쪽 관측과 연속성, 유한 문 경계 통과를 재검증한다. 기존 안정 관측 0.2초·3회, 최대 관측 간격0.25초·크기변화1.8 정책을 재사용한다. 소실 대기는 적용하지 않는다.
- MVP `RuleBackend.confirmations`에서 기존 방향·소실 규칙과 분기한다. 원래 의심 payload/ID는 보존하고 별도 확인 근거를 같은 사건에 연결한다.
- 확인 근거의 출처를 `visible_gate_crossing_v1`로 남기고 시각·방향·사건 연결을 검증한다. 새 근거를 과거 EXP-0045 계산 결과로 표시하지 않는다. 새 분석 버전은 `MVP-1.0-rc2`다.

## 004 저장 자료 검증

기존 MVP-0005에서 60.533초 경계 후보와61.600초 outside_to_inside 의심이 있었으나 침입 검출0건이었다. 저장된 박스/추적/특징점 입력을 새 판정 코드로 재생했다. 새 detector/tracker/flow 추론은 없다.

- 원시 후보7개, 사건 카드3개는 유지.
- 침입 검출 카드0→1, 최초 확인61.600초.
- 원본 관측과 이전 분석·영역·카드 파일의 해시 동일.
- 새 결과는 로컬 `outputs/validation/visible-crossing-v3/`에 별도로 저장. 전체45개 재평가나 요약 지표 갱신은 하지 않았다.

## 005는 반대 방향과 평가 정의 문제

사용자는 안쪽에서 바깥쪽으로 나오는 장면이라고 검수했다. 원본 정답 설명도 학교에 들어가 있던 사람이 울타리를 넘어 밖으로 나가는 상황이다. 씬 설정은 outside_to_inside와inside_to_outside 양방향 후보를 허용하며, 67.2·67.3초 등 저장된 방향 계산은 outward다.

그러나 자동 침입 검출은 inward만 인정한다. 따라서005는 방향 미정의가 아니라 **양방향 후보 감시 / 안쪽 진입만 확인 / 데이터셋의 양방향 침입 범주** 사이의 범위 차이가 있다. 이번004수정으로 퇴장을 침입으로 승격하지 않았다. 출입 양방향 경계 통과를 제품의 확인 대상으로 삼을지는 별도 결정이 필요하다. 공식 라벨·기존 평가 분모·과거 점수를 임의로 변경하지 않는다.

## 검증 이력과 한계

일반 `.venv`에서는 OpenCV가 없어 최초 시험 명령이 실패했으며, 기존 `.venv-cv-batch02`와`PYTHONPATH=tests`로 실행했다. 과거 `test_saved_actual_outputs_without_replay`는 현재 소스 바이트가 동결EXP-0048 당시 해시와 동일해야 한다고 검사하므로 승인된 소스 변경에서 실패한다. 과거 receipt를 갱신해 통과시키지 않고 현재 동작 회귀와 구분했다.

독립 검토에서 문 선분의 연장선 교차와 역방향 유한 교차를 잘못 인정하는 두 반례를 발견했다. 안정된 바깥→안쪽 방향과 일치하는 실제 관측 경로가 유한 선분 자체를 통과하도록 보완했고 두 반례를 음성 시험에 추가했다. 독립 재검토에서 추가 지적은 없었고 관련138개 시험이 통과했다. 최종 현재 동작 회귀290개 통과(위 과거 소스동일성 검사1개는 별도 구분), 최종004재생도61.600초 확인을 유지했다. 중간v1/v2와 최종v3 결과를 각각 보존했다.

한 개발 사례의 판정 개선이며 새로운 전체 정확도/재현율이나 신원 추적 정확도를 주장하지 않는다. 모델 출력에서 안정된 관측 연결이 실제 동일인을 항상 보장하는 것은 아니다. 기존 웹에 등록된 과거 실행 결과는 재분석되지 않으며 자동 변경하지 않는다.
