# 현재 작업 — EXP-0029 실제 Tracklet 연결 비교

사용자가 2026-10-30 승인한 다음 작업이다. [EXP-0029 실행 문서](experiments/EXP-0029-tracklet-linking.md)를 읽고 **구현된 코드를 실제 로컬 자료에 실행한 뒤 비교 영상과 결과를 남겨라.** 이전 EXP-0028 종료/추가실행 금지는 해당 배치의 기록이며, 이번 범위는 새 사용자 승인이다. 파인튜닝·Roboflow 전체 라벨 검수로 돌아가지 않는다.

1. 로컬 변경/과거 결과를 보존하며 main을 동기화한다. `test_*tracklet*.py`의 41개 합성 테스트를 로컬 환경에서 실행한다. 새 코드는 실제 CCTV/ONNX로 실행된 적이 없으므로 필요한 API/의존성 호환 수정과 테스트를 수행한다. 테스트 통과를 실제 사람 연결 성공으로 바꾸지 않는다.
2. 기존 FCOS 관측 + EXP-0028 ByteTrack gap의 `frames.jsonl`을 출발점으로 쓴다. 기존 raw ID를 수정하지 않고 `t...` 구간과 `p...` 연결 ID를 추가한다. 원본 대표 crop을 실제 pretrained ReID encoder로 비교한다. 파일명·사용자 설명의 사람ID를 정답 연결 규칙으로 사용하지 않는다.
3. 030은84–100초로 시작한다. 007은48–68초만 돌리고 끝내지 말고 같은 FCOS로68–105초(또는 원본 끝)까지 새 검출 캐시를 보완한다. 확장 구간에는 기존 GPU 큐를 사용하고 원본PTS·기존 구간을 보존한다. 새 확장 캐시와 gap tracker 출력의 연속성을 확인해 넘기 전과 넘은 후를 포함한다. 030 후기 안정 관측이 부족하면100–105초만 추가한다.
4. 로컬 배경/물리적 경계를 보고 바깥·안쪽 안전 polygon을 설정하고 source SHA/크기에 결속한다. 전이 영역은 제외한다. 문서의 예시 좌표를 그대로 쓰지 않는다. 원격에서 알 수 없는 설정이라는 이유로 계획 문서만 늘리지 말고 로컬에서 실제 설정한다. 구분 불가능하면 연결 비교는 진행하고 영역 판단 한계를 기록한다.
5. 새 `sceneguard.run_tracklet_linking`의 `--render`로 원본/원래ID/사후연결ID 영상을 만든다. 같은 영역 규칙의 연결 전/후 후보도 비교한다. 저장 features를 재사용할 수 있으므로 원본/설정이 같으면 불필요한 임베딩 재추론을 하지 않는다.
6. 자동 연결의 대표 이미지·영상과 이미 받은 사용자 관찰을 이용해 올바른 연결/오연결/유보·놓침/접근 오탐을 작은 사례표로 보고한다. 인간에게 확인이 필요한 항목은 묶어서 제시하되, 전 프레임 정답이나113라벨 검수를 진행 조건으로 만들지 않는다. 사후 연결 영상은 실시간 동작이 아니라고 표시한다.
7. 기존 결과 화면 등록·실제 영상 재생·GitHub 코드/결과 갱신 후 종료한다. 기존 공식 라벨·코드·결과는 비교 기준으로 보존한다. 미디어/대표 이미지/원시 좌표/embedding/weights는 로컬 Git 제외 경로에만 둔다.

이번에는 추가 학습이나 다른 검출기·tracker·ReID 모델을 새로 고르지 않는다. 5초 연결, 한 설정의 두 영상 비교로 실용 가능성을 판단한다. 실패하면 입력 박스 부족/외형 혼동/영역 판정/연결 제한 중 확인된 원인만 기록하고 임의로 성공 사례를 만들지 않는다.
