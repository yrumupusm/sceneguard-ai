# EXP-0047 — 의심 이후 관찰, 바깥 이탈 해제, 확인 상태 알림

2026-11-01 최신 사용자 승인. 넓게 침입 의심을 만들고 **그 뒤의 관측으로 해제 또는 확인**한다. 문 구역, 안쪽/바깥쪽 영역, 기존 방향과 소실 대기, EXP45 자동 확인은 유지한다. 새 모델·학습·수동 사람 박스·VLM·새 검출/ByteTrack/flow·구역 재조정은 이번 범위가 아니다. 이전 실험 종료 문구는 이번 명시적 승인을 막지 않는다.

## 준비 상태

추가 코드 `incident_lifecycle.py`, `lifecycle_followup.py`, `exp0047_application.py`와 시험 2파일이다. 작성 환경에서 합성 54개가 통과했다. 현재 저장소의 `incident_cards.py`와 `directional_loss.py`를 정확한 Git blob SHA로 대조한 읽기 전용 사본으로 시험했다. 방향·묶음은 실제 기존 함수이며, 합성 재생의 문 구역 판정은 사각형 fixture를 주입했다. **실제 CCTV, 로컬 입력 검증/PortalGate, 웹, 전체 회귀, 실알림 전달은 아직 실행하지 않았다.** 코드 준비를 성능 개선 완료로 보고하지 않는다.

## 판정과 상태

- 문 주변 후보를 침입 의심으로 받는다. 후보 생성이 곧 새 사람 출현이라는 설명을 쓰지 않는다.
- 해당 관측의 최근 이동이 바깥 방향이고, 실제 프레임에서 기존 1초 동안 관측이 이어지지 않으면 **연결된 의심만 자동 해제**한다. 보행로 끝까지 보일 필요는 없다. 방향을 모름/정지/영상 종료/소스 공백/특징창 만료는 해제 이유가 아니다.
- 문 근처 관측 이력 뒤 안쪽 이동·소실이면 **침입 확인 · 자동**이다. 기존 EXP45 확인 00772.6초·03092.733333/93.033333초는 정확한 원래 근거와 시각을 보존한다. 새 경로가 더 일찍 확인하면 그 새 근거와 기존 근거의 시각을 분리한다.
- 이미 확인된 근거는 이후 이탈로 취소하지 않는다. 아직 의심인 동일 관측의 과거 후보는 바깥 이탈로 정리할 수 있다. 다른 관측·해결되지 않은 별도 근거까지 해제하지 않는다.
- 한 사건의 근거 중 확인이 있으면 확인, 확인 없이 남은 의심이 있으면 의심, 모두 해제됐으면 의심 해제다. 여러 명이라고 사람별 카드를 만들거나 정확한 신원/인원수를 요구하지 않는다.
- 같은 카드의 첫 의심은 한 번, **첫 확인으로 올라갈 때 별도 한 번** 알림 의도를 만든다. 동일 확인 반복은 무음 갱신, 의심 해제는 상태/이력 갱신이다. 처음부터 확인인 동일시각 묶음은 확인 알림 하나만 만든다. 첫 의심→확인은 새 카드 생성이 아니라 같은 카드 갱신이다.
- 원래 `status`/event payload/수동 검토는 그대로다. `automatic_status='의심 해제'`를 수동 `침입 아님`으로 바꾸지 않는다. 해제 뒤 이미 보낸 첫 알림이 없던 일이 되는 것도 아니다.

## 관측 연결

EXP46 `observation-runs.json`의 실제 관측열을 재사용한다. raw ID를 사람 신원으로 쓰지 않는다. B는 저장된 관측열, 기존 소실 후보는 원래 실제 관측 참조로 연결한다. EXP46의 중복 제거로 참조가 없으면 같은 프레임의 유일한 포함 박스(.9 기존 기준)만 보조 연결하며 방법을 기록한다. 모호한 연결은 미결 근거로 남기되 다른 명확한 사례까지 막지 않는다.

기존 관측열이 끊겨도, 대상에 연결된 같은 특징점이 다른 실제 박스의 유일한 관측열로 이어지면 의심의 관찰 대상을 넘긴다. 원래 ID/박스/관측열은 수정하지 않는다. 이전 실제 관측 이력은 방향 계산용 계보로만 이어서 활용한다. 단순히 근처에 한 사람이 있다는 이유로 다른 의심을 해제하지 않는다. 여러 소스가 같은 후속 대상에 경쟁하면 결합하지 않고 원인을 기록한다.

이 연결은 완벽한 동일인 복원이 아니다. 혼합 박스/오연결은 잘못된 해제의 원인이 될 수 있다. **모든 실제 해제는 원본과 관측 계보로 확인**한다. 기존 규칙으로 방향이 안 나오거나 연결이 막히면 `binding-audit`/`followup-audit`로 원인별 수를 보여준다. 전부 유보된 것을 안전한 성능 개선으로 포장하지 않는다.

기존 3초/10초는 새 후보의 사건 묶음에만 사용한다. 의심을 추적·해제할 수 있는 기한은 아니다. 후보가 추가되지 않아도 연결된 관측의 후속 상태를 평가한다. 짧은 재검출은 기존 관측열 또는 점 대응으로 이어서 보고, 완전한 전신·VLM 동의·반대편 재등장 조건을 추가하지 않는다.

## 로컬 실행

로컬 변경을 보존하고 최신 main을 반영한다. 기존 Run·환경·서버·큐를 사용한다. 아래 기존 경로는 출력이 실제 존재하는지 확인하고, 새 출력은 덮어쓰지 않는다.

```bash
.venv-cv-batch02/bin/python -m unittest discover -s tests -p 'test_*lifecycle*.py' -v
.venv-cv-batch02/bin/python -m sceneguard.exp0047_application \
  --baseline outputs/exp0035/007-v1.json --paths outputs/exp0042/007-v1 \
  --portal-result outputs/exp0046/007-v1 --output outputs/exp0047/007-v1
.venv-cv-batch02/bin/python -m sceneguard.exp0047_application \
  --baseline outputs/exp0035/030-v1.json --paths outputs/exp0042/030-v1 \
  --portal-result outputs/exp0046/030-v1 --output outputs/exp0047/030-v1
```

실제 경로·자료형·미세 시계 반올림 등 연결 오류는 원인을 기록해 고친다. 승인된 입력·영역·방향 기준·판정 의도를 바꾸어 오류를 숨기지 않는다. 실제 입력에는 `prepared_inputs`, EXP46 해시, scene/region, 매 프레임 실제 박스 참조 검증이 있다. 관련 입력만 검사하고 수만 파일 재감사로 확대하지 않는다.

출력은 `lifecycle-cards.json`, `notification-intents.json`, `binding-audit.json`, `followup-audit.json`, `resolutions.json`, `summary.json`과 바이트 보존된 기존 보기다. raw/좌표/관측계보/원본/영상/DB는 로컬 전용이다. 비교 결과는 `live_notifications_enabled=false`; 외부 알림을 새로 발송하지 않는다.

## 실제 비교와 최소 화면 연결 — 반드시 수행

1. 같은 007/030 전체 구간을 시간순으로 처리한다. 구간 끝에서 강제로 해제하지 않는다. 새 후보/옛 후보 연결률, 바깥 소실 해제·안쪽 소실 확인·방향 미확정·연결 미확정을 구분한다. **시간만 흘렀다는 이유로 미결 건을 전부 해제하지 않는다.**
2. 실제 해제된 구간을 원본 전후와 함께 확인한다. 필요한 침입 의심까지 해제했는지, 다른 사람의 이탈을 잘못 사용했는지 기록한다. 기존 사용자 검수는 재사용한다. 실제 바깥 이탈 사례가 없다면 해제 성능은 미평가로 남기고 합성 시험을 실영상 성공으로 바꾸지 않는다.
3. 기존 A 확인 근거가 보존되고, 007/030의 **확인 상태 변화가 앞선 접근 카드의 무음 갱신에 묻히지 않는지** 확인한다. 첫 경보/첫 확인/확인 알림 시각을 따로 표시한다. 새 카드 개수나 알림 감소만으로 정확도 개선이라고 하지 않는다.
4. 새 `incident_lifecycle_v1`은 기존 candidate timeline과 다른 계약이다. 기존 어댑터에 억지로 통과시키지 말고 최소 전용 표시를 추가한다. `lifecycle_cards_at`으로 당시 상태만 재생하고, `notification_intents`의 `kind`/`notification_key`를 쓴다. `created` 또는 기존 `first_notification_pts is None`만으로 확인 알림을 막으면 안 된다.
5. 같은 카드에서 의심→해제/확인, 여러 근거 중 일부 해제, 되감기, 재생 중 폴링, 반복 로드/재시작 시 중복 알림 의도 방지를 확인한다. 재생/비교의 알림 영수증은 운영 영수증과 분리하고 기존 DB를 초기화하지 않는다. 수동 검토는 별도 유지한다.
6. 원본/문 구역/평균 이동 방향/마지막 실제 관측/현재 상태만 간단하게 표시한다. 모든 중간 프레임을 별도 영상으로 늘리지 말고 전체2개와 변경 사례 묶음 정도로 전달한다. 영상 의미가 애매하면 새 해당 구간만 보여준다. 이미 본 장면·수동 박스·정밀 신원 정답을 반복 요구하지 않는다.
7. 실제 결과·독립 코드/수치 검토·전달 기록을 GitHub에 게시한다. 원본18후보와 B20후보는 보존하되 후속 상태는 별도 비교한다. 기본 MVP 자동 교체는 하지 않는다. 잘못된 해제/확인, 유효한 개선, 미평가를 구분한다.

핵심 목표: **의심을 넓게 잡고, 바깥으로 떠나면 정리하며, 안쪽 침입 확인으로 바뀌면 놓치지 않고 알린다.** 최초 오경보를 줄인 실험과 후속 의심 정리/상태 알림 개선을 구분한다.
