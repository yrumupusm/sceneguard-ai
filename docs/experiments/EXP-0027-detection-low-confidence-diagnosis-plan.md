# EXP-0027 — YOLO Detection 낮은 점수 후보 및 Roboflow 라벨 의미 감사

- 날짜: 2026-10-29
- 상태: **실행 지시 준비(원격 GitHub). 로컬 추론·라벨의 실제 이미지 검수·결과 등록 미실행**
- 사용자 승인 맥락: EXP-0026의 실패 원인을 좁히기 위한 **추가 학습 없는 진단** 진행.
- 이전 근거: [EXP-0026](EXP-0026-exploratory-person-finetune.md), [준비 데이터](../data/CLIMBING_FENCE_PREPARATION.md), [EXP-0004 FCOS 임계값 결과](EXP-0004-fcos-score-threshold-comparison.md).
- 목적: pretrained YOLO26m Detection과 EXP-0026 best Detection이 울타리 넘는 사람을 아예 후보로 찾지 못하는지, 아니면 `conf=0.25` 이전에 제거하는지 확인. 라벨/도메인 차이가 학습에 미친 영향은 **가설로 분리**하며, 이 진단만으로 원인 확정 금지.

## 핵심 사전 사실 (변경 불가)

1. EXP-0026은 `conf=0.25`를 적용한 YOLO.predict **최종 Results**만 보존했다. 이 캐시에는 0.25 미만 박스가 없음. 이를 캐시 재필터만으로 복구했다고 하면 안 된다.
2. EXP-0026의 학습은 COCO80→person1-class이며, pretrained 기준 역시 같은 **Detection** checkpoint의 person0 행을 사용했다. Pose 640/960은 별도 실험이며 동일 모델 before/after로 합산하지 않는다.
3. EXP-0004는 **FCOS**의 낮은 최종 임계값에서 일부 사람 복원과 중복·배경 의심 동반을 확인한 *과거 별도 검출기* 실험이다. 그 값을 이번 YOLO 결과로 대체하지 않는다.
4. 원본 Roboflow export는 `fence / people-jump-fence / person-climbing-fence`의 **3 클래스**이며, 247장/사람 잠정 박스354행(기존 bbox335 + polygon 외접19), `fence` 247행 제외, `people-jump-fence` 박스의 개별 사람 대응 미검수. 파일명 기반 원본 후보107그룹, 로컬 검수 패널113개.
5. EXP-0026의 best checkpoint는 로컬 전용 `outputs/batch0007/EXP-0026/train_compare/616f05a480c7434f82253e90ae7a096e/training/weights/best.pt`, SHA256 `1b120a24c8983507e137304ec3ef814a2415d97c866113df80a6cb61c260dd4f`. pretrained checkpoint는 `weights/yolo26m.pt`, SHA256 `401cea9ab23ad19246ff7744859816bc599f350e93c9dd30367b6f0a0745d0b7`.

## A. CPU-only 첫 단계: 기존 바이트/결과 확인과 라벨 감사

1. 로컬 `data/climbing_fence/person_bbox_draft_v1`의 원본/잠정 자료·manifest 해시가 EXP-0026 기록과 동일한지 **읽기 전용 검증**한다. 원본 ZIP, 이미 변환된 라벨, summary의 `D0_passed:false`, train/val/test split, 113개 `review/` PNG를 바꾸지 않는다.
2. 113개 검수 패널의 로컬 목록을 만들고 `people-jump-fence` 포함 8개 박스, polygon 19개 행부터 **원본/변환 비교**가 가능하도록 정리한다. 패널 하나가 여러 위험 요소에 속해도 중복 검토 대상을 임의로 부풀리지 않는다.
3. 사람 검수 필드: (a) 박스가 **1명/복수명/장면** 중 무엇을 나타내는지, (b) **전신/가시 신체 일부/울타리 포함/불명확**, (c) 프레임 안 **미라벨 사람** 존재, (d) 접이식 철제문·원거리/가림 등 SceneGuard C6와 구도 유사성, (e) 변환 후 bbox의 적합 여부.
4. **이미지 내용은 사람 검수 전 모두 미확정**으로 남긴다. 에이전트가 확인하지 못한 PNG를 보고 양호/불량으로 자동 판정하지 않는다. 학습 데이터 리라벨링/삭제는 이번 진단 범위 밖이다.
5. 보고서에는 113개 검수 상태별 집계와 별도 주석 검수자의 의견을 분리한다. 판단 전에는 `review_pending` 유지.

## B. 새 로컬 추론: 정확히 2 Detection × 7 고정 프레임 = 최대 14회

- 입력: **EXP-0026 평가용 7장 로컬 RGB/crop/정확한 native PTS 캐시 그대로** 재사용. 새 프레임 디코딩, 새 영역 선택, 데이터 다운로드/업로드 없음.
- 목록과 순서는 E01_030 **84,90,94,50,55초(C6)** 및 E01_007 **47.5,52.5초(기존 C3)**. 030 ROI 원본 좌표 `[537,216,1440,864]`; 007 ROI는 고정 `configs/mvp0001_cameras.json` 검증값. 동일 프레임은 중복 추론하지 않는다.
- 모델: (1) EXP-0026에서 쓴 pretrained `yolo26m.pt`; (2) 위 SHA256에 고정된 `best.pt`. 추가 모델/새 체크포인트·학습·VLM/pose·데이터 다운로드 없음.
- 추론: 양쪽 모두 Ultralytics 8.4.192 공식 `YOLO.predict`, CUDA0, FP32, imgsz640, rectFalse, batch1, classes[0], max_det300, iou0.7, nmsFalse, 같은 ROI·색상·좌표 복원. **유일한 변경 축: `conf=0.25` → `conf=0.05`**. 낮은 임계값은 *진단 관측용*이며 기본 설정을 변경하지 않는다.
- `max_det`·모델 내부 필터·후처리로 사라진 후보는 보이지 않을 수 있다. 따라서 **0.05에서 결과 없음 = 내부에서 어떤 반응도 없음**이라고 단정하지 않는다.
- 기존 EXP-0026의 0.25 결과는 **읽기 전용 비교**. 이번 0.05 Results에서 `>=0.25`인 박스를 CPU로 필터해 기존 0.25 저장 결과와 위치·점수·순서를 비교한다. 실행 간 또는 임계값 변경에 따른 후처리 차이가 보이면 별도 기록하고 억지로 일치 처리하지 않는다.
- 0.05 아래로 임계값 sweep하거나 960 입력/ROI/가중치 변경, SAHI/추적/후속 행동 판단을 **이 실험에서 추가하지 않는다**.

### B-1. 출력과 시각 검수

각 프레임·모델별로 `[0.05,0.10)`, `[0.10,0.25)`, `[0.25,1]` 점수 구간의 후보 수, 전체 후보 수, 상위 점수와 bbox를 **로컬 전용** 저장한다. `0.25`를 포함하는 박스의 과거 캐시 대응을 별도 표시. x/y crop offset은 한 번만 적용하고 원본 RGB 전체에 검출 박스를 표시한다.

한 프레임당 **원본 / pretrained 낮은 점수 / fine-tuned 낮은 점수** 3패널, 총 7장(로컬). 구간별 박스 색을 구분하고 `score`를 표시한다. 읽기 어려울 만큼 박스가 많으면 별도 순위표/단일 모델 패널로 보완하되 그리기 위해 결과 박스를 삭제하지 않는다.

사용자가 한 번에 검수할 항목:
- E01_030 84초 접근 중 3명의 박스가 유지되는지(각 모델).
- 90초 **넘는 3명** 중 어느 사람 위치에 박스가 있는지. 여러 박스가 한 사람 일부를 반복 둘러싼 것은 별도 사람 복원으로 계수하지 않음.
- 94초 **문 위 1명 / 이미 넘어간 1명** 각각의 박스 대응 여부.
- 50/55초, 007 접근 장면에서 사람 누락과 울타리/기둥/배경 오검출 증가 여부.
- 신체 일부·중복·가림·ROI 절단·불명확은 정확한 사람별 annotation 없으면 보류.

기계의 박스 개수는 **사람별 TP, recall, accuracy, mAP, 행동 이벤트 정확도**가 아니다. 사용자 실제 이미지 대응 검수 전의 지표는 오직 기계 출력 수다.

## C. 실행 경계 / 안전 / 전달

1. 기존 BATCH-0007 EXP-0026 완료 상태·기존42+1 queue job/attempt·원본·라벨·모델 weight·원시 출력 및 검수 결과 전부 **불변**으로 유지한다.
2. 실행기는 **새 EXP-0027 전용 경로**에만 추가한다. 이전 `batch07_detect` runner/고정 `train_compare` job key·authorization을 다시 쓰거나 재실행하지 않는다.
3. 기존 Orca Run/실효 Task·Dispatch 확인 후 **canonical 직렬 GPU 큐**와 여유 VRAM **6144MiB 이상** 게이트, 실행 소스+입력+체크포인트 해시+실제 lease 검증을 사용한다. 직접 runner 실행, 기존 큐 우회, 자동 축소/재시도, 타 프로세스 강제 종료 금지.
4. CPU 합성 테스트: 두 체크포인트 hash·모델/클래스, 7개의 native PTS, crop/색상/offset, Result Nx6 및 유한 값, confidence [0.05,1], score bins, 빈 결과, 캐시0.25 재사용, output 비덮어쓰기, queue/authorization/실행 게이트, 데이터셋 불변, 공개 파일 경계. **GPU 실행 전** 독립 검토.
5. 실제 GPU 허용 한도: pretrained 7회 + fine-tuned 7회, 각 1회 예측(공식 warmup은 별도 계측). 정상 empty는 재시도 사유가 아님. 오류 발생 시 근거 기록 후 자동 재시도하지 않는다.
6. 공개 GitHub에는 **새 계획/코드/집계/한계/검토 결과만**. 원본 CCTV·Roboflow 이미지·라벨/raw bbox·low-score 후보 좌표·오버레이·best.pt·runtime/DB/receipt는 로컬에만. 새 결과를 기존 로컬 웹에 등록할 수 있으나 실제 렌더링 검증 전에는 노출 성공으로 주장하지 않는다.
7. 종료 문서에는 7장×모델의 3개 confidence bin 수, `>=0.25` 기존 캐시와의 대응, 실제 사람별 시각 검수 완료/미완료, 113 라벨 검수 진행 상태, 실행 시간/메모리, 계속 남는 문제와 **다음 한 가지 권고**를 분리 보고한다. 추론 성공만으로 파인튜닝 성공·기본 채택으로 표시하지 않는다.
8. 종료 후 추가 epochs, threshold sweep, 해상도 변경, 모델 교체, 규칙/추적/VLM 결합 작업을 자동으로 예약하지 않는다.
