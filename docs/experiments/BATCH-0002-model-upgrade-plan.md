# BATCH-0002 — 모델 대안 검증과 조건부 CV·VLM 결합 실험

2026-10-29. 사용자 승인: 기존 SceneGuard의 **모델 개선**을 진행한다. 이 문서는 승인 범위와 사전 고정 평가 계약의 상한이며, **GitHub 문서 작성 자체는 로컬 실험 실행/모델 채택이 아니다.** 현행 `main`의 EXP-0017 종료 상태와 기존 기본값을 유지한 채, 총괄이 이 범위 안에서 구체 실행 manifest와 게이트를 사전 고정한다.

## 0. 이미 확인된 문제와 이번 목적

- CV: FCOS ResNet50-FPN은 030 약84초의 접근 인물 3명을 잡았으나 약90초의 실제 문 넘기 자세에서는 최종 사람 검출 0이었다. 같은 구간의 복수/부분 박스와 031의 배경 의심도 있었다. ByteTrack에서 국소 연결은 개선됐지만 007의 박스 급변 기반 후보가 생겼다. **FCOS/ByteTrack은 채택 보류이며 현재 MVP에는 연결되어 있지 않다.**
- VLM: 현 MVP는 Qwen3-VL-2B-Instruct가 5초·약2fps로 원본 전체 또는 고정 ROI를 직접 분석한다. 사용자 확정 5초창 q 6개에서 비시도 5개 중 B/C 각각 2개를 후보화하고, 시도 q04에서는 B 누락/C 후보였다. EXP-0017의 프롬프트 변경은 B의 잘못된 후보 2→3, C 2→2, 추가 v 양성 2개의 후보 1→0으로 개선되지 않아 채택 보류다.
- 목적: (A) **모델에 실제 구별 가능한 시각 정보가 들어가는가**를 먼저 점검하고, (B) 사람 검출 대안 1개 및 VLM 대안 1개를 독립 비교하며, (C) 두 결과에 실질적 상호 보완 근거가 있을 때만 **작은 오프라인 결합 PoC 1개**를 수행한다. 결합 구조를 정답으로 전제하지 않는다. **모델 2개를 억지로 연결하거나 정밀 정답 없이 성공을 주장하지 않는다.**

## 1. 후보 상한 및 공식 출처

- CV 신규 가중치 **최대 1개**: 우선 검토 후보는 Roboflow의 **RF-DETR Medium (COCO pretrained)**. 코드 및 Core Nano–Large 공개 가중치는 Apache-2.0이라고 공식 문서에 표시된다. 고정 576×576 입력이 CCTV 작은 사람에게 유리하다고 가정할 수 없으므로, FCOS의 실제 변환 크기와 비교해 전처리 손실을 먼저 검토하고 선택 이유를 ADR에 남긴다. Python/torch/Transformers 의존성 충돌 시 **격리 가상환경**을 사용한다. 공식 문서: https://github.com/roboflow/rf-detr/blob/develop/docs/learn/run/detection.md 및 https://github.com/roboflow/rf-detr . RT-DETR-R50 (https://huggingface.co/PekingU/rtdetr_r50vd_coco_o365)은 대안 검토만 가능하며, 두 번째 CV 가중치 다운로드·실행은 이번 승인 범위가 아니다.
- VLM 신규 가중치 **최대 1개**: 우선 검토 후보는 **Qwen3-VL-4B-Instruct** (https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct , Apache-2.0). 기존 2B와 같은 계열이라 비교하기 용이하지만, **실제 성능이 높다는 근거는 아직 없다**. RTX 3080 10GB에서 4bit 등 양자화가 필요할 수 있다. 공식 bitsandbytes 안내 https://huggingface.co/docs/transformers/quantization/bitsandbytes 참고. 양자화 적용 범위·메모리·추론 출력 변화를 기록하고, **2B BF16 대비 용량/양자화가 동시에 달라지는 비교**임을 인정한다. Qwen3.5-4B (https://huggingface.co/Qwen/Qwen3.5-4B)는 향후 대안으로만 기록하고 이번에 추가 다운로드하지 않는다.
- 실제 선택은 공식 모델 카드/라이선스/체크포인트 revision/장비·환경 호환성·무료 로컬 실행을 총괄이 검증한 뒤 확정한다. 모델명만으로 설치·실행 성공 또는 품질 향상을 주장하지 않는다. 모델별 dependency와 환경 freeze를 별도로 기록한다.
- **추가 재학습·파인튜닝·라벨에 맞춘 prompt 반복 튜닝·상용 API·유료 결제·새 CV/VLM 모델 무한 탐색은 금지**.

## 2. 1단계 — 입력 충분성·관찰 근거 감사 (CPU/로컬, 신규 추론 없음)

1. 사용자 확정 q01–q06(007/030)과 v01–v04(004/021), 기존 030 84/90/94초와 007 64–66초를 우선한다. **기존 10개 5초창은 모두 개발·진단용**이며 독립·무작위 테스트가 아니다. v03은 문 옆 틈의 시도/진행이지만 경계선 연결은 미확정, q04 완료는 관찰되지 않았다. 031 집단 미완료를 030으로 이전하지 않는다.
2. 모델의 실제 입력 RGB·시간 PTS·시각 토큰·resize·crop/ROI·공간상 사람 크기와, 원본 중 대응 시각을 **로컬에서** 대조한다. 5초·2fps의 10프레임에 신체를 올리는 과정이 어떤 프레임에 나타나는지, 시간 샘플링 손실 또는 과도한 축소의 **관찰 가능한 사실과 미확정 가설**을 구분한다. 과거 processor RGB가 저장되지 않은 q 구간은 재구성 자료를 원래 실행의 정확한 바이트라고 주장하지 않는다.
3. 선택한 시간에 **실제 관찰이 가능한지**를 확인하지 않은 상태에서 사람 탐지 성공/실패, 시도 완료, 오탐 시간을 정밀 정답화하지 않는다. 원본 픽셀은 클라우드 에이전트/외부 서비스에 전달하지 않는다. 사용자 재검수가 정말 필요하면 질문을 작은 묶음 하나로 모으고, 기존 확정 사항을 다시 묻지 않는다.
4. 입력 자체에 충분한 동작 단서가 없다는 근거가 뚜렷하면, **모델 교체 결과만으로 문제를 해결할 수 있다는 가설을 보류**하고 그 한계를 보고한다. 적합한 정보가 있으면 다음 단계로 진행한다. 이 감사만으로 추론 코드를 변경하거나 새 답을 생성하지 않는다.

## 3. 2단계 — CV 모델 비교 (기존 FCOS vs 신규 1개)

- 기존 원본 PTS 프레임을 고정하여 030의 84/90/94초, 007의 52/64/66초, 031의 32/40초, 006 후기 보행, 검수된 v01/v03 중 **실제 비교 가능한 진단 프레임**을 사전 고른다. 전체 최대 **240개 고유 디코딩 프레임**, 동일 시각·좌표계·카메라 조건을 우선 사용한다. 원본 시각/정답/사람 상자를 모델 입력 메타데이터로 보내지 않는다.
- 정확한 프레임에 대한 기존 FCOS 캐시가 있으면 재사용; 없으면 **기존 고정 FCOS**를 비교용으로 동일 프레임에 한 번만 추론한다. 신규 CV 모델의 기본 설정·preprocess/resize·confidence·NMS를 사전 고정하고 로컬 출력 bbox/score·원본 좌표 mapping/해시를 보존한다.
- 시각 확인 가능한 사람의 **존재와 bbox의 위치 일치·누락·중복·의심 배경 박스·넘기 순간의 유지 여부**를 별도 검수표로 비교한다. 단순 검출 개수 또는 COCO AP를 이 CCTV의 recall/precision/성공률로 취급하지 않는다. 사람별 정답 bbox가 없으면 수치 precision/recall/F1은 null. 006 후기 사람은 기존 ROI 바깥이므로 ROI 안 정상 구분 성공으로 세지 않는다.
- ByteTrack을 붙이기 전에 **실제 넘기 프레임에서 탐지기가 사람을 놓치는지**부터 판단한다. 지속 ID·바운딩박스 하단 점프가 이벤트 근거로 충분하지 않다. detector만 개선되었다는 증거 없이 추적기/이벤트 규칙을 교체하지 않는다.
- 최소 GPU smoke(1~2개 프레임)→메모리·입출력 확인→지정 프레임 전체 실행. 기본 모델보다 실제 관찰을 더 안정적으로 복원하는 근거가 없으면 채택 보류하고 CV 실행을 종료한다.

## 4. 3단계 — VLM 모델 비교 (기존 Qwen 2B vs 신규 4B)

- 사용자 확인한 10개 q/v 개발창에서 **기존 채택 보류인 EXP-0017 revised prompt가 아니라 이전 공통 원본 prompt**를 고정한다. q01–q06은 B 전체화면 및 기존 C 고정 ROI, v01–v04는 해당 카메라에 교정 ROI가 없으므로 전체화면만. 모델의 공식 processor 차이는 허용하되 실제 시간·프레임 개수·해상도·visual token·context length를 보존한다. 기존 2B 결과를 정확히 재사용할 수 없는 조건은 새 기준 실행과 구분한다.
- 새 4B는 격리 환경에서 weight/transformers/quantization 지원을 확인한 뒤 **양성 q04·음성 q05 각 1개 최소 smoke**를 먼저 수행한다. 기존 단일 GPU queue, 실행 전 여유 VRAM 최소 **6,144MiB 게이트(상향 가능, 하향 금지)**, OOM·환경 불일치 시 중단하며 무음 CPU offload·일부 프레임 삭제·추론 해상도 축소로 '성공' 표시하지 않는다. 실패 재시도는 job당 최대 1회.
- smoke 통과 시 나머지 사전 고정된 10창을 **중복 없이** 처리한다. 기준 2B와 새 4B를 사용자 검수된 창의 동일 행동 정의로 비교하되, **후보/유보/완료 주장/상세 근거/파싱/비용/양자화 여부**를 각각 표시한다. 비사건 후보가 줄면서 양성 q04/v01/v03을 놓치지 않는지를 우선 보고, 사람/행동이 실제로 보이는지 불확실하면 판단 보류한다.
- q/v는 소규모·선택 편향·카메라 중복이 있으므로 정확도/F1/오탐률/독립 일반화 성능을 새로 만들어내지 않는다. 성능 차이는 해당 개발창의 기술적 관찰로만 기록한다. 모델이 '완료'라고 썼다는 이유만으로 넘기 완료를 확정하지 않는다.

## 5. 4단계 — 통합 여부 게이트 (조건부 PoC만)

- CV가 **시도 순간의 실제 사람 위치를 유의미하게 복원**하고 VLM의 실패와 **상호 보완 가능성**이 출력 근거로 확인됐을 때만, 기존 출력·PTS·ROI를 대응시킨 **오프라인 결합 PoC 최대 1개**를 수행한다. 두 후보가 모두 부족하면 **통합을 건너뛰고 실패/보류로 종료**한다. 결합을 과제 성공의 필수 산출물로 만들지 않는다.
- 결합 방식을 선택한 이유와 대체 모델 단독 대비 어떤 **검토 가능한 정보**가 추가되는지 보여준다. CV가 사람을 못 잡으면 VLM을 금지하는 **CV-only 게이트는 허용하지 않는다**. 일정 간격 VLM 경로/검토 보류가 살아 있어야 한다. CCTV 사람 권한/위법성 판단을 하지 않는다.
- 병합 사건 수·신규 후보 수 증가, 추적 ID의 지속, 새 카드 등록만으로 성능 개선이라 주장하지 않는다. 코드가 작동하는 것과 실제 행동 정확도·비용·재현성을 별도로 평가한다. 새 전체 원본 3개 재추론이나 운영용 배포는 이 범위에 포함되지 않는다.

## 6. 실행 책임, 자원, 중단 기준

- 기존 **Astra max 총괄 1명**, Sol high 담당(입력/CV, VLM/평가 중 분담) 최대 2명 + 독립 **Astra high 검토** 1명. Orca **native Task/Dispatch**를 사용하고 실제 세션/effective model 확인. 중첩 작업자/새 총괄/새 공통 큐 금지. CPU 문서·코드 준비만 병렬; GPU 작업은 **기존 canonical queue 단일 직렬**.
- 모든 새 model weight/임시 패키지는 로컬 전용, 별도 `.venv-*` 권장. 기존 `.venv`, `.venv-vlm`, `EXP-0001~0017`, 정답 및 설정/모델 결과는 변경·덮어쓰기 금지. 코드는 실행 전 commit, source/input/weights/prompt/환경/설정 SHA 고정.
- 최소 smoke 실패 또는 정확한 비교 불가, 게이트 미충족, 사용자 확인 자료 부족 시 근거 있는 중간 결과를 기록하고 **해당 단계에서 멈춤**. 작업별 오류 재시도 최대 1회, 반복 prompt 튜닝·자동 데이터 확보·새 모델 탐색 금지. 임의 타 프로세스 종료/게이트 낮춤/큐 우회 금지.
- 프레임/원본 영상/입력 시트/raw model responses/token IDs/가중치/절대경로/runtime/SQLite/receipt/credential을 GitHub·클라우드 agent 이미지 도구로 공개하거나 전송하지 않는다. code/비식별 metrics·오류/결론만 게시한다.

## 7. 납품·검증

1. **입력 충분성 감사 요약:** 프레임별 실제 가시 단서, crop·resize·2fps의 손실/미확정.
2. **CV 비교:** 같은 PTS에서 사람 bbox·작은 사람·넘기 자세·오검출 의심 비교, 채택/보류·이유·장비 메모리/시간.
3. **VLM 비교:** q/v 같은 10창에서 기존 2B/신규 4B의 사용자라벨·후보/유보/완료·근거 사실성/비용 비교; 4bit 등 양자화의 제약.
4. **결합 선택:** 조건 충족 시 PoC 1개와 VLM-only 대비 근거 변화. 불충족 시 **비통합 결정 근거**로 완료.
5. **독립 검토:** Astra가 소스 해시·실제 sample provenance·원문/측정치·비교 해석을 검사. 이전 결과의 사람 정답을 정밀 GT로 몰래 바꾸지 않는다.
6. **기존 전달 프로세스:** 새 BATCH/EXP ID로 보고서·metrics·review binding·로컬 근거 artifact 등록, 현재 읽기 전용 웹의 담당 카드·보고서·그래프·원본 참고 영상 재생/seek 확인, GitHub remote HEAD/서비스 버전을 별도 receipt로 검증. 이전 결과와 blocked job은 보존한다.
7. 최종 한 페이지에서 **실제 완료 / 미실행·차단 / 모델 선택 근거 / 남은 행동 오류 / 다음 하나의 선택**을 구분하고 더 진행하지 않는다. 실패 결과도 유효한 배치 종료다.
