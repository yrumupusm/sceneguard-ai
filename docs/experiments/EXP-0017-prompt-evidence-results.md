# EXP-0017 — 고정 프롬프트 개선안의 실제 비교 결과

2026-10-29 KST. [EXP-0017 계획](EXP-0017-plan.md)에 따라 GPU 자원 확보 후 [EXP-0016](EXP-0016-prompt-evidence-rubric.md)의 고정 사양을 재개했다. **4개 직렬 작업·20개 생성은 완료했으나, 목표한 행동 판단 개선은 확인되지 않았다. 수정 프롬프트 기본 적용은 보류하고 기존 구성을 유지한다.** EXP-0016 차단 결과, EXP-0013/14/15와 공식 라벨은 보존한다.

## 변경 원리와 실행

[ADR-0017](../decisions/ADR-0017-qwen-temporal-evidence-prompt.md)의 한 원리만 비교했다. 공통 질문에서 프레임 순서에 따른 신체와 경계의 상대 움직임을 근거로 요구하고, 접근·대기·접촉만으로 넘기를 추정하지 않도록 한 것이다. 모델은 기존 Qwen3-VL-2B-Instruct, revision `89644892e4d85e24eaac8bacfd4f463576704203`, weight SHA `7de1838c87a5349b016c26a1c3f7d2bc400a3d485f95ef39a7059ffd734977a0`를 재사용했다. 모델·가중치·ROI·샘플링·generation·parser·후처리 변화나 결과별 튜닝은 없다. 이전 출력의 잘못된 근거/행동 연결은 관찰 사실이지만, 그 원인이 prompt인지 시각 표현·가림·샘플링인지는 이 실험으로 분리하지 못한다.

기존 Run `run_3d23462a014a`, Sol high 실행 Task `task_032ba4cbc816` / Dispatch `ctx_65e6cdf6b6f4`, 실행 code commit `64ab297775d712a18f5149c0fd8f3d8d19dec848`를 사용했다. 기존 공통 queue에서 4개 job이 겹치지 않고 성공했으며 실행 오류·OOM·retry는 0이었다. runner gate는 free 8015–8026 MiB로 고정 최소 6144 MiB를 통과했다. 정확한 job/attempt·환경·source/input/config 해시·재현 명령·실측은 [실행 보고서](EXP-0017-execution.md)에 있다. 저장 경로는 고정 runner 계약상 EXP-0016 namespace의 **새 attempt**이고 새 결과 등록 ID는 EXP-0017이다.

## 입력 비교의 검증 범위

모든 창은 원본의 5초 구간을 2 fps로 선택한 10개 실제 프레임이다. processor도 10개 프레임을 받았고 추가 샘플링·시간축 패딩은 없었다. 원본 PTS와 순서를 유지했다. 영상 이름·공식 사건 시각/캡션·사용자 라벨·과거 모델 답변은 모델 질문에 넣지 않았다. 실제 질문에는 익명 window ID만 사용했다.

| 입력 | 원본/고정 crop 크기 W×H | 공식 resize W×H | 시각 토큰/창 | 수정 prompt 입력 토큰/창 |
| --- | --- | --- | ---: | ---: |
| q 전체화면 B | 1920×1080 | 768×448 | 1680 | 2073 |
| q C3 ROI (007) | 576×648 | 544×608 | 1615 | 2008 |
| q C6 ROI (030) | 903×648 | 704×480 | 1650 | 2043 |
| v 전체화면 | 1280×720 또는 1920×1080 | 768×448 | 1680 | 2073 (기존 1947) |

q의 과거/현재 비교는 source hash, native PTS, decoded RGB hash 및 저장된 visual processor metadata가 일치한다. 그러나 과거 q 실행에는 실제 processor RGB 배열과 확장 질문 전문이 저장되지 않아 그 byte 동일성을 증명할 수 없다. v 기존/수정 비교는 저장된 processor RGB까지 동일하고, native frame/PTS·환경·설정과 확장 문자열의 **질문 문구 외 동일성**을 확인했다. 저장되지 않은 내부 processor tensor 전체까지 같다고 주장하지 않는다. 자세한 검사는 [comparison.json](../../records/EXP-0017/comparison.json), [평가 코드](../../scripts/evaluate_exp0017.py)에 있다.

## q01–q06 개발 회귀 비교

B는 전체화면, C는 기존 고정 ROI다. `없음`은 모델이 candidate를 출력하지 않았다는 뜻이며 정상 판정이 아니다. `유보`는 action의 indeterminate이고 candidate와 함께 나올 수 있다. 모델 답변의 세부 묘사는 아래의 **총괄 검수 초안**이며 새로운 사용자 정답으로 쓰지 않는다.

| 창 / 사용자 확인 | 기존 B | 기존 C | 수정 B | 수정 C | 변화와 남은 문제 |
| --- | --- | --- | --- | --- | --- |
| q01 007 0–5s: 시도 없음, 문 밖 차량 | 없음 | 없음 | 없음 | 없음 | 신규 후보는 없지만 양쪽 답변의 사람 묘사는 사용자 관찰로 뒷받침되지 않는다. 후보 없음만으로 설명 정확성을 인정하지 않는다. |
| q02 007 47.5–52.5s: 접근만 | 후보 | 없음 | 후보 | 없음 | B는 보행/접근 근거로 넘기와 완료를 계속 선택한다. 잘못된 후보 감소 없음. C의 후보 없음은 기존과 같음. |
| q03 007 52.5–57.5s: 시도 없음 | 없음 | 후보 | 후보 | 후보 | B에 잘못된 후보가 새로 생겼다. 두 답변 모두 문 넘기·완료를 주장해 사용자 관찰과 충돌한다. |
| q04 007 62.5–67.5s: 시도/진행, 완료 전 종료 | 없음 | 후보 | 없음 | 후보 + 유보 | C 후보는 유지됐으나 완료값이 기존 indeterminate에서 observed로 바뀌어 사용자 완료 관찰과 충돌한다. B는 대기라고 설명해 시도를 계속 놓친다. C의 부분적 후보 일치가 완료/세부 신체 설명의 정답성은 아니다. |
| q05 030 50–55s: 세 명 중 한 명 접근만 | 후보 | 후보 | 후보 | 후보 | 양쪽 모두 넘기/완료를 계속 주장한다. 경계 근처 보행·횡단보도 서술과 넘기 선택을 구분하지 못했다. |
| q06 030 155–160s: 사람/사건 없음 | 없음 | 없음 | 없음 | 유보 | C는 후보는 없지만 사람을 묘사하며 유보한다. B의 동물 묘사도 사람 행동 판단의 근거가 아니며 기존 검수로 확인되지 않았다. 유보를 정상 성공으로 세지 않는다. |

확인된 no-attempt 5개에서 candidate가 있었던 창 수는 B **2→3**, C **2→2**다. 유일한 attempt/progress 양성 q04는 B **없음→없음**, C **후보→후보(유보 동반)**다. q01/q06 신규 candidate는 없으나 q06 C 상태가 유보로 달라졌다. 목표는 충족되지 않았다. 이 수치는 이미 개발에 쓴 6개 창의 진단 개수이며 정확도·F1·오탐률이 아니다. primary positive 0이라는 EXP-0015의 구분도 유지한다.

## 별도 사용자 검수 4개 창

v01/v02는 E01_004, v03/v04는 E01_021로 원본 그룹은 **2개**다. q 개선에 직접 쓰지 않은 창이지만 무작위/카메라·장소 독립 맹검 표본이 아니며 일반화 성능을 추정할 수 없다. 네 창에는 기존 교정 ROI가 없으므로 full-frame만 비교했다.

| 창 / 사용자 확인 | 기존 prompt | 수정 prompt | 관찰된 차이와 한계 |
| --- | --- | --- | --- |
| v01 004 60–65s: 시도·진행 | 후보, 완료 observed 주장 | 유보, 완료 not_confirmed | 양성 후보가 사라졌다. 두 답변의 근거는 상자 이동/보행 위주여서 기존 candidate도 실제 넘기 동작을 근거 있게 설명했다고 확정할 수 없다. 수정의 유보를 개선으로 계산하지 않는다. 사용자 완료 정답은 미평가다. |
| v02 004 0–5s: 비사건 | 없음 | 없음 | 후보 없음은 양쪽 유지. 사람·차량·벽에 대한 세부 묘사는 사용자 비사건 라벨만으로 검증되지 않는다. |
| v03 021 65–70s: 문 옆 틈에서 시도·진행 | 없음 | 없음 | 둘 다 정지/대기로 설명해 시도 후보를 놓친다. 사용자가 말한 위치는 문 자체가 아닌 옆 틈이며 정확한 경계 연결과 완료는 미확정/미평가로 유지한다. |
| v04 021 0–5s: 비사건 | 후보 | 후보 | 양쪽은 보행로/횡단보도 이동 서술을 stepping_over_boundary와 완료로 선택한다. 사용자 비사건과 candidate가 충돌한다. |

시도 양성 두 창 중 candidate 출력 수 **1→0**, 비사건 두 창의 candidate 수 **1→1**이다. v 전체 candidate **2→1** 감소는 v01의 양성 후보를 잃어서 생겼으므로 개선이 아니다. 실제 입력 표본의 PTS/프레임 포함은 검증했지만 2 fps로 선택된 표본만으로 모든 원래 동작을 충분히 볼 수 있는지는 별도 사람 검수가 없으며 실패 원인 미확정으로 남긴다. 추가 질문으로 같은 영상 전체 검수를 다시 요청하지 않았다.

## 형식과 비용

| 같은 창 집합 | strict JSON 기존→수정 | 공통 후처리 파싱 기존→수정 | 출력 토큰 기존→수정 | 생성시간 합계 기존→수정 |
| --- | --- | --- | --- | --- |
| q B 6개 | 3/6→3/6 | 6/6→6/6 | 531→655 | 16.892→23.572 s |
| q C 6개 | 6/6→6/6 | 6/6→6/6 | 593→647 | 18.133→22.084 s |
| v 4개 | 2/4→2/4 | 4/4→4/4 | 389→488 | 14.654→16.198 s |

공통 후처리는 전체 응답을 감싼 JSON code fence만 제거하는 기존 규칙이다. 파싱 성공을 행동 이해 향상으로 계산하지 않는다. 이번 새 생성 20개는 strict 13개, 공통 파싱 20개이며 token-limit hit 0이다.

새 네 job의 load는 각각 3.458/2.309/2.388/2.300초, 전처리 합계는 0.729/0.335/0.409/0.386초였다. 생성 합계 76.508초, queue attempt wall time 합계 179.958초, 새 출력 2179토큰이다. PyTorch peak allocated는 최대 4469.48 MiB, peak reserved는 최대 4672 MiB였다. 별도 device sampling 사용량 최대 6982 MiB에는 다른 GPU 프로세스도 포함된다. 각 창의 응답 길이와 환경 부하가 달라 생성시간 차이를 prompt만의 인과 효과로 확정하지 않는다. 선택 창의 생성시간을 전체 영상 FPS·실시간 경보 지연으로 보고하지 않는다.

## 검증, 재현, 적용 판단

평가기는 저장 결과만 읽고 기존 parser/classifier를 사용한다. 21개 CPU 합성 계약 테스트에서 입력/질문/설정 불일치, missing/parse_failed/indeterminate, q04 소실과 단순 후보 감소, v 그룹·완료 미평가 등을 검사했다. 실제 131개 파일을 해시로 바인딩하고 기존 레코드/설정의 불변성을 확인했다. 추론 소스는 이전 구현과 같아 추론 테스트 suite 전체를 반복 실행하지 않았다. 세부 검증과 재현은 [평가 노트](EXP-0017-evaluation-notes.md) 및 실행 보고서를 따른다.

```bash
python3 scripts/evaluate_exp0017.py --run-index runtime/EXP-0017/run-index.json
python3 -m unittest tests_mvp.test_exp0017_evaluation -v
```

- 기능: 기존 큐를 통한 4개 고정 작업과 20개 응답 저장 완료. 이것은 연속 원본 전체의 새 MVP 검증이 아니라 선택한 창의 prompt 비교다. 원본 전체 MVP 실행 근거는 EXP-0013에 남아 있다.
- 행동 성능: q02/q03/q05 false candidate 감소 실패, q04 B 누락 지속, q04 C 완료 과장, v01 후보 소실 및 v03 누락. 개선안 기본 적용 보류. 기존 B/C도 성능 부족/채택 보류 상태이며, 원래 설정 유지가 성능 충족 선언은 아니다.
- 후속 우선 대상: 경계 근접·보행·횡단보도 이동과 실제 몸 올림/경계 상대 이동의 시각 근거를 더 잘 확인할 수 있는지 조사하는 별도 실험 계획. 이번에는 질문을 다시 튜닝하거나 새 입력/모델을 추가하지 않는다.
- 정답 한계: 사용자 창 관찰만 확정 라벨로 사용한다. 본문의 모델 근거 해석은 총괄 초안이다. 원시 응답, 원본/추출 미디어, 가중치, local receipts는 로컬 전용이며 공개 기록은 요약/측정값뿐이다.
