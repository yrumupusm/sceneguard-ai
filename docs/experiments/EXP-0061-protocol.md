# EXP-0061 — 검수된 오탐 우선 억제 · 첫 5영상 비교

2026-11-05. 사용자는 오탐부터 해결하고, 근거가 부족해 확인하지 못하는 실제 침입은 의심으로 유지하며 확인 누락을 분리 집계하는 방향을 승인했다. 기존 알고리즘에서 필요한 부분만 수정한다. 이른 시각 최적화·사건 묶음 전면 재설계·새 모델/검출/추적/특징 추출·영역 수정은 하지 않는다.

대조는 EXP-0060이 사용한 EXP-0058 결합85모듈(0bbc027070af9f981b6e0aa1257e2251f97729c3e7821796bc9003d37d87bece)과 보존된 최종 출력이다. 새 후보는 별도 격리 소스에서 만든다. 운영85모듈 및 기존 결과·정답·검수DB는 유지한다. 전후 서로 다른 대조를 혼합하지 않는다.

## 확인할 문제와 변경 원칙

- 011117초: 접근 후 되돌아갔다는 사용자 관찰. 연결 모호성 유예 종료 뒤 접근·소실로 확인한 사례.
- 017109.3초: 사용자가 오탐으로 판단. 약3.619픽셀 접근과 소실만으로 확인한 사례. 실제 통과는 사용자 관찰상79–86초이고,64.133333초 준비 행동 확인은 적절성 보류다.
- 0359초대: 사용자가 접근 후 되돌아간 오탐으로 판단.9.733333초 접근·소실뿐 아니라9.766667초 같은 소실의 새 출현 보조 및11.4초 기존 방향 근거가 있어 첫 통지 하나만 없애면 해결로 보지 않는다.

연결이 해결되지 않은 관측을 단순 유예 만료로 통과 근거로 승격하지 않는다. 접근 이력은 의심 유지에 사용할 수 있지만, 접근＋방향 미확정 소실만으로 확인하지 않는다. 같은 불확실한 출발·소실이 다른 보조 경로에서 다시 확인되는 우회도 검토한다. 독립적인 실제 통과 근거까지 무조건 취소하지 않는다. 시각/영상ID/추적ID 예외, 검수 라벨의 추론 입력 사용, 임계값 탐색은 금지한다. 소실 대기 시간·박스 하단 중앙·원래 검출 점수·기존 관측 연결 수치는 유지한다.

구현 담당이 정확한 변경 원리와 영향을 문서화하고, 독립 검토가 기존 경로 영향·시간 인과성·반례를 확인한 뒤 소스를 고정한다. 실제 영상 실행은 그 다음 총괄이 승인한다. 코드 통과를 오탐 해결로 표현하지 않는다.

## 첫 비교 범위와 평가

011·013·015·017·035 **5영상 전구간**만 기존 저장 측정값으로 CPU 규칙 재생한다.013·015는 기존 성공을 잃는지 보는 대조 사례다. 최대2CPU 작업, 대조 재생0회, 새 GPU/검출/추적/flow/VLM0회다. 새 조건을 고정한 뒤 영상별1회 실행하며 실패 로그와 모든 시도는 보존한다. 실제 결과에 맞춘 자동 임계값 변경·반복 탐색은 하지 않는다. 전체45개로 자동 확대하지 않는다.

평가는 공식 사건 매칭과 사용자 검수층을 분리한다. 알려진 오탐3장면의 **모든 확인 근거와 모든 카드 통지**를 점검해 시각 이동·다른 경로 재확인을 놓치지 않는다. 영상의 다른 실제 침입을 통째로 음성 처리하지 않는다. 정밀 음성 구간은 새로 꾸며내지 않고, 기존 소실/출발 관측 계보·후속 근거·저장 시각으로 감사한다. 후속 통지가 다른 실제 행동인지 애매하면 미검수로 남긴다.

공식 확인/의심 매칭, 추가 누락과 기존 확인 손실, 모든 최초 확인 시각, 이른·늦은 확인, 의심 유지/해제/확인 상태, 추가/삭제 근거와 통지, 기존 성공013·015의 변화를 함께 공개한다. 실제 침입이 의심까지만 남으면 의심 감지 성공과 확인 누락을 구분한다. 비침입 의심 유지는 확인 누락으로 세지 않는다. 이 시험의 오탐 제거를 모든 상황의 오탐0 보장으로 확대하지 않는다.
