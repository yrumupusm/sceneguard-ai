# YOLO26 첫 시험 실행의 모델 초기 상태 검사 수정

첫 실제 YOLO26m 시험은 코드 `a8d6e852800c7266eba663419fd9c916b7624a33`에서 모델을 읽은 직후 실패했다. 큐 작업과 실패 영수증을 보존했으며 검출 결과는0개다. 다른 크기나 전체45 실행으로 넘어가지 않았다. 두 실행 프로세스가 종료됐고 기존135작업/시도 행이 그대로이며 실패1개만 추가됐음을 실행 담당·총괄·독립 검토자가 확인했다.

원인은 잘못된 초기 상태 검사였다. 세 크기의 실제 공식 가중치 모두 사람 class0을 포함한80종 검출기이고 one-to-one 검출 분기가 존재한다. 그러나 저장된 가중치에는 설치된 Ultralytics8.4.192가 읽는 내부 실행 모드 값이 없어 로드 직후 `end2end=False`로 표시된다. 공식 예측 초기화는 이미 고정한 `nms=False`로부터 native 분기를 선택한 뒤 fusion을 수행한다. 총괄의 첫 검사는 그 선택이 일어나기 전에 모드가 이미 참이어야 한다고 잘못 요구했다. 합성 시험과 첫 코드 검토가 실제 가중치의 초기 모드 차이를 잡지 못했다는 한계도 남긴다.

수정은 로드 시 두 native 분기의 존재와 사람 검출 구성을 확인하고 공식 setter로 같은 end-to-end 모드를 선택하는 것이다. 실제 예측 뒤의 native 모드·FP32 검사도 유지한다. 체크포인트·입력·0.05 저장 기준·0.5 표시 기준·NMS 조건은 변경하지 않는다. CPU에서 세 실제 체크포인트를 읽고 공식 backend 초기화를 거쳐 native 모드와 FP32를 확인했다. 이 확인은 forward0회이며 GPU 시험 성공으로 세지 않는다.

미지원 분기 거절과 로드 직후 모드가 거짓인 지원 모델의 처리를 회귀 시험에 추가했다. 실패한v1의 실행 승인·중단 기록은 보존하고, 수정된 커밋과 기존136행을 고정한v2를 독립 검토한 후 새 시험을 실행한다. 큐의 실패 행 재시도나 기존 결과 덮어쓰기는 하지 않는다.
