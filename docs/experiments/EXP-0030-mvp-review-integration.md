# EXP-0030 — 현행 영역으로 사건·연결 검토·근거 영상 통합

2026-10-30. 사용자 수정 영역을 현재 설정으로 고정하고, 저장된 FCOS·ByteTrack gap·EXP-0029 관측과 특징으로 030의84–100초,007의48–105초를 처리했다. **검토 자료를 실제로 생성하는 기능과 사람의 동일성·행동을 맞히는 성능은 별개**다. 새 모델이나 자동 동일인 복원 없이 원래 사건 후보, 불확실한 연결 제안과 원본 근거를 함께 열어보는 흐름이다.

## 범위와 실행 조건

main `adaa238`을 로컬 변경 손실 없이 fast-forward했다. [후속 지시](../CODEX_MVP_CONTINUATION.md)에 따라030은 사용자 수정 파일의 SHA `8e3e66c14f0c771ca39fae595bad1c9938c5e2a78850ff50d617a05c25ab7236`,007은 현행 파일의 SHA `80b0adc3ec594670f3587d05ba9518b72513c9ad50c8f300435182143aee4a42`에 묶었다. 좌표는 로컬 전용이다. **영역 수정 전후 비교·효과 검사·재튜닝은 하지 않았다.** 과거 영역에서 만든 events 파일도 현행 후보 입력으로 쓰지 않았다.

기존 FCOS/ByteTrack/사전학습 ReID의 관측·raw ID·PTS·512차원 특징·accepted association을 그대로 읽었다. 검출·추적·encoder forward, 새 가중치, 학습, GPU 작업은 모두0회다. 현재 영역의 양측 관측 후보만 기존 `region_events`로 계산하고, upstream `mvp_review_candidates.make_feed`에 원래 gap 선 후보와 함께 전달했다. 이전 파일을 덮어쓰지 않는 `outputs/exp0030/current-v1/`에 한 번 실행했다.

기존 Orca Run에서 Sol high 구현·영상 담당, Astra high 독립 검토를 사용했다. 영상 담당의 최초 시작은 선택적 Codex 업데이트 안내 때문에 차단됐다. 업데이트를 건너뛰고 실패한 시작을 정리한 뒤 같은 Task를1회 다시 시작했다. 모델 실행 오류·GPU retry와는 다르며, 설치 버전과 기존 환경을 바꾸지 않았다.

## 바뀐 기능과 고정한 진단 기준

- `run_mvp_review.py`: 입력/소스 해시, 실제 관측 행의 완전한 분할, 대표 선택, 원래 chain을 검증한다. 원래 line 후보와 현행 양측 후보, 연결 제안·품질·Q01–Q08 감사를 결합한다.
- `mvp_review_quality.py`: 동시 관측 IoU≥0.5 또는 작은 박스 포함률≥0.8, 같은raw ID의0.2초 이내 높이/너비 비율≥1.5를 진단 플래그로 남긴다. 대표의 나머지 대표들과의 평균 유사도가0.65 미만이고 두 번째 최소 평균과0.15 이상 차이 나면 불일치 가능성을 표시한다. 실행 전 한 세트로 고정했으며, 외형 연결 임계값0.65는 그대로다. 모든 대표를 보존한다.
- `mvp_review_evidence.py`: 원본/기존raw ID/기존auto chain/검토할 연결의2×2 연속 영상, 원본 근거 클립, native PTS 대응표와 로컬 인덱스를 만든다. 실제 대응 검출 박스만 그리며, 예측 위치를 관측처럼 표시하지 않는다.

품질 기준은 설명 가능한 개발용 주의 표시다. 신체 부위·개인 수를 인식하거나 혼합 raw ID를 분리하지 않는다. 안정적인 부분·복수 인물 크롭, 완만한 ID 변질을 놓칠 수 있고, 실제 몸 움직임도 급격한 크기 변화로 표시될 수 있다. 대표 하나를 제거하거나 두 사람을 강제 병합하지 않았다.
