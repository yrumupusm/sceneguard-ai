실제 코드의 점수·크기 순위는 양쪽 모두 `score × sqrt(area)`다. 지시서의 간단한 면적 표현보다 이 실제 구현을 우선해 기록하며 코드를 변경하지 않았다. 시간 분산도 정확히 같은 초 간격이 아니라 **시간순 관측 수를 최대3개 bin으로 나눈 방식**이다. 대표 시간창과 위험 우선순위가 같이 바뀌는 묶음 비교이므로 각각의 독립 효과로 해석할 수 없다.

위험 표시는 사람 수나 신체 부위 인식이 아니다. 모든 관측이 위험해도 대표를 지우지 않으며, 경고가 없어도 복수 인물·부분 신체가 들어갈 수 있다. 선택은 전체 저장 구간의 이후 관측도 이용하는 오프라인 절차다. 실시간 경보 지연을 측정한 실험이 아니다.

기존 `(frame_index, cache_index)`의 특징은 재추론 없이 정규화해서 재사용했다. 원래 특징 파일은 바이트 그대로 보존하지만 새 JSON의 정규화 벡터 직렬화가 원래 바이트와 같다는 뜻은 아니다. 새 대표만 기존 `create_encoder`의 공식 CPU ReID 경로로 계산했다.

- 모델: 기존 `yolo26n-reid.onnx`, SHA256 `8529c383197ae4c468eda535d1b165f8b4162cf17bf5fbcff49c7cb6455bc0bb`.
- Ultralytics8.4.192, ONNX Runtime1.23.2, ONNX1.19.1, torch2.5.1+cu124, NumPy2.2.6, PyAV16.0.1, lap0.5.12. 기존 환경/의존성 유지.
- 실제 장치/공급자: CPU / CPUExecutionProvider만 사용, FP32, RGB448×448, 특징512D. 실제 모델 forward는 모두 batch1.
- 전처리: 기존 공식 gain1.02+pad10 crop, BGR→RGB, bilinear 정방형 리사이즈, FP32/255. 비교판의 저장 tight JPEG와 실제 입력 전처리 재현 그림을 구분했다. 그림은 당시 tensor 덤프가 아니라 원본·bbox로 공식 전처리를 재현한 것이다.

유일한 추가 수락은007의**raw17/t0014→raw19/t0016**이다. 유사도0.580951→0.678615로0.65를 넘었다. 원본82–85.666667초 대표와 별도로83.733333/83.8/83.866667/84.033333초 native 프레임을 대조했다. 어두운 상의·밝은 바지의 **일반 보행자 한 사람이 보도에서 연속해서 이동**하고 옆의 파란 상의 사람과 구분된다. raw17의83.8초 박스는 몸 일부로 줄고 raw19에서 길어지지만 화면의 사람 이동은 연속적이다.
