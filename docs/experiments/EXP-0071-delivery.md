## 실제 화면 확인과 제한

기존 서비스 `127.0.0.1:8765`의 EXP-0071에서 로컬 Chromium으로 다음을 실제 확인했다. 픽셀/스크린샷을 클라우드로 전송하지 않고 DOM·해시·재생 상태만 조회했다.

- 보고서·측정값·검토의 서비스 해시가 등록된 정확한 원문과 일치.
- 영상5개의 실제 디코딩, 1920×640 표시, 재생·2초 이동·0초 되감기 성공. 길이는8초3개, 약8.333초2개.
- 16.5초 재생 중 주기 갱신에도 영상 노드와 재생 유지.
- 검수 화면의 질문5개와 각 `요청 구간 보기` 버튼에서 연결된 영상의 재생·이동·되감기 성공. 답변은 전부 pending/answer_version0이며 테스트 답변을 제출하지 않음.

첫 별도 Chromium 실행은 `libnspr4.so` 로드 실패였고, 기존 로컬 browser-deps의 라이브러리 경로를 명시한 재실행이 통과했다. 새 패키지를 설치하지 않았다. 결과는 `browser.json`(실패), `browser-v2.json`(성공)에 구분했다.

기존 공통 Orca 브라우저 검사 명령은 이미 제거된 담당 슬롯 UI를 찾아 `Slot card absent`로 실패했다. 이를 성공으로 덮어쓰거나 이번 작업에서 웹 코드를 바꾸지 않았다. 현재 UI용 별도 native 점검의 첫 시도도 재생 중 폴링 검사에서 실패했다. 이때 검수 페이지에 머문 채 숨겨진 이력 상세의 영상을 검사한 경로를 확인했다. 이력 화면으로 명시 이동한 재확인에서는 보고서 해시·14지표, 영상5개 및 각 질문 영상5개의 실제 재생·이동·되감기가 모두 통과했다(`orca-browser-current-ui-v2.json`). 이 재확인에는 폴링 항목을 제외했으므로 별도 Chromium의 폴링 통과와 혼동하지 않는다. 실패 receipt도 보존했다.

보이는 질문 영상으로 추가 확인한 native 16.5초 검사에서도 노드는 유지되고 디코딩 프레임17→41은 증가했지만 종료 시 paused=true여서 반복 재생 유지 조건은 통과하지 못했다(`orca-visible-question-poll.json`). 일반 재생·seek·되감기 성공과 이 반복 재생 한계를 구분한다. 원인 해결이나 웹 코드 수정은 이번 자료 준비 범위에서 수행하지 않았다.
