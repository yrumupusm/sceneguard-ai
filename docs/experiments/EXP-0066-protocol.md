# EXP-0066 — FCOS 누락 장면의 모델별 비교

2026-11-07. 사용자가 제공한 `SceneGuard_FCOS_miss_comparison.zip`과 “이제 준비해서 모델별 비교 들어가자” 요청을 실행한다. ZIP SHA256은 `7faf28e60bd17043b4255eec1a25a9927a454a75251df848854dc3112e2538b1`이다. 시작 코드 `cbf89c236d0b0f3316362f6a31510a552e2d8f79`, 기존 로컬 변경과 EXP-0062/0064/0065 결과는 보존한다.

## 목적과 비교 범위

FCOS가 실제 사람을 놓친 장면에서도 다른 모델이 사람과 넘기 행동의 근거를 얻는지 확인한다. 사람 박스 회복, 행동 구별, 사건 확정은 별도 항목이다. 새 모델 입력을 FCOS 박스나 알림으로 제한하지 않는다. 기본 서비스 모델·판정 규칙은 교체하지 않는다.

45개 전체 원본과 native FPS의 저장 FCOS 출력을 먼저 감사한다. 알려진 006/007/030/031 사례 외에 검수된 015/039/043 박스 단절도 실제 검출 캐시와 대조한다. 추적 ID 단절이나 박스 행 수만으로 사람별 검출 FN/TP를 확정하지 않는다. 전체 가시 사람 정답이 없으면 전체 검출 재현율은 미측정이다.

실행 영역은 45개 원본 전구간으로 고정한다. 알려진 실패만 고른 짧은 구간의 수치를 전체 성능으로 확대하지 않는다. 전체 시간 범위를 1초 간격으로 관측하되 이는 매 native 프레임의 모델 추론을 뜻하지 않는다. 알려진 초 단위 사례의 추가 관측은 별도 진단으로 표시한다.

각 실제 실행 전에 공식 소스 commit, 구성 파일, 가중치 SHA256, 의존성과 전처리를 로컬 명세에 고정한다. 가중치 접근 실패, 미지원 의존성, OOM은 해당 모델의 상태로 남기며 다른 크기로 몰래 대체하지 않는다. AVA 점수나 특징을 CCTV 넘기 확률로 이름만 바꾸지 않는다.

공통 주 조건은 전체 화면, 배치 1, 16프레임, 물리 시간 간격 `4/30`초이다. anchor 기준 `-8..7` 간격의 목표 시각을 실제 native PTS의 가장 가까운 프레임에 대응하고 동률은 앞 프레임을 선택한다. 경계 밖 시각은 끝 프레임 반복으로 명시하며 관측 수를 늘려 세지 않는다. 첫 검증에서 입력 차원 호환이 필요하면 실제 고정 대안을 별도 조건으로 기록한다. R3D18의 기존 8프레임/3FPS 사람 주변 입력 결과는 원래 조건으로 보존한다.

전체 화면을 유지하는 resize/pad를 사용하고 실제 좌표 역변환을 저장한다. 모델별 기본 해상도 때문에 유효 사람 픽셀 크기가 다름을 기록한다. 동일 감시 영역/유효 사람 크기 통제 결과가 없으면 공간 통제가 완료됐다고 쓰지 않는다. 수동 사람 crop은 상한 진단이며 실제 자동 누락 복구가 아니다.

center 시각과 마지막 실제 입력 시각을 모두 저장한다. 미래 프레임을 이용한 결과를 center 시점에 발생한 알림으로 세지 않는다. CPU decode, 전처리, GPU 추론, 후처리 시간과 GPU 최대 allocated/reserved 메모리를 분리한다.

## 보호 자료와 정답

EXP-0062 AFTER 사건 기준 37/52와 기존 R3D18 가중치를 동결한다. 학교 45개와 EXP-0064 시험 자료는 학습·임계값 선택에서 제외한다. 동일 시각의 다른 사람이나 다른 출입구 후보를 성공으로 세지 않는다. 최근 EXP-0065 검수 9건을 재사용하며 034 서 있기, FP1 라벨 충돌, FP2 빈 박스/후속 월담의 시각 불확실성은 보존한다.

신규 행동 head가 필요하면 기존 보호 분할의 학습/검증 자료를 새 입력 조건에 맞춰 감사한 뒤 별도 명세로 고정한다. 사람별 정상 라벨이 있다고 화면 전체를 정상으로 만들지 않는다. 검증 음성이 앉기에 치우친 한계를 숨기거나 학교 자료로 임계값을 고르지 않는다. 확보되지 않은 정답을 모델 예측·파일명만으로 생성하지 않는다.

## 실행과 완료 조건

기존 canonical GPU 큐만 사용한다. 실제 active Orca 배정, 독립 검토, 고정 소스/입력, 기존 GPU 잠금과 실제 attempt를 검증한다. 기존 환경은 보존하고 새 의존성은 별도 환경에 설치한다. E: 정리는 사용자가 진행하며 새 파일은 Linux 저장소에 작성한다.

소량 실제 입력으로 전처리·박스 좌표·출력·자원 사용을 확인한 뒤 고정한 전구간을 실행한다. 실행 성공, 의미 검수, 성능 개선을 별도 보고한다. 모델별 미실행/실패도 표에서 유지한다. 실제 원본/박스/입력 범위/점수 비교 자료를 만들고 새로 애매한 장면만 기존 웹에 검수 요청한다. 정답이 없는 지표는 `null` 또는 미측정으로 남긴다.

진행 결과와 모델 명세는 후속 결과 문서에 기록한다. 이 문서 작성만으로 모델 준비·추론·학습·평가가 완료된 것은 아니다.
