# EXP-0037 — 영상 분석·사건 카드·검토 저장 마무리

2026-10-30. **추적 단절 후처리는 효과가 없어 미채택한다.** 기존 침입 의심 규칙·모델·사용자 영역은 유지한다. 영상 선택부터 분석·근거 영상·수동 검토 저장까지 연결하는 기능 검증이며 침입 판별 정확도가 개선됐다는 결과가 아니다.

## B. 원본 영상에서 사건 카드까지

`sceneguard.video_cards` 한 명령에 원본·C3/C6·구간을 명시하면 검출 캐시 확인 → 기존 ByteTrack gap → 접근/소실 → EXP-0035 의심 → 사건 카드 → 원본 근거 영상 → 기존 서비스 등록까지 실행한다. 원본 SHA, 모델/입력/내부 필터/카메라 설정, native PTS/time_base와 캐시 SHA를 검사한다. 현재 사용자 영역과 가림 주석을 그대로 읽는다. 캐시가 없을 때만 기존 canonical GPU 큐에서 기존 FCOS 가중치를 사용하며 활성 Run/Task/Dispatch와 lease·프로세스·소스를 검증한다.

|---|---|---|---:|---:|

전체 시간은 검증·분석·원본 디코딩·H264 근거 저장을 포함한다. 선택한 구간을 다 본 뒤 결과를 내는 **비실시간 저장 영상 분석**이다. 사건의 원본 PTS·논리적 후보 발생 시각과 실제 처리 완료 UTC/소요시간을 따로 저장한다. 알림 재생 시각이나 캐시 재사용 속도를 실시간 탐지 지연/추론 FPS라고 부르지 않는다. 두 개발 구간의 새 추적 관측·segment·events·기존 gap 알림은 보존된 이전 결과를 정확 재현했다.

새 검출은 기존 RTX3080에서1job/1attempt, FP32/batch1, FCOS COCO_V1/입력800–1333/기존 내부 설정으로 실행했다. 실제 여유6699MiB에서 기존6144MiB gate를 통과했다.90프레임과 기존 zero warmup10회를 구분한다. 검출 자식 전체17.850초, warmup1.108초, warmup 후 프레임 루프8.621초이며 PyTorch peak allocated434.083MiB/reserved472.000MiB다. 이 메모리는 다른 GPU 프로세스의 사용량을 포함하지 않는다. 새 가중치·학습·VLM·추론 retry는0이다.90프레임의 후보0은 확인된 정상 판정이나 미탐 없음의 증거가 아니다.

실제 GPU 실행은 source hash `4b260b84b776ac177347cc68e814619e5f3dafea837bdc887c032df22913d391`에 결속된다. 이후 큐가 다른 대기 작업을 먼저 실행하지 않도록 정확한 job ID를 lock/transaction 안에서 선택하는 보호와 등록 표시를 보완했다. 이 최종 큐 선택 보호는 합성 CPU 테스트로 확인했으며 **새 GPU 실행으로 재검증하지 않았다**. 실제 작업 당시 큐가 비어 있었고 실행된 job은 요청한 job이었다.27개 실행 소스의 복원 해시가 원래 queue source hash와 일치함을 독립 확인했고, 이를 최종 소스가 GPU에서 실행됐다는 주장으로 바꾸지 않았다.

최종 명령과 지원 범위는 [실행 안내](../design/MVP_FINISH_CLI.md)에 있다. `--register-config`/`--registration-id`를 포함한 동일 명령을 실제 재실행해 완료된 추적·분석·미디어의 모든 바이트를 확인하고 재사용했다.0070.223초/0300.243초/짧은 캐시0.139초이며 새 추론0, 새 등록 중복0이다. 원본·설정·코드/완료 파일이 달라지면 거부하며 다른 분석은 새 출력 경로를 사용한다.

최종 자료는 `outputs/exp0037/video007-v4/`, `video030-v3/`, `fresh007-reuse-v2/`다. 각 디렉터리에 `analysis/cards.json`, `evidence/original.mp4`, 카드별 근거 MP4, native PTS 대응, 상태·등록·단계 영수증이 있다. 실제 새 추론 계보는 `fresh007-45-48-v1/`에 별도 보존했다. 구현/등록 연결을 고치는 동안007초기3회·030초기2회의 CPU 분석/재인코딩도 있었으며 중간 출력과 비용을 `worker-delivery.json`에 보존했다. 고정 후처리 비교를 반복하거나 검출 모델을 재실행한 것은 아니다.

**원본 선택 → 선택 구간 분석 → 등록 → 원본 카드 재생 → 근거 이동 → 별도 검토 저장**을 실제 확인했다. 두 CLI의 최초 토스트는0072회/0303회, 다시 재생했을 때 추가0회였다.007 첫 자동 검증은 재생이 목표 시점 전에 멈춰 실패 기록을 남겼지만 이미 표시된2회 DOM 토스트와 영수증을 보존했고, 후속 검증에서 나머지 재생/0303회와 반복0을 확인했다. 영수증을 초기화하지 않았다. 같은 영상의45–48초와48–105초는 등록 ID로 구분해 각각 선택하며, 표시에는 구간·저장 검출 사용을 함께 보여준다. 원본 근거 재인코딩은 화질 손실이 가능한 표시 자료이며 원본 파일 자체는 보존한다.

지원 범위는 이미 설정된 C3/C6의 원본30fps·PTS 시작0·같은 영상 크기/카메라다. 카메라를 파일명으로 자동 추정하지 않는다. `--whole` 경로는 구현됐지만 이번에는 전체 원본 끝까지의 새 분석을 실행하지 않았고, 다른 영상/독립 정상·침입 검증도 하지 않았다. 개발 표본에서의 기능 확인을 범용 성능으로 확대하지 않는다.

## C. 수동 검토 저장의 실제 확인

기존 서비스의 사건 카드에 자동 상태와 별개로 검토 상태·작성자·메모·UTC 수정 시각·버전·이력을 연결했다. 선택지는 침입 의심/침입 확인/침입 아님/판단 불가다. 현재 등록된 bundle SHA·session·incident ID를 서버와 클라이언트가 대조하며 미등록 카드나 바뀐 자료에 오래된 메모를 저장하지 않는다. 같은 출처의 동시 수정도 `expected_version`으로 확인하고409를 표시한다. 메모는 HTML이 아닌 텍스트다.

실제 브라우저에서 첫 저장1, 수정2, 동시 수정3 뒤 오래된 화면의 저장409, 명시적 재확인 저장4를 확인했다. 이력4개를 덮어쓰지 않았다. 시험 메모는 모두 **Codex 기능 검증·정답 아님**, 상태는 판단 불가로 기록했으며 자동 카드의 침입 의심은 그대로다. 시험 기록을 사용자 확정 검수로 취급하지 않는다.

- 실제 자동 폴링16.5초, 수동 목록 갱신, 되감기 후 다시 이동에서도 동일 영상·카드·열린 검토가 유지됐다.
- 새로고침과 실제 서비스 종료/시작 뒤 선택한 EXP-0037/007, 원본57.9초(클립9.9초), 펼친 원래 알림/검토 상세, 버전4와 수정 이력이 복원됐다.
- 별도 로컬 검토 DB의 현재1행/이력4행과 기존 알림 영수증5행을 재시작 전후 정확 대조했다. GPU 큐 DB와 검토 DB·알림 DB는 분리했다.
- 첫 서비스 종료는 열려 있던 영상 스트림 때문에12초 내 완료되지 않았고 상태를 보존했다. 스트림을 닫은 뒤 동일 서비스만 정상 중지/시작했다. 다른 프로세스를 강제 종료하거나 새 서버를 띄우지 않았다.

이것은 로컬 저장 기능이다. 운영용 인증이나 사용자 수신을 영구 보장하는 시스템은 아니다. 서비스 재시작 때는 화면을 닫거나 영상 연결을 종료한 뒤 기존 관리 명령을 사용한다.

## 검증·한계와 완료 범위

관련 CPU/큐156테스트(새 CLI19, MVP29, 큐14, 완화24, 접근32, gap8, 카드30), 기존+새 웹 서버14테스트와 JS 회귀를 확인했다. 큐 FIFO 순서 assertion이 동시 부하 중 한 번 실패했으며 해당 사례와 전체14개를 다시 실행해 통과했다. 실패는 보존했고 알고리즘을 바꾸지 않았다. 독립 검토는 출처가 바뀐 검토 저장, resume symlink, 다른 큐 작업 실행, 같은 영상의 중복 선택지를 지적했으며 해당 결속/선택 문제를 수정·시험했다. 전체 저장소의 분리 환경 의존성을 해결하거나 전체 테스트 통과를 주장하는 작업은 아니다.
