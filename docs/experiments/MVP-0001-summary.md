# MVP-0001 — 핵심 로컬 실행 흐름과 자원 차단 결과

> **후속 상태:** 최초 자원 차단 기록은 그대로 보존한다. 같은 승인 범위의 재개 실행·통합 결과는 [EXP-0013](EXP-0013-mvp-comparison.md)이며, 실제 모델 실행은 완료했으나 행동 성능과 기본 채택은 미검증·보류다.

2026-10-28. **MVP 완성 아님.** 시간창·후보/판단 불가·근거 저장 코드와 CPU 검증은 준비했지만, GPU 자원 부족으로 새 행동 분석과 원본 전체 모델 실행은 시작하지 않았다. 기존 BATCH-0001 종료·채택 보류를 보존하며, 이번 범위를 별도로 기록하고 자동 다음 실행 없이 멈춘다.

A의 박스 경계 후보와 B/C의 행동 문장은 출력 의미가 달라 같은 정확도로 순위를 매기지 않는다. B의 과거 값은 [BATCH-0001](BATCH-0001-vlm-comparison.md), 새 입력 준비는 [EXP11](EXP-0011-fixed-camera-input.md), 원본 전체 경로/차단은 [EXP12](EXP-0012-continuous-mvp.md)가 원본이다. 후보 구성을 늘리거나 새 가중치를 받지 않았다. 이번에는 성능 부족을 개선했다고도, 새 C가 실패했다고도 결론 낼 새 응답이 없다.

## 실행 흐름과 저장 계약

[CLI](../design/MVP_LOCAL_CLI.md)와 [카메라 예제](../../configs/mvp0001_cameras.json)를 사용한다. 기존 queue의 `mvp-0001` 명령만 실제 모델을 구성할 수 있다. 원본5초 창/2.5초 간격/약2fps로 CV 후보 없이도 분석한다. 공식 시각·캡션·정답·기존 답변은 analyzer 입력에서 제외한다. C3/C6/C7 ROI는 과거 정적 배경 설정이며 C1/C4는 전체화면이다.

넘기 행동은 candidate, 접촉은 contact_review, 판단 불가/표본 부족/파싱 실패는 별도 상태다. 같은 소스·카메라·행동의 겹치는 창만 묶고 모든 constituent와 근거·불확실성·원문 참조를 보존한다. 모델의 완료 문장만으로 후보를 만들지 않는다. 사건 추정 구간·마지막 입력 PTS·원본에서 결과가 가능해진 시각·실제 출력 UTC·후속 병합/근거 저장 시각을 구분한다. 오프라인 wallclock을 실시간 경보 지연으로 바꾸지 않는다.

원본 근거는 앞뒤2초를 포함해 실제 도착 범위로 제한하며, 예측/보정된 영상으로 대체하지 않는다. 이 기능은 합성 CPU 테스트에서 확인했고 **이번 실제 원본의 새 모델 후보/근거 결과는 아직 없다**. 로컬에 보관한 새 미디어는 전처리 입력 확인용이며 결과 영상이 아니다. 웹에는 원본 참고 자료와 입력 시트를 명확히 표시한다.

## 자원 차단과 재개 조건

10:56:18 UTC RTX3080 전체10,240MiB 중 사용8,248MiB·여유1,806MiB·GPU99%를 확인했다. 실행 전 고정한 최소 여유6,144MiB에 못 미친다. Windows 쪽 외부 GPU 사용도 확인했고 사용자에게 정리를 요청했다. 외부 프로세스를 임의 종료하거나 점유 중 모델을 얹지 않았다. 모델 OOM 실패나 실행 오류 retry로 세지 않으며 실제 GPU job은 등록/시작하지 않았다.

CPU 준비에서는 기존 EXP8 adapter와 현재 adapter 사이의 정확한 코드 해시 차이로 첫 C1 재사용 검증이 중단됐다. 차이는 EXP10의 같은16384/3584000 budget dict 두 곳을 상수로 옮긴 변경이었다. 특정 두 소스 해시·해당 차이만 검증하고 실제 processor RGB/expanded prompt/native PTS/가중치/환경/생성 조건 동일성을 별도로 확인해 한 번의 수정 준비를 마쳤다. 더 넓은 의미 동등성을 추정해 허용하지 않았다. 첫 실패 기록은 남겼다.

남은 핵심 작업은 GPU 여유 확보 후 동일 승인 범위의 C 개발 baseline→근거에 따른 개선 여부 결정→B/C 원본3개 전체 실행→행동/비용 검토다. 이번 자원 차단 보고서/등록 ID는 덮어쓰지 않고 후속 실제 결과를 별도 ID/attempt로 기록한다. 작은 설정마다 재승인을 요구하는 대신 기존 한도·동결 조건을 유지한다. GPU 자원 확보는 실제 관측으로 확인해야 하며 자동 예약은 없다.

사용자 관찰은030 약84초 접근/90초 넘기,031 약33초 접촉 등 확인된 범위만 보존한다. 개별 넘기 완료·가려진 신체·정확한 onset과 미검수 정상 구간은 미확정이다. 새 모델 응답이 없어 추가 영상 의미 검수를 요청하지 않았다. 정답이 없는 정확도·F1·오탐률은 만들지 않는다.

## 후속 실행 상태 — EXP-0013

위 자원 차단 분석은 EXP-0011/12 당시 사실을 보존한다. 이후 GPU 여유가 고정 gate를 넘은 것을 확인해 총괄이 같은 Run·기존 GPU 큐에서 새 담당을 배정하고 [EXP-0013](EXP-0013-mvp-comparison.md)의 새 비교를 실행했다. 세 job은 순차 완료됐으며 전체 처리 후보·근거를 만들었다. 개발 suite 47개, Orca/등록/viewer suite 75개 통과(1개 조건부 skip)는 담당자 보고이며 독립 재실행 결과가 아니다.

EXP-0013 담당자·측정치·검토는 `records/assignments.json`, `records/catalog.json`, [독립 검토](../reviews/MVP-0002-independent-review.md), `docs/reviews/EXP-0013.binding.json`에 연결했다. 독립 검토는 현재 보고서/metrics 해시와 39개 숫자, 3개 요약 파일 해시를 확인했으며 장면의 개별 시각·raw 실행·영상은 열지 않았다. 실행 통합 성공과 행동 판단 성능은 별도다: 행동 정확도·F1·오탐률은 미산출, 제품 기본 적용은 보류. GitHub 게시와 로컬 브라우저 확인은 [전달 기록](../orchestration/MVP-0001_DELIVERY.md)의 최신 후속 절차에서 각각 증명한다.
