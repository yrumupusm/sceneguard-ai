사용자는 마지막 영상에 대해 ‘내려간 사람에게 특징점이 붙기 전에 영상이 끝나는 것 같다’고 설명했다. 이는 관찰 범위에 대한 추정으로 남긴다. 종료 뒤 특징점이 다시 사람에게 붙는지, 추적이 회복되는지는 확인되지 않았다. 클립을 연장하거나 특징 계산을 다시 실행하지 않았다.

첨부 정지 이미지는 030의 문 주변 잔상을 설명하는 로컬 근거다. 이미지 자체를 GitHub에 올리지 않는다. 화면의 선은 이전 위치를 이은 이력도 포함하므로, 눈에 남은 모든 선을 현재 배경점의 오추적이라고 단정할 수 없다. 개별 점의 현재 위치·시작/종료 시각을 새로 대응시킨 정밀 검수는 아니다.

## 결과 해석에 반영할 내용

1. **007의 접근 문맥 후보를 단순한 배경 오추적으로만 설명할 수 없다.** 첫 영상에서 사람이 잘 따라가지고도 새 후보가 나왔다는 사용자 관찰이다. 이전 접근 행동 검수를 함께 보면 사람을 따라가는 기능과 접근/침입을 구별하는 점수 규칙은 별도로 평가해야 한다. 세 후보 각각에 기여한 개별 점까지 정답으로 확정한 것은 아니다.
2. **007 63초 후보는 사람 움직임과 약간의 문·배경 혼합이 있다.** 이 답변은 특징점 대상에 대한 관찰이다. 정확한 63.066667초의 행동을 새로 ‘침입 시작’ 또는 ‘대기’로 확정하지 않는다. 기존 62.5초 대기와65초대 침입 시작 검수를 유지한다.
3. **030 87초대는 일시적으로 문에서 바깥쪽으로 물러나는 움직임과 문 잔상이 관찰됐다.** 다시 사람에게 붙는다는 사실은 클립 단위의 유용한 관찰이다. 이것만으로 후보 발생 순간에 경계를 침입했거나 반대로 침입하지 않았다고 확정하지 않는다. 정확한 후보 시각과 행동의 대응은 남은 불확실성이다.
4. **030 92초대 후보의 근거 구간에는 실제 침입 진행이 보인다.** 다만 사람과 문이 섞이고, 사람이 내려간 뒤 문에 경로가 남는다. ‘침입 장면과 시간상 겹침’은 사용자 관찰로 보강됐지만 후보가 올바른 사람 움직임 때문에 발생했다는 인과적 증명은 아니다. 기존90.4초보다 새92.2초가 늦다는 사실도 그대로다.
5. **007 64–74초 신규 후보0이라는 핵심 실패는 바뀌지 않는다.** 이번 네 영상 검수는 해당 누락 구간의 점 추적 품질을 직접 검수한 것이 아니다. 54/63초에서 잘 따라간다는 답을65초대까지 일반화하지 않는다. 저장 신호가 기준을 넘지 못했다는 기존 진단과, 필요한 사람의 유효한 변화를 어떤 점이 담았는지는 구분한다.

네 문맥의 사용자 답변은 수신 완료다. 사람 정체·개별 특징점·정확한 행동 시작 시각을 모두 확정한 정답 세트는 아니다. 정확도/F1·개별 사람 추적 성공률을 만들지 않는다. 문 잔상이 곧 후보 원인이라는 결론이나 단순 임계값 변경의 정당화도 하지 않는다.

## 결정과 보존

**기본 적용 보류를 유지한다.** 사람이 잘 추적되는 접근 문맥에서도 후보가 발생하고, 필요한007 시작 구간에는 새 후보가 없었다. 030에는 침입 문맥의 추가 후보가 있지만 조기 포착 이득은 없고 배경 혼합 및 종료 뒤 추적 여부가 남아 있다. 다음 원인 구분은 사람 경로 자체의 품질과 점수 규칙의 구별 능력을 나누는 것이다. 이번 답변을 근거로 새 조건·임계값·영역·모델을 수정하지 않는다.

새 실행/렌더/추론/특징 추적은0이며 공식 라벨·기존 출력·검토DB·통지 영수증은 유지했다. 기존 웹의 동결 결과는 등록 당시 문서로 보존한다. 이 추가 기록은 GitHub 문서와 현재 인계 지침에 반영하며, 독립 재검토·웹 재등록·최종 브라우저 검증까지 수행했다고 표시하지 않는다. 기존 브라우저 시간 초과로 남은 전달 검증 상태는 [전달 기록](EXP-0042-delivery.md)을 따른다.
