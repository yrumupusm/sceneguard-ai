# BATCH-0002 — 모델 대안 비교와 적용 판단

2026-10-29 KST. **입력 감사, RF-DETR 11프레임 실행, Qwen 4B의 고정 16개 view 생성을 완료했다. 두 신규 모델의 기본 적용은 보류하고 결합 PoC는 생략한다.** 4B는 일부 접근 장면의 잘못된 후보를 줄였지만 양성 v01에 유효한 판정을 제공하지 못하고 출력 형식 실패 6개를 남겼다. 기존 CV·MVP·프롬프트·ROI·경계 설정과 EXP-0006 적용 보류는 유지한다. 실험·회귀 검사 완료가 행동 성능 충족이나 MVP 운영 채택을 뜻하지 않는다.

## 평가 범위와 사용자 관찰

[EXP-0018 입력 감사](EXP-0018-input-audit.md)는 10개 개발창의 20개 저장 입력 변형, 200개 프레임 관측과 103개 고유 원본 프레임을 대조했다. PTS·RGB·crop·resize 출처가 일치한다는 사실과 행동을 구별하기에 충분하다는 판단은 다르다. 과거 q 실행의 processor RGB가 없어 그 당시와의 pixel 동등성은 확정할 수 없다.

검수 화면의 **원본 PTS**는 해당 프레임이 원본 파일의 시간축에서 표시되는 시각이다. 예를 들어 원본 PTS 62.5초는 잘라낸 5초 클립의 재생 62.5초가 아니라 원본의 해당 위치다. 실제 촬영 시계 시각을 뜻하지 않으며, 정수 native PTS와 time base를 곱해 초로 표시한다.

이번 사용자 확인은 별도 [입력 검수 기록](../../configs/batch0002_user_input_review.json)에 보존했다. q04는 문을 잡고 발을 올리며 완료는 관찰되지 않았다. B/C 각 입력의 가시성은 따로 확정되지 않았다. v01은 줄을 넘어 반대편에 서 있는 모습까지 보였다는 새 한정 관찰이며, 과거 완료 미평가 이력은 보존한다. v03은 문 옆 바위에 올라서는 중 끝난다. 기존 옆 틈의 시도 라벨과 이 새 관찰을 함께 기록하되 바위 올라섬을 경계 넘기로 확정하지 않는다.

q의 비시도 5개/시도 양성 1개/primary 양성 0개를 유지한다. q06의 사람·사건 없음은 030의 155–160초에만 적용한다. 006의 후기 보행은 기존 ROI 밖이므로 ROI 안 정상 통행 구분 성공으로 세지 않는다. q/v는 이미 개발에 쓰인 4개 원본의 선택창이며 독립 테스트·정확도·F1·시간당 오탐률을 만들지 않는다.

CV는 모델·전처리가 함께 다르고, VLM은 용량과 양자화가 함께 다르다. 원래 질문, ROI, PTS, 프레임 예산과 공통 parser를 유지한다. 위 비용은 각 실행의 관측이며 전체 영상 실시간 처리 성능이나 일반적인 속도 우위가 아니다.

2B는 원문 schema 11/16·코드블록 제거 후 16/16, 4B는 원문/공통 후처리 모두 10/16이다. 4B의 6개 실패를 정상이나 모델의 적절한 판단 유보로 변환하지 않는다. 생성 토큰은 각각 1,513/1,523개다. 새 실행의 준비 시간 1.592–6.481초에는 원본 디코딩/processor 작업이 포함되며, 기존 q의 저장 prepare 시간과 범위가 같지 않다. 새 실행의 반복 입력·환경·가중치 해시 검증 시간과 개별 모델 로딩, 큐 대기는 생성 시간과 분리한다. GPU allocator 수치는 다른 프로세스까지 합친 장치 전체 메모리가 아니다. 2B는 준비 전에, 새 4B 생성 peak는 입력 전송 뒤에 집계를 초기화하므로 동일 범위의 메모리 절감률을 계산하지 않는다. 4B의 별도 로딩 peak도 생성 peak와 구분한다.

## q 개발 회귀 비교

아래 `후보 없음`은 유효한 구조화 응답에 넘기 행동 분류가 없다는 뜻이며 정상 판정 성공을 뜻하지 않는다. `형식 실패`는 행동 목록이 비어 기존 공통 parser를 통과하지 못해 후보 판정이 null인 경우다. 코드블록 제거만 허용하고 의미를 바꾸는 보정은 하지 않았다. B는 전체 화면, C는 기존 고정 ROI다.

| 창과 사용자 관찰 | 기존 2B B / C | 새 4B B / C | 남은 문제 |
| --- | --- | --- | --- |
| q01: 사람의 넘기 시도 없음 | 후보 없음 / 후보 없음 | 형식 실패 / 형식 실패 | 새 B 원문에는 완료 주장도 남음. 파싱 null과 별개로 보존하며 정상 판별 성공으로 세지 않음 |
| q02: 접근만 | 후보 / 후보 없음 | 후보 없음 / 후보 없음 | 후보 분류 대조이며 세부 영상 근거의 완전한 검증은 아님 |
| q03: 접근, 시도 없음 | 후보 없음 / 후보 | 후보 없음 / 후보 없음 | B는 여전히 완료를 관찰했다고 주장 |
| q04: 문을 잡고 발 올림, 완료 미관찰 | 후보 없음 / 후보 | 후보 없음 / 후보 | B의 시도 누락 지속. C 완료 응답은 기존 판단 불가 → 새 미확인 |
| q05: 접근만 | 후보 / 후보 | 후보 없음 / 후보 없음 | B는 여전히 완료를 관찰했다고 주장 |
| q06: 해당 5초에 사람·사건 없음 | 후보 없음 / 후보 없음 | 형식 실패 / 형식 실패 | 030 전체 영상의 부재 정답으로 확장하지 않음 |

접근 세 창의 여섯 view는 모두 파싱됐고, 잘못된 후보는 기존 B 2개/C 2개에서 새 B 0개/C 0개로 줄었다. 그러나 나머지 비시도 두 창의 네 view는 **판정 불능인 파싱 실패**로 남는다. 이를 비시도 전체에서 `오탐 0/10`이나 정상 판별 10건으로 보고하지 않는다. q04 B는 계속 누락되고 q03 B/q05 B의 완료 주장은 접근-only 사용자 기록으로 뒷받침되지 않는다. 이 부분 결과만으로 새 모델을 채택하지 않는다.

## v 구간과 통합 판단

| 창과 사용자 관찰 | 기존 2B | 새 4B | 해석 |
| --- | --- | --- | --- |
| v01: 줄 넘기 후 반대편에 서 있음 | 후보, 세부 설명의 근거 문제는 기존 기록 참조 | 빈 행동 목록으로 형식 실패, 후보 판정 null | 양성 장면에서 유효한 출력을 제공하지 못함. 정상 판정이나 확정적 유보로 바꾸지 않음 |
| v02: 비사건 | 후보 없음 | 유효 응답, 접촉 분류, 넘기 후보 없음 | 넘기 후보 부재와 별개로 접촉 동작의 실제 근거는 미확정 |
| v03: 문 옆 바위 올라섬, 기존 옆 틈 시도 관찰과 경계 관계 미확정 | 후보 없음 | 형식 실패, 후보 판정 null | 바위 올라섬을 경계 넘기로 확정하지 않으며 확정적 경계 누락으로 세지 않음 |
| v04: 비사건 | 후보 | 유효 응답, 넘기 후보 없음 | 후보 분류는 비사건 관찰과 부합하나 세부 행동의 실제 근거는 미확정 |

CV의 새 박스가 실제 시도 인물을 제대로 복원했는지 미확정이고, VLM도 q04 전체 화면 누락과 v01의 사용 불가능한 출력을 남겼다. 상호 보완을 입증할 근거가 부족하므로 **이번 CV+VLM 결합 PoC는 실행하지 않는다.** 후보 두 개를 기본 파이프라인에 연결하지 않으며 기존 구성도 운영 성능 충족으로 승격하지 않는다.

v01의 형식 실패는 시도/완료가 보이는 양성에서 사용 가능한 후보를 받지 못한 결과다. v03의 빈 행동 목록 및 사람 부재 서술은 사용자의 바위 올라섬 관찰과 대조되는 **텍스트 검토 초안**이지만, 경계 통과 정답이나 특정 인물의 행동 시각을 새로 확정하지 않는다. 코드블록 제거 이외의 의미 보정이나 정답별 프롬프트 수정은 하지 않았다.

## 실행·검토·전달

선정 근거는 [RF-DETR ADR-0018](../decisions/ADR-0018-batch0002-cv-candidate.md), [Qwen ADR-0019](../decisions/ADR-0019-batch0002-vlm-candidate.md), 실행 상한은 [계획](BATCH-0002-model-upgrade-plan.md)과 [실행 계약](BATCH-0002-execution-contract.md)에 있다. 기존 Astra max 총괄·Sol high 담당·Astra high 독립 검토와 단일 GPU 큐를 사용한다. 새 가중치는 CV 1개와 VLM 1개, 환경은 별도 두 개다. 실행 오류 재시도 상한은 작업별 1회이며 성공한 프레임/생성은 다시 실행하지 않는다.

VLM은 17개 새 queue job/attempt에서 16개 생성을 각각 한 번 완료했다. 추가 한 건은 v01의 과거 입력 기록에 집계 해시 필드가 없어 발생한 모델 로딩 전 준비 오류다. 원 실패와 12개 성공 출력을 보존하고, 독립 검토한 메타데이터 호환성 수정 뒤 v01의 논리적 retry 한 번만 사용했다. 최초 소스는 `952c52f`, 수정 후 네 v 실행 소스는 `78ba67d`이며 모델 설정은 동일하다. 관련 28개 회귀 검사와 전체 115개 중 113개 통과/2개 skip, 네 실제 v의 CPU processor·RGB·확장 질문 동등성 확인을 기록했다. 초기 테스트의 fixture 오류와 기존 queue 테스트의 순서 경합 실패도 숨기지 않고 EXP-0020에 남긴다.

입력 감사와 CV의 독립 검토, 웹 등록·실제 영상 재생/seek와 GitHub byte 검증은 통과했다. VLM의 최종 독립 검토·등록·GitHub·실제 화면 증거도 [전달 기록](BATCH-0002-delivery.md)에서 각각 확인한다. 원본 영상·이미지·weights·raw 결과·runtime·인증정보는 로컬에만 둔다. 기존 읽기 전용 화면을 재사용하며 새 웹 기능은 추가하지 않는다.

이번 신규 가중치 2개·고정 기준 비교 한도를 종료한다. **추가 GPU 작업·자동 재시도·새 모델 탐색을 예약하지 않는다.** 다음 별도 검증 후보는 같은 4B와 원래 질문을 고정하고, v01 같은 전체 화면 양성에 배경 기준 고정 감시 영역 입력 한 축만 비교하는 것이다. q04의 B/C 차이는 이 가설을 검토할 근거지만 ROI가 원인이라는 증명은 아니다. 사람 정답 위치나 사건 시각으로 프레임별 crop을 만들지 않으며, 이번 배치에서 이 후속 실험을 실행하지 않았다.
