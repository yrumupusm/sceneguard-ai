# EXP-0028 — 실제 연속 FCOS 캐시의 strict / 3초 기억 비교

2026-10-30 KST. [실행 명세](EXP-0028-practical-tracking.md)와 [최신 사용자 범위](../CODEX_PRACTICAL_TRACKING.md)에 따른 실제 CPU 실행 기록이다. **030/007의 strict/gap 재생과 조건부 사전학습 BoT-SORT/ReID 한 조건을 실제 실행했지만, 030의 중요한 월장 전후 ID 단절은 남았다.** 007의 기존 접근 구간 후보는 strict 2→gap 0→ReID 1이다. 기술 실행과 비교 영상 생성은 완료 범위이고, 같은 사람 연결·정밀 통과 성능·기본 채택은 확정하지 않는다. 기존 로컬 웹 등록·브라우저 실제 재생·GitHub 전달은 코디네이터의 별도 확인 대기다.

이번 실행은 기존 사전학습 FCOS COCO_V1의 원본 프레임별 캐시를 읽었다. EXP-0026 best/last, Roboflow 데이터, 새 검출기 추론·학습·GPU 작업은 사용하지 않았다. 원본 영상·기존 캐시·기존 ByteTrack/경계 구현과 과거 EXP-0005 결과는 보존한다. 사람이 부여한 정체 정답 없이 ID 유지·박스 증가를 실제 사람 복원으로 해석하지 않는다.

## 실제 실행과 재현

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*gap*.py' -v
.venv/bin/python -m sceneguard.replay_gap_tracking 030 007 --retain-seconds 3 \
  --output-root outputs/exp0028/practical-v1
.venv/bin/python -m unittest discover -s tests -p 'test_exp0028_renderer.py' -v
.venv/bin/python scripts/render_exp0028_tracking.py 030 007
```

지정 27개 테스트와 새 렌더러 계약 5개 테스트가 통과했다. 실제 ByteTrack 의존성 통합 실행은 기존 `.venv`의 Python 3.10.12 / numpy 2.2.6 / scipy 1.15.3 / lap 0.5.12 / cython-bbox 0.1.5에서 성공했다. 렌더러는 기존 av 16.0.1 / Pillow 12.3.0을 사용한다. 모델 로딩·검출 추론·재식별을 CPU 재생에 포함했다고 보고하지 않는다.

입력은 `outputs/cv_phase2d/cache030`(480프레임, 원본 PTS 84.000000–99.966667)과 `cache007`(600프레임, 48.000000–67.966667)이다. **전체 캐시 구간**을 재생한 것이며 두 원본 MP4 전체 처리가 아니다. 원본 간격 1/30초, native PTS 간격 512, time_base 1/15360이다. 캐시·metadata SHA와 모델 SHA를 검증했다. 새 `strict/frames.jsonl`은 두 영상 모두 `outputs/cv_phase2e/track{ID}/C/frames.jsonl`과 **바이트 동일**하며, 후보는 `condition` 이름만 제외한 모든 필드가 동일하다. 재관측 목록도 동일하다.

초기 #1은 ReID에서 90.600초에 끝나고, 91.866667–92.033333초에는 새 #8이 생겼다. gap #1과 동일 cache index 검출을 ReID #1이 153개, #8이 6개 공유하므로 같은 캐시 궤적 자체가 분리됐음을 확인할 수 있다. 이후 gap #9/#11과 각각 42/22개 검출을 공유하는 ReID #12(95.333–96.733초)/#13(97.333–98.233초)도 별도다. 이전 흰옷 인물 관찰에 연결한 중요한 전후 ID 단절은 해결되지 않았다. 또한 ReID #1에 89.133333→90.566667의 1.433초 재관측이 생겼지만 인접 인물과의 정확한 대응·오연결 여부는 미확정이다.

**007:** ReID #1은 49.033333–67.966667초, #2는 49.100–61.900초로 초기 숫자 ID가 더 오래 관측된다. 그 관측이 기존 여러 ID의 검출을 합쳐 이어받은 사실만으로 같은 인물을 정확히 연결했다고 할 수 없다. #1은 gap #1/#5/#8 등의 캐시 검출과 겹치고, #2는 gap #2/#7과 겹친다. 기존 겹침·중복 박스 문제와 함께 봐야 한다. ReID #2의 후보는 추정 56.300000초/실제 emission 56.733333초로 **기존 접근·부분 박스 변화 구간에서 다시 1개 발생**한다. 56.666667초 이후 gap #2는 더 높은 점수의 긴 박스로 전환하지만 ReID #2는 낮은 점수의 짧은 부분 박스 캐시 행을 계속 연결해 .2초 반대편 누적을 채운다. 같은 dwell인데 결과가 다른 이유는 선택된 실제 검출 행도 달라졌기 때문이다. gap의 0개보다 유리하다고 보고할 수 없고 실제 통과 성공으로 바꾸지 않는다. ReID의 동일 ID 내 2초 cooldown은 반대 방향 후보 1개를 억제한 것으로 기록됐다. 물리적 정체/완료 GT 없이 오연결률·IDF1·행동 F1은 산출하지 않는다.

## 로컬 비교 영상과 남은 전달

각 `outputs/exp0028/practical-v1/review{030,007}/`에 `continuous_original_strict_gap.mp4`(1920×600, 전체 화면 3열)와 `focused_original_strict_gap.mp4`(1800×780, 표시 전용 크롭 3열)를 **생성하고 전부 재디코딩 확인했다**. 030은 각 480프레임/16초, 007은 각 600프레임/20초다. 030 파일 크기는 8,558,892/15,580,023바이트, 007은 5,623,845/10,104,432바이트다. 원본/strict/gap 순서이며 원본 패널 사람 위에는 표시하지 않는다. 실선은 관측 bbox, 자홍 점선은 예측, ID색과 별도 표는 점수·H/L·UNCONFIRMED를 표시한다. 흰 경계·노란 ROI, bbox 하단점, 실제 emission과 candidate 시각을 구분한다. 원본 native PTS와 time_base를 매 프레임 표시한다. 크롭은 표시용이며 입력·추적 좌표를 바꾸지 않는다.

별도 `review{030,007}_reid/`에 `continuous_original_gap_reid.mp4`와 `focused_original_gap_reid.mp4`를 원본/gap/BoT-ReID 순서로 추가했고 전체 재디코딩을 통과했다. 030은 각 480프레임/16초, 8,726,886/15,969,758바이트이고 007은 각 600프레임/20초, 5,773,105/10,398,212바이트다. 이 네 파일도 원본 상대 native PTS와 정확히 일치한다. 기존 네 파일은 덮지 않았다. 생성 명령은 아래와 같다.

```bash
.venv/bin/python scripts/render_exp0028_tracking.py 030 007 \
  --reid-root outputs/exp0028/reid-v1
```

렌더러는 매 관측의 cache index/점수/정규화 bbox를 원래 캐시와 대조하며, 원본 MP4 SHA를 기존 detector 입력 SHA와 검증한다. 출력 MP4를 전부 재디코딩해 프레임 수와 상대 native 시각을 원본 캐시와 정확 비교하고, strict/gap 각 영상에서 입력·core·과거 출력 39파일의 SHA 보존을 검증했다. 상세 로컬 영수증·개별 ID 목록은 `review{ID}*/render_receipt.json`이다. 이후 ReID 표시 지원을 추가하기 전 최초 생성 소스는 `renderer_strict_gap_source.py`에 로컬 동결해 영수증의 renderer SHA와 대조했다. `records/EXP-0028/metrics.json`의 **58개 항목**은 기존 metrics validator와 모든 source SHA·실측값 source pointer 대조를 통과했다. 매체·원시 좌표·프레임·영수증은 로컬 전용이며 Git에는 넣지 않는다.

현재 strict/gap 및 ReID 계산과 **총 8개 비교 영상 생성·전체 재디코딩 시각 검증을 완료**했다. 030/007 후보 출력 화면에서 원본/관측 박스/점수·H/L/서로 다른 실제 emission 표시가 읽히는 것을 확인했다. 이것을 전 프레임 정체 검수나 브라우저 실제 재생 완료라고 바꾸지 않는다. 기본 적용·동일 사람 연결 성공·정밀 통과 성능은 보류하며, 기존 로컬 결과 화면 등록·실제 화면 재생·GitHub 전달은 코디네이터의 별도 확인 대기다. 자체 파인튜닝이나 Roboflow 검수 완료를 진행 조건으로 되돌리지 않는다.
