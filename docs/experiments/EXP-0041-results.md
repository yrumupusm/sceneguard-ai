# EXP-0041 — 사건을 먼저 묶고 통지를 결정한 실제 비교

2026-10-31. **저장 점수 재생과 사건 묶음 보존은 완료했다. 0.55는 접근·대기 경보를 줄이는 유망한 개발 설정 후보이며, 기본 MVP를 자동 교체하지 않는다.** 원래 5개 사건 이력을 보존하면서 통지 사건은 5→3개다. 필요한00770.133333초·03090.4초 첫 의심은 같은 시각에 남는다. 추가 제외 장면의 사용자 확인과 독립 검증 범위는 아래와 구분한다.

## 실행 범위와 출처

깨끗한 로컬7ab5494를 main53ed3dc로 fast-forward했다. 같은 Orca Run에서Sol high가 CPU 실행, Astra high가 독립 검토, Terra high가 기존 화면 최소 연결을 담당했다. 설치·GPU·새 검출·영상 특징 추적·VLM·모델·학습·영역 변경0이다. 저장 입력은EXP0040의007/030 baseline·audits·summary·request뿐이며 원래18후보 중 소실14건 전체에 같은 세 기준을 적용했다.007/030 각1회, 실행 오류/재시도0이다.

원본 사건 생성·3초 간격/첫 후보부터최대10초 묶음·점수 가중치·경로 충돌·별도 경계 근거 보호는 유지했다. `seed_decision`의 점수 기준만0.55/0.65/0.70으로 비교하고 새 규칙이나 특정시각/ID 예외를 추가하지 않았다. 기준을 넘는 관측 연속성은 **통지 제외 근거**이며 침입 확률이 아니다.

새 순서는 전체 후보 → 원래 사건 이력 → 사건 안의 통지 대상이다. 검토 전용 행도 사건 연결에 남는다. `first_alert_pts`는 첫 원래 후보, `first_notification_pts`는 실제 첫 통지 대상의 논리 시각이다. 첫 후보가 검토 전용이고 나중에 통지 대상이 들어오면 `updated, notify=true`에서 알리며 과거로 소급하지 않는다. 이번 실제 자료에서는 이 지연 유형이 없고 합성 시험으로 확인했다.

## 설정 후보와 연결 방안

사건을 먼저 묶는 처리 순서는0.70에서도 카드 분리 결함을 해소하므로 유지할 구성 후보다.0.55는 알려진 접근 첫 경보를 줄이고 필요한 기존 의심을 보존한 **우선 개발 시연 후보**로 고정한다. 다만 추가 제외 장면과 다른 영상의 검증이 남으므로 운영 기본 적용·침입 성능 충족으로 표시하지 않는다.0.65/0.70은 접근 사건 첫 경보를 줄이지 못했다.

연결 지점은 기존 전체 후보 스트림 뒤 `NotificationGrouper.push(event, notify_candidate=...)`이며, 원래 사건 묶음 전에 행을 삭제하지 않는다. 기존 연속성 판단 helper의분할을 통지 정책으로만 넘기고 `notify`/`first_notification_pts`를 소비한다. 시각별 원래 행·검토 전용 이력을 보존하고 운영 통지 영수증은기존별도영역 그대로쓴다. 지금은저장결과비교로만연결하며 `live_notifications_enabled=false`다. 새 검출흐름이나실시간연속성계산의도입까지끝난것으로표현하지 않는다.

검토 전용 행이 사건을 이어주면가까운다른상황을같이묶을가능성이있으며3초/10초 기존한계를유지한다. 임계값 추가탐색·새학습·기본MVP 교체는 하지 않는다.
