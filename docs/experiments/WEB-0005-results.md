# WEB-0005 — 실험별 검수 진입과 답변 처리 연결

2026-11-03. 실험 상세 오른쪽에 **영상 검수로 이동** 버튼과 검수 상태를 연결했다. 공통 영상 검수 탭은 제거했다. 실제 서비스의 EXP-0044 이동·재생·되감기·새로고침·복귀와 모바일 표시를 확인했고, 격리된 임시 저장소에서 답변 저장·AI 처리·수정·서비스 재시작 유지를 검증했다. 모델·검출·영역·판정 결과는 변경하지 않았다.

## 사용자가 보는 변화

- 각 실험 목록에 요청이 있으면 **! 검수 필요 N건** 또는 처리 상태가 표시된다. 상세의 오른쪽 버튼은 그 실험의 검수 페이지로 이동한다.
- **검수 필요 → 검수 완료·AI 확인 대기 → 반영 검토 중 → 반영 완료/보류**를 구분한다. 새 답변 수정은 AI 확인 대기로 되돌아간다. 요청이 없는 실험은 **검수 요청 없음**이며 완료가 아니다.
- 검수 화면에는 해당 실험에 연결된 질문·영상·사건 자료만 표시한다. 요청 구간 보기, 선택형/직접 답변, 검토자, 메모, 답변·처리 이력을 제공한다. 기존 사건/박스/누락 검수도 유지하고 검토자·메모에 표시 이름을 붙였다.
- 자동 갱신은 작성 중인 답변이나 재생 화면을 교체하지 않는다. 저장 전 질문 새로고침을 막고 입력을 보존한다. 저장 중에는 입력을 잠가 제출한 답변과 화면의 답변이 달라지지 않게 한다.
- 같은 bundle을 여러 위치에서 열어도 검수 라디오 선택은 서로 간섭하지 않는다. 실험별 영상 선택 저장 키를 분리했다.

새 요청 저장소는 공통 runtime의 `review-requests.sqlite3`다. 웹은 답변 저장만 제공하고, 요청 생성·AI 확인·반영 기록은 로컬 CLI로 처리한다. 작업 시작 지침에 `pending --include-acknowledged` 조회와 관련 답변 반영 절차를 추가했다. 서버가 AI나 모델을 자동 실행하지는 않는다. 운영 요청을 임의로 생성하지 않았으며 실제 초기 조회 결과는 **0건**이다.

## 발견과 수정 이력

- 기본 `.venv`에는 FastAPI가 없어 최초 시험 import가 실패했다. 실제 서비스의 기존 `.venv-orca-lab`으로 실행했으며 패키지 설치나 환경 변경은 하지 않았다.
- 새 route import 후 기존 incident 모듈을 직접 먼저 읽는 시험에서 순환 import를 발견했다. same-origin 검사를 요청 처리 시 가져오도록 바꿨고 기존 직접 import 시험이 통과했다.
- 독립 검토에서 저장 중 편집 손실, 시계가 없는 artifact 단독 요청 시각, 중복 검수 라디오 그룹을 확인했다. 입력 잠금, 시각 지정은 등록 bundle만 허용, 렌더 인스턴스별 라디오 이름으로 수정 후 재검증했다.
- 기존 Node fixture가 직접 자식 textarea·삭제된 링크·이전 저장 키를 가정해 실패했다. UI 구조에 맞게 고치되 기존 동작 검증은 유지했다.
- 첫 격리 서버 재시작은 브라우저 미디어 연결 때문에 종료 대기 시간을 초과했다. 브라우저 연결을 먼저 닫고 격리 서버에 종료 대기 한도를 지정한 재실행에서 종료·시작과 데이터 유지가 통과했다. 운영 서비스 재시작은 기존 소유권 확인 명령으로 수행했다.

구현 담당과 독립 검토는 기존 Orca Run에서 수행했다. [독립 검토](../reviews/WEB-0005-independent-review.md)는 최초 발견과 수정 후 결과를 구분한다. 사용자 관찰의 정확도나 침입 판정 성능을 개선한 실험은 아니다.

## 한계와 운영

과거 자유 메모나 예전 검토 상태를 새 요청의 완료로 소급 변환하지 않는다. 질문이 없는 과거 실험은 요청 없음으로 남는다. AI 반영 상태는 에이전트가 정확한 답변 버전을 읽고 CLI로 실제 처리 이력을 기록해야 바뀐다.

시각이 있는 질문은 재생 시계가 등록된 bundle을 사용한다. artifact만 연결하는 질문은 시각 없이 가능하다. 해당 실험에 영상이 없으면 다른 실험 영상을 대신 보여주지 않는다. 기존 MVP 통합 결과의 등록 소속은 그대로 유지하며 이번 UI 작업에서 과거 등록을 재분류하지 않았다.

같은 실험의 폴링/이력 복귀는 초안을 유지하지만, 다른 실험의 검수로 이동하거나 브라우저를 닫기 전에는 저장해야 한다. 요청에 묶인 원문은 불변이며 실제 반영은 새 후속 문서·결과·코드에 기록한다. 기존 원문을 변경하면 이전 요청의 후속 처리가 거부된다.
