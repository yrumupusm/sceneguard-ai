## 실행과 독립 검토

main53ed3dc를 로컬 변경 없이 fast-forward했다. 기존 Orca Run에서 Sol high 담당을 배정했고 담당3의 결과 미등록·진행 중 상태를 실제 브라우저에서 확인했다. 007/030 저장 점수를 각각 한 번 실행해 0.55/0.65/0.70을 비교했다. 실행 오류·재시도 0, 새 GPU/특징/검출/추적/VLM 0이다. CPU 117시험과 실제 6결과 검증이 통과했다. 0.70에서도 카드가 분리되지 않고 원래 ID/소속이 보존된다.

Astra high는 원래 18개 payload, 5사건 소속, 14감사행, 세 기준, 첫 통지, 시각별 snapshot을 독립 대조했다. 46합성시험과 추가 7시험을 확인했으며 CPU117개와 중복 합산하지 않는다. 보호 17,095파일 7,816,589,743바이트와 queue50/50·검토2/이력5·영수증10은 독립 재검사에서도 같았다. [독립 검토](../reviews/EXP-0041-independent-review.md)는 보고서와 측정값의 정확한 SHA에 결속됐다.

실행 소스는 main53ed3dc 바이트 그대로다. 최소 웹 어댑터와 회귀 수정은7903bfc, 실제 보고서·측정값·검토·등록은6a5d682에 커밋했다. 기존 점수·raw·영상·DB는 커밋하지 않았다.

## 기존 화면 연결과 실패 기록

새 contract `group_all_then_notify_v1`을 검증하고 전체 사건 이력과 통지 사건을 구분한다. 기존 baseline은 검증 후 메모리에서 같은 표시 contract로 변환하며 원본 파일은 유지한다. 시각별 snapshot·첫 통지·검토 전용 이력은 현재 PTS까지만 표시한다. 비교 보기는 통지 영수증 claim을 비활성화한다.

기존 서비스의 소유 프로세스 identity를 확인하고 두 SQLite 논리 백업/무결성 검사 뒤 기존 lab stop/start로 재시작했다. 새 서버나 큐는 없다. 서비스가 읽는 app.js/incident.py의 SHA를 확인했고 이후 등록 자료는 기존 폴링으로 반영한다.

웹 Python16시험·JS문법 검사가 통과했다. 기존 Node fixture는 등록 URL에 experiment_id 쿼리가 없는 것을 가정해 실패했고 수정 전 HEAD에서도 같은 실패를 재현했다. 한 줄 fixture 수정 뒤 기존 재생/seek/무음 갱신/영수증/폴링/선택 시험을 한 번 통과했다. 처음 Python 시험명 오타도 별도 실패 로그로 보존했다. 이는 실험 실행 오류와 구분한다.

## 등록과 실제 화면

기존 complete 절차로 담당3에 보고서·31측정항목·독립 검토·13기존 영상 참조를 등록했다. 같은 완료 명령 재실행은 `already_registered`로 중복을 만들지 않았다. 이전39 catalog 행과13 incident 등록을 보존하고 baseline/0.55/0.65/0.70 ×007/030의8보기를 추가했다.

실제 브라우저에서 보고서·31측정항목·2그래프·검토와13영상 각각의 재생/seek를 확인했다(`web-video-receipt.json`). 8보기의 원래 후보 시각별 사건 이력/통지 사건/첫 통지/검토 전용 참조와 시작 시각으로 되감기를 확인했다(`web-views-retry-receipt.json`). 0.55의007 첫 사건은 검토 전용에 남고70.133초 이후에만 필요한 통지 사건이 나타난다.03086.033초 사건도 검토 전용이며90.4초 통지 사건은 유지된다.0.65/0.70과baseline의 첫 통지는 원래 시각 그대로다.
