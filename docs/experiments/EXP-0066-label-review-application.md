# EXP-0066 — 사람 위치 라벨 검수 반영

2026-11-08. 사용자 검수로 **행동 대상의 위치 주석과 화면 내 모든 사람의 검출 정답이 다름**을 확인했다. 여섯 구간의 답변을 읽고 학습 후보/보완 대상으로 분리했다. 검출 모델 추가 학습은 아직 실행하지 않았다. 검수 완료와 학습 데이터 완성은 구분한다.

## 받은 답변과 적용 범위

웹에서 저장한 답변 다섯 건과 5번에 대한 사용자 채팅 관찰 한 건을 사용했다. 3번은 수정 답변 버전2, 나머지는 버전1이다. 5번은 앞서 재입력이 필요 없다고 안내했으므로 채팅 원문을 기존 요청에 `사용자 채팅 관찰 · Codex 전사`라는 출처와 함께 기록했다. 사용자가 웹 버튼을 눌렀거나 AI가 영상을 새로 판단한 것으로 기록하지 않았다. 기존 답변/처리 이력은 보존한다.

| 번호 | 원본 표시 시각(초) | 관찰 | 적용 |
|---|---|---|---|
| 1 | 33.000–41.000 | 넘는 사람 외의 사람은 박스가 없음 | 25프레임 전체 사람 검출 학습 보류 |
| 2 | 13.333–21.333 | 보이는 사람 모두 박스 있음 | 기존 train의 25프레임만 준비 자료로 추출 |
| 3 | 53.000–61.000 | 약60초부터 박스가 사라짐 | 경계/누락 문제로 25프레임 보류 |
| 4 | 15.667–23.667 | 보이는 사람 모두 박스 있음 | 기존 train의 25프레임만 준비 자료로 추출 |
| 5 | 13.333–21.333 | 뒤따르는 사람의 박스 없음; 영상 끝 이후 월담 여부 모름 | 기존 validation의 25프레임 보완 대상으로 보존 |
| 6 | 3.333–11.333 | 보이는 사람 모두 박스 있음 | 기존 validation의 25프레임만 준비 자료로 추출 |

이는 표시된 구간의 **사람 박스 누락 여부** 검수다. 정밀 좌표·행동 종류·시작/종료·프레임 번호 해석을 전부 인증한 답변이 아니다. 전체797개 라벨이나 보이지 않는 프레임으로 확대하지 않는다. 박스 없는 구간을 정상/빈 배경으로 확정하지 않는다.

3번은 표시 프로그램이 현재 있는 박스를 숨긴 문제가 아니다. 기존 origin1 표시에서 59.333초까지3개, 59.667초2개, 60초1개, 60.333초부터0개로 원본 주석이 끝난다. 앞부분53–54초에도 박스가 없고 중간에는 서로 다른 두 박스가 actor0을 공유한다. 사람 정체성을 자동 병합하지 않으며, 사용자 관찰을 근거로 경계의 정답을 임의 연장하지 않는다.

5번의 라벨에는 wall_over 행동 주석만 있다. 채팅 관찰의 뒤따르는 사람이 다른 시점의 actor1과 같은 사람인지, 이후 실제로 넘는지는 확정하지 않는다. 행동 대상만 표시한 주석으로는 정상일 수 있지만, 전체 화면 사람 검출기 학습에 그대로 쓰면 미주석 사람을 배경으로 취급할 수 있다.

## 실제 준비 결과

`scripts/export_reviewed_person_pilot.py`는 답변 버전·바인딩·원래 분할·리뷰/계획 해시를 검증하고, **2·4·6번 75프레임(train50/validation25), 기존 박스100개**를 추출한다. 각 원본의 SHA와 실제 RGB SHA, native PTS, 해상도를 표시 자료와 대조한다. 프레임과 기존 좌표를 PNG/YOLO person 형식으로 저장하고 원래 행동/actor 주석은 별도로 보존한다. 원래 촬영 그룹과 원본 해시의 분할 중복은0이다.

로컬 산출물은 `outputs/model-comparison/exp0066/reviewed-person-pilot-v1/manifest.json`, 답변/선택 근거는 `runtime/model-comparison/exp0066/label-review-followup/reviewed-v1/`에 있다. 1·3·5번75프레임은 보완 대상으로 남긴다. 이 준비 자료는 `training_release=false`이며 정밀 좌표와 시간 정렬 검증을 마친 완성 데이터셋이 아니다. 월담 후보는 모두 보류됐고, 남은 validation25프레임은 앉기뿐이다. 이것만 학습해 학교 CCTV 월담 개선을 주장하지 않는다.

별도 객체 라벨 ZIP도 조사했다. Training46,080개와 Validation5,760개, 총51,840개 JSON에서18종 객체 클래스가 나왔지만 person 클래스는 없었다. Training의 빈 JSON1개는 파싱 실패로 별도 보존했다. 영상/이미지 추출이나 모델 추론 없이 스키마만 확인했으며, 시설물 객체 박스를 사람 정답으로 대체하지 않는다.

## 다음 학습 전에 필요한 작업

1. 월담 학습 후보에서 넘는 사람과 주변 사람을 모두 포함하는 위치 주석을 보완한다. 기존 모델은 초안 보조에만 쓰고 예측을 그대로 정답으로 승인하지 않는다. 실제로 보이는 프레임을 대상으로 하며 가려진 사람의 위치를 추측하지 않는다.
2. 부분 주석을 그대로 활용하려면 미주석 사람을 배경 손실에서 제외하는 방법을 별도 설계·검증해야 한다. 현재 구현/검증되지 않았으므로 일반 YOLO/EVAD/STMixer 학습에 바로 적용하지 않는다.
3. 앉기에만 치우친 검증 정상 구성을 보행·대기·접근 후 돌아가기로 보완한다. 같은 촬영/멀티카메라 자료를 train과 validation에 나누지 않는다. 학교45개와 EXP-0064 시험 자료는 계속 보호한다.
4. 동일 데이터/입력/후처리·선택 규칙을 고정한 후 YOLO26m/l/x와 EVAD-B/L·STMixer의 실제 가중치 추가 학습을 진행한다. 기존 사전학습 결과를 보존해 같은 대상·시점의 복구와 새 누락을 비교한다. 후보 수 증가를 성능 향상으로 세지 않는다.

지금 남은 문제는 사용자에게 같은 의미 질문을 다시 받는 일이 아니라 **빠진 위치 주석을 보완하는 일**이다. 이번 검수 반영은 위치 주석 자동 생성, 행동 정답 소급 수정, 모델 학습 완료나 학교 성능 개선을 뜻하지 않는다.

## 재현과 검증

```bash
.venv-exp0066-encoders/bin/python -m unittest tests.test_reviewed_person_pilot
.venv-exp0066-encoders/bin/python scripts/export_reviewed_person_pilot.py \
  --review outputs/model-comparison/exp0066/detector-label-review-v1/review.json \
  --responses runtime/model-comparison/exp0066/label-review-followup/reviewed-v1/acknowledged-answers.json \
  --decisions runtime/model-comparison/exp0066/label-review-followup/reviewed-v1/decisions.json \
  --plan outputs/model-comparison/exp0066/head-plan-v2/manifest.json \
  --output outputs/model-comparison/exp0066/reviewed-person-pilot-v1
```

재실행은 새 출력 디렉터리를 지정한다. 기존 산출물을 덮어쓰지 않는다. 변경 답변·미검수 프레임·분할 변경·촬영 그룹 누수·빈 라벨의 배경 승격을 막는9개 시험을 통과했다. 최초 실행은 Python3.10의 `hashlib.file_digest` 미지원으로 추출 시작 전 실패했고, 스트리밍 SHA 구현으로 수정 후 같은 환경에서 재실행했다. 이는 데이터 검증이며 모델 성능 시험이 아니다. 원래 웹 등록 보고서/지표/바인딩/미디어는 수정하지 않는다.

실제 추출75프레임의 이미지/라벨 해시와100개 박스 행을 다시 대조했다. 출력 manifest SHA는 `1df00c365ed086e3d6a2fa801a65fdf78bda5f41361c600c3ce3c237385ff814`다. 웹 API에서 여섯 요청 모두 해당 답변 버전의 `applied` 처리를 확인했다(3번 요청 version5, 나머지 version4). 1·3·5번의 반영은 **보완 대상 제외 목록 적용**이며 박스 수정 완료가 아니다. 기존 결속된 보고서·지표·검토·바인딩 네 파일은 해시가 그대로다. 공개 요약은 [검수 적용 기록](../../records/EXP-0066/label-review-application.json)에 있다.

이번 상태 표시의 별도 Chromium 확인은 `libnspr4.so` 누락으로 브라우저 시작에 실패했다. 답변 저장과 API 상태 조회는 성공했지만, 이번 변경 후 실제 화면의 배지 표시를 재확인했다고 주장하지 않는다. 서비스나 기존 검수 자료는 재시작/교체하지 않았다.
