# EXP-0010 — Qwen 전체 화면 픽셀 예산 대조: 실행 전 결정

2026-10-28 총괄 결정. EXP-0008의 기준 job `e15b2f2fe1744eac816fef216a131374`, attempt `8b93c06304724009b8ca5a0d15a28288`의 여섯 응답을 확인한 뒤, **Qwen 개선 조건 한 개**만 실행한다. 같은 배치의 baseline 보존, 새 ID/큐 job/attempt를 사용한다. 실효 모델 담당은 Sol high, 독립 검토는 기존 Astra high다.

## 실패 근거와 가설

EXP-0008은 6개 생성 완료, strict JSON2/6·펜스 제거 후6/6, OOM/반복/길이 한도 실패0이다. 그러나 02는 기존 몸 올리기/넘기 관찰과 달리 열린 문·횡단보도 통행을 설명하고, 04/05는 대기 중심으로 넘기를 놓친다. 01/02/04/05/06은 자기 근거에서 반대편 이동을 설명하지 않으면서 완료 `observed`를 출력한다. 따라서 출력 형식만 바꾸는 개선은 이번 행동 구분 문제를 검증하지 못한다.

가설은 작은 사람의 화면 정보 손실이 일부 행동 누락에 기여할 수 있다는 것이다. **원인 확정이 아니다.** 기준은 전체1080×1920 입력을448×768로 줄였다. 더 큰 전체 화면 입력에서 행동 근거가 개선되는지 확인하되, 완료 환각이나 유보 부족이 그대로일 가능성을 함께 평가한다. 특정 사람 위치 crop·클립별 frame 선택·정답 제공은 하지 않는다.

## 한 번만 고정하는 변화

- Qwen video processor의 `size.longest_edge`: **3,584,000 → 7,168,000**. 이 API 필드는 영상 전체 픽셀 예산이며 최종 가로 길이를 직접 지정하는 값이 아니다. 공식 전처리로 나온 실제 해상도/grid/visual tokens를 기록한다.
- `shortest_edge=16,384`, 기존10프레임·원본 PTS/전체 화면, 모델 revision/BF16/SDPA, prompt, seed0/greedy/max384/rep1, batch1은 그대로다.
- 모든6클립에 같은 한 설정. 실제 해상도는 CPU 전처리 검증으로 확인할 수 있으나 결과를 보고 예산을 다시 고르지 않는다.
- RTX3080 baseline peak allocated 약4.34GiB와 작업 전 실제 여유를 근거로 두 배 예산을 한 번 시도한다. 성공 보장이 아니며 OOM/실패도 보존한다. 자동 예산 축소·새 모델·반복 탐색 없음. 실행 오류 retry 최대1회이며 동일 설정에서만 허용한다.
- 기존 공통 큐의 고정 command 안에 `qwen_high_pixels` 한 변형만 등록한다. 별도 큐나 외부 실행 경로는 없다. Smol baseline이 끝나고 큐가 유휴인 뒤 등록 코드를 변경한다.

## 판정

기존 동일 관찰 초안을 기준으로 여섯 클립의 행동 부합, 실제 넘기 누락, 근거 없는 설명/완료, 불확실성 유보를 나란히 검토한다. 응답의 넘기 단어만으로 개선이라고 하지 않는다. strict 및 후처리 JSON 파싱과 속도/메모리는 별도 표다. 더 큰 입력도 실패하면 해당 조건을 실패로 남기고 추가 조건을 시도하지 않는다. 최종 일반화 정확도·최적 설정·자동 채택은 판단하지 않는다.
