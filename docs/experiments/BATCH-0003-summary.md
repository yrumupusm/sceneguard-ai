# BATCH-0003 — YOLO26m-Pose 실행 실패와 평가 미완료

2026-10-29 KST. **실험 어댑터의 호환성 오류 두 건으로 smoke가 실패했고, 허용된 오류 재시도 한 번을 소진해 GPU 실행을 종료했다.** 관절 출력은 0개다. YOLO26m-Pose의 사람/관절 품질 또는 접근과 넘기 구분 능력을 평가한 결과가 아니다. 준비·테스트 통과와 실제 실행 성공을 구별하며 기본 CV/VLM은 유지한다.

## 실제로 수행한 범위

공식 `ultralytics 8.4.192`/COCO `yolo26m-pose.pt` 한 개만 별도 환경에서 준비했다. 기존 11개 진단 PTS와 지정된 다섯 창을 합쳐 267개 고유 프레임을 고정했다. full-frame 640/FP32/batch1/conf>0.25, 관절 진단 confidence>=0.5, end2end/NMS-free 한 조건이며 학습·추가 모델·VLM 실행은 없다. 정확한 출처·해시·조건은 [ADR-0020](../decisions/ADR-0020-yolo26m-pose.md), 입력/예산 계약은 [실행 계약](BATCH-0003-execution-contract.md)에 있다.

기존 Run/공통 GPU 큐에서 두 번의 smoke 작업을 실행했다. 최초 실패 작업은 변경하지 않고, 수정된 소스의 별도 작업을 한 번의 논리적 retry로 연결했다. 나머지 265개는 enqueue/실행하지 않았다.

| 항목 | 확인한 사실 | 판정 |
| --- | --- | --- |
| 준비·CPU 검사 | 267개 입력·단일 가중치·격리 환경 고정. 수정 전 68개 중 67통과/1skip, 수정 후 70개 중 69통과/1skip. 독립 검사 7개→9개 통과 | 준비 완료. 실제 API 호환성의 모든 조건을 검증한 것은 아님 |

## 오류와 사전 검토의 한계

첫 소스 `b52ac221a2e43924f86efd8fbd32a0df4973ceec`의 직접 unfused 호출 경로는 공식 backend가 수행하는 `inner.end2end=True` 선택을 빠뜨렸다. 최초 결합 assertion은 실제 속성값을 기록하지 않아 당시 실패 항목을 로그만으로 단정할 수 없다. 별도 retry의 초기화 전후 기록은 같은 checkpoint에서 이 선택이 필요함을 뒷받침한다.

수정 소스 `1b12d85c20ba922de5062148045281849055ef9e`의 첫 호출은 `BaseModel.predict()`가 받지 않는 `visualize=False`를 전달했다. 고정 버전의 signature는 `predict(self, x, profile=False, augment=False, embed=None)`다. `embed`는 지원되며 문제 인자는 `visualize`다. 네트워크 예측 결과가 반환되기 전에 실패했다.

두 문제는 **실험 연결 코드의 오류**이며 모델의 사람/관절 인식 실패 사례가 아니다. 사전 합성 검사와 독립 검토가 전체 호출 인자의 호환성을 놓쳤다. 이 검사의 부족을 모델 벤치마크나 가림 문제로 설명하지 않는다. 실패 이후 실행 코드를 다시 바꾸거나 세 번째 시도를 하지 않았으며, 실패 집계·정적 signature 검사는 별도 CPU 기록으로 남긴다.

## 비용과 평가 가능 범위

두 실패의 모델 로딩 시간은 각각 0.3475초, 0.3690초이고, queue attempt 경과는 약 9.211초, 9.182초다. 두 번 모두 기존 free VRAM 6144MiB gate를 통과했다(7172/7169MiB). OOM이 원인은 아니다.

기록된 모델 **로딩 구간** allocator peak는 각각 98,152,448 bytes(약 93.61MiB)다. 전체 프로세스·입력 전송 이후·성공 추론의 peak를 뜻하지 않는다. 두 번째 작업은 입력 준비/전송 뒤 호출에서 실패했으며 전체 추론 peak와 처리 FPS는 미측정이다. 파라미터 로딩 비용을 영상 처리 성능으로 바꾸어 보고하지 않는다.

실제 사람·관절 정확성, 정상 접근과 넘기 구분, 관측 단절, accuracy/F1/FPR 및 운영 가능성은 모두 미측정이다. 결과 화면의 참고 영상은 입력 장면 확인용이며 새 pose overlay나 성공 예측이 아니다. 출력이 없어 이번에는 추가 사용자 관절 검수를 요청하지 않는다. 기존 사용자 관찰·공식 라벨·EXP-0001~0020은 보존한다.

## 다음 결정에 필요한 근거

기본 모델을 교체할 근거는 없다. 다음 별도 범위를 정한다면 같은 checkpoint·설정의 공식 호출 인자와 head 초기화를 CPU 계약으로 먼저 검증하고, 성공한 소규모 smoke에서 실제 원본/관절 대응을 확인해야 한다. 그 이후에만 관절 누락·혼동·연속성 및 물리적 경계 해석에 근거해 행동 규칙 진입을 판단할 수 있다. 이번 배치에서 그 후속 GPU 실행을 예약하거나 수행하지 않는다.
