# EXP-0028 — 짧은 누락을 허용하는 실용형 추적·경계 후보

> 2026-10-30 후속: [실제 strict/gap 및 조건부 ReID 결과](EXP-0028-results.md), [ReID 실행 상세](EXP-0028-reid-comparison.md)를 우선한다. 아래 미실행 상태는 원격 초기 코드 작성 시점의 이력이다.

## 현재 상태

**코드 구현 및 합성 CPU 테스트 27개 통과. 실제 CCTV 캐시 재생·ByteTrack 통합 실행·영상 검수는 아직 하지 않았다.** 테스트는 경계 상태 19개와 가짜 adapter를 사용한 캐시/실행 계약 8개다. 이를 실제 동일 인물 재연결 성공이나 CCTV 성능으로 표현하지 않는다.

## 이번 사용자 결정

직접 파인튜닝한 EXP-0026 best/last는 이번 구현에서 사용하지 않는다. 가중치와 실패 기록을 삭제하지는 않는다. Roboflow 라벨 의미 검수도 다음 작업의 필수 조건에서 제외한다. 목표는 모든 프레임의 완벽한 사람 검출이 아니라 **넘기 전후의 사람을 가능한 범위에서 연결하고 통과 후보·근거 영상을 만드는 미니 프로젝트**다.

이전 배치의 추가 실험 금지는 종료된 범위의 이력으로 보존한다. 이번에는 아래 실용형 비교를 진행한다. 보안·원본 보존은 유지하되 모든 장면/모든 프레임의 정밀 정답을 먼저 완성해야만 진행하는 방식은 사용하지 않는다.

## 구현

- `sceneguard/gap_boundary.py`: 관측 누락 시 경계 상태를 즉시 삭제하지 않고 ID별 마지막 실제 관측으로부터 최대 3초 보존한다. 예측 위치는 메모리 만료 시간을 연장하거나 통과 경보를 단독 발생시키지 않는다. 재관측 뒤의 실제 관측으로 반대편 상태를 확인한다.
- `sceneguard/replay_gap_tracking.py`: 기존 **사전학습 FCOS COCO_V1의 연속 검출 캐시**를 동일 입력으로 재생한다. `strict`는 기존 ByteTrack low 연결 + 기존 경계 규칙, `gap`은 같은 ByteTrack의 유지 프레임 수를 실제 프레임 간격 기준 약 3초로 늘리고 새 경계 규칙을 사용한다. 새 검출기 추론이나 학습은 없다. FCOS를 최종 검출기로 채택했다는 의미가 아니라, 이미 있는 연속 캐시로 먼저 규칙 변경을 확인한다는 선택이다.
- 기존 `boundary.py`, `byte_adapter.py`, vendored ByteTrack 및 과거 결과는 수정하지 않는다. 새 CLI만 별도로 사용한다.

`gap` 초기 설정은 기억 3초, 반대편 실제 관측 누적 0.2초 및 최소 3회, 같은 ID의 경보 간격 2초다. 누락 시간 자체를 관측 시간으로 더하지 않는다. 한 프레임 누락은 관측 누적을 잠시 멈출 뿐 이전 쪽 상태를 지우지 않는다. 수치들은 시작 설정이지 최적값/정확도 보증이 아니다. 추적 buffer·경계 기억·확인/중복억제가 함께 달라지는 실용형 구성 비교이며 단일 원인 효과 실험은 아니다.

**새 경계 모듈은 동일 인물을 스스로 알아보는 ReID 모델이 아니다.** 추적기가 같은 ID로 재연결했을 때 경계 쪽에서 이전 상태를 잃지 않도록 하는 코드다. 3초 buffer는 ID 재연결을 허용할 뿐 보장하지 않는다. 잘못된 ID 연결과 전후 검출 자체가 없는 경우는 그대로 실패할 수 있다.

## 실행

저장소 루트의 기존 CPU 추적 의존성이 있는 환경에서:

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*gap*.py' -v
.venv/bin/python -m sceneguard.replay_gap_tracking 030 007 \
  --retain-seconds 3 \
  --output-root outputs/exp0028/practical-v1
```

해당 환경에 기존 ByteTrack 의존성(numpy/scipy/lap/cython_bbox)이 없다면 프로젝트에서 EXP-0005를 실행한 환경을 사용한다. 이 CLI는 GPU를 로드하지 않는다. 같은 결과 디렉터리는 덮어쓰지 않으므로 재실행이 필요한 경우 새로운 출력 경로를 사용하고 변경한 조건을 기록한다.

입력은 `outputs/cv_phase2d/cache030` 및 `cache007`의 `run.json`/`person_cache.jsonl`이다. 기존 약 30fps 연속 캐시만 지원하고 불규칙 시각/프레임 생략 입력은 거부한다. 모델 SHA와 캐시 해시를 검사하며 다른 모델의 캐시를 같은 입력인 것처럼 처리하지 않는다. 출력은 `track030/{strict,gap}` 등의 `frames.jsonl`, `events.jsonl`, `reobservations.jsonl`, `summary.json`이다. 원시 좌표는 Git 제외 `outputs/`에만 둔다.

## 로컬에서 이어서 할 일

1. 위 두 연속 구간을 실제로 재생하고, 기존 렌더러를 활용해 **원본 / strict / gap** 비교 영상을 만든다. 실제 관측과 예측만 있는 구간은 표시를 구분한다. 넘기 전/가림/넘은 후의 ID와 알림 시점을 영상에서 확인한다. 기존 렌더러의 A/B/C 고정 경로는 새 strict/gap 경로와 다르므로 원본을 덮지 말고 새 출력용으로 연결한다. 렌더링은 이 패치에서 아직 구현·실행하지 않았다.
2. 같은 사람 연결/잘못된 사람 연결/실제 통과 후보/접근 중 잘못된 경보를 사건 단위로 간단히 기록한다. 박스 수나 ID 유지시간만을 성공 지표로 삼지 않는다. 통과 뒤 다시 나타나는 장면이 기존 캐시 밖에 있다면 해당 구간을 미평가로 두고, 필요한 연속 구간만 같은 사전학습 검출기로 확장한다. GPU 추론이 필요할 때만 기존 프로젝트의 GPU 큐를 사용한다.
3. 짧은 가림 뒤에도 ID 단절·오연결이 주요 문제로 남으면 **동일 검출 입력 + BoT-SORT/ReID 활성 구성 1개**를 비교한다. 외형 계산에는 원본 사람 이미지가 필요하므로 박스 JSON만으로 ReID를 수행했다고 하지 않는다. 공식 지원 API/사전학습 임베더/사용조건을 확인하며 자체 재학습하지 않는다. 이 단계는 이 패치에 구현되지 않았다.

실제 비교에서 충분히 연결되는 장면은 MVP 시연으로 사용하고, 비슷한 복장·긴 가림·동시 월장·부분 신체 박스에서의 실패는 한계로 기록한다. 기존 bbox 하단 중심의 기하학적 한계는 남아 있다. 급격한 실제 왕복을 2초 cooldown이 억제할 가능성도 있다. 변경 결과가 좋아 보인다는 이유만으로 법적 침입/물리적 월장 완료까지 자동 확정하지 않는다.
