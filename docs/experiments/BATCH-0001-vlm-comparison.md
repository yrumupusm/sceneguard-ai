# BATCH-0001 — 두 로컬 VLM의 CCTV 행동 구분 비교

2026-10-28. 같은 EXP-0007 개발 클립6개를 Qwen3-VL-2B와 SmolVLM2-2.2B에 입력했다. 추가 모델은 Smol 한 개다. 기존 CV·추적·경계 규칙 및 EXP-0006 기본 적용 보류를 유지한다. [고정 계약](BATCH-0001-plan.md), [선정 ADR](../decisions/ADR-0015-first-vlm-comparison-batch.md), [독립 검토](../reviews/BATCH-0001-independent-review.md).

## 평가 범위

기존 사용자 관찰과 Codex 검수 초안에 대한 **응답 근거 검토**다. 이번 클라우드 에이전트는 CCTV 픽셀을 새로 받아 검수하지 않았다. 모델의 단어·ID·완료 선언을 정답으로 쓰지 않으며, 정밀 정답·독립 테스트·최종 정확도/F1/오탐률은 없다. 같은 카메라의 여러 클립이 포함된다. 미리 선택한5초 클립 분석이며 연속 영상 자동 사건 발견이나 실시간 탐지 지연 측정이 아니다.

공통 영어 질문, 출력4항목, seed0/greedy/max384/rep1, batch1을 생성 전에 고정했다. 기존 EXP-0007 한국어 결과와는 질문 조건도 달라 정확 재현이나 언어만의 효과로 해석하지 않는다. 원본1920×1080의 동일10프레임·순서·native PTS를 재사용하고, 모델별 공식 영상 전처리 차이는 별도 기록한다. Qwen 기준448×768/1680 visual tokens, Smol384×384/810 tokens다. 서로 다른 구조의 토큰 단위를 같은 정보량으로 간주하지 않는다.

## 기준 결과의 행동 검토 초안

| 클립 / 기존 관찰 초안 | Qwen 기준 EXP-0008 | Smol 기준 EXP-0009 |
|---|---|---|
| 01 일반 접근·대기 | 접근/대기는 부분 부합. 근거는 접근인데 완료를 선언 | 통행/대기 enum과 근거의 경계 넘어가기 표현이 모순. 구체적 시각 근거 없음 |
| 02 몸 올리기·넘기 진행 | stepping enum이 있으나 열린 문·횡단보도 통행이라는 근거가 기존 관찰과 불일치. 넘기 이해 성공으로 세지 않음 | 통행/대기만 설명해 기존 넘기 관찰 누락 |
| 03 후기 일반 통행 | 대기 중심이라 부분 부합/행동 차이. 가림과 위치 판단의 불확실성 언급 | 통행 enum이지만 근거는 넘어가기. 일반 통행을 넘기로 오설명할 우려; 완료 indeterminate만으로 적절한 근거 유보라고 보지 않음 |
| 04 다른 넘기 | 정지·대기로 설명해 몸/다리 올리기 누락. 완료 근거 부족 | 대기 enum과 stepping 근거가 모순. 신체 움직임 근거가 없어 성공 판정 불가 |
| 05 다른 넘기 | 대기/통행 중심, 넘기 누락. 가방/자전거 등의 세부는 현재 기록으로 확정 못함 | 다섯 action enum을 모두 나열하고 근거는 통행. 넘기 단어만으로 부합 판정 불가 |
| 06 접촉·가림 불확실 | 통행+contact를 적지만 근거는 울타리 근처 위치뿐. 불확실성 없이 완료 선언 | 모든 action enum과 추상적인 uncertainties 반복. indeterminate가 있어도 관찰 근거에 따른 유보를 확인하지 못함 |

Qwen 기준의 완료 `observed`는01/02/04/05/06에서 나타난다. **다섯 확정 오탐**이라는 뜻이 아니라, 응답 자체에 반대편 이동 근거가 없고 기존 관찰의 완료 미확정 상태와 충돌한다는 뜻이다. Smol은 완료 observed0개지만 일반적 유보 문구를 적었다는 사실만으로 더 잘 보정된 판단이라고 주장하지 않는다.

실제 입력에는 EXP-0007에서 검수한 02의 몸 상승·문 위 자세, 04의 다리 올림 표본이 그대로 있다. 이번 입력 해시/PTS 확인은 그 이력을 연결하며 새 픽셀 검수가 아니다. 05의 작은 신체 및06의 접촉·가림 식별 충분성은 사람 확인이 필요하다. 로컬 웹에02/06을 우선 확인 대상으로 표시하고 나머지 입력도 열 수 있게 한다.

## 형식과 실행 비용

| 조건 | 원문 JSON / 허용 후처리 | 평균 생성 초 (범위) | peak allocated GiB | 실행 실패/재시도 |
|---|---|---:|---:|---|
| EXP-0008 Qwen 기준 | 2/6 → 6/6 | 2.692 (2.136~3.430) | 4.342 | 0/0 |
| EXP-0009 Smol 기준 | 6/6 → 6/6 | 1.874 (1.224~2.354) | 4.519 | 0/0 |

공통 후처리는 전체를 감싼 단일 코드 펜스 및 양끝 공백만 제거한다. 의미 수정/잘린 JSON 복구는 없다. 형식 통과가 행동 개선은 아니다. 모델+processor load는 Qwen2.494초, Smol2.748초다. warm 파일 캐시와 현재 화면 점유를 포함한 단일 배치이며 cold-load/통제된 속도 벤치마크가 아니다. 생성 시간은 generate와 GPU 동기화이며 전처리·원본 최초 디코딩·큐 대기·클립 확보 시간과 다르다. Smol 출력이 더 짧고 입력량도 달라 속도 차이를 모델 구조 하나로 설명할 수 없다.

## 개선 결정

Qwen의 원문은 형식보다 행동 누락과 근거 없는 완료가 문제다. 전체 화면 픽셀 예산만 두 배로 하는 [EXP-0010 사전 계획](EXP-0010-qwen-pixel-budget-plan.md)을 하나 고정했다. 작은 사람 정보 손실은 가설이며 원인으로 확정하지 않는다. Smol은 enum/근거 모순과 선택지 반복에 대해 현재 근거에서 한 수치만 바꿔 설명 가능한 행동 개선 가설을 정하기 어려워 추가 조건을 실행하지 않는다. 개별 클립 답에 맞춘 프롬프트 수정은 하지 않는다.
