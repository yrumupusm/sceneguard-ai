# EXP-0039 — 검출 누락과 추적 단절을 구분하고 원본 영상으로 보강

2026-10-31 사용자 승인. 추가 학습·데이터 수집·수동 바운딩박스 제작은 하지 않는다. **CV의 넓은 침입 의심 생성·출입구별 사건 카드를 유지하고, VLM은 선택적 참고 수단으로만 둔다.** 기존 승인 종료 문단은 과거 기록이며 이번 작업을 막지 않는다.

## 목적과 준비 상태

박스 ID가 끝났는데도 원본에 대상이 계속 보이는 경우와, 직접 관측할 수 없게 된 경우를 구분할 추가 정보를 얻는다. ‘ID 소실 = 실제 침입’이라는 새 규칙을 만들지 않는다. 출발 영역·정확한 동일인·이동 방향·VLM 답변을 의심 생성의 필수조건으로 다시 추가하지 않는다.

추가 소스:
- `sceneguard/gap_observation_support.py`: 모든 저장 검출과 추적 연결 상태 감사, 원본 특징점의 짧은 전후방 LK 추적. 새 가중치 없음.
- `sceneguard/exp0039_application.py`: 기존 EXP-0035 결과와 원본을 읽기 전용으로 검증해 감사 JSON, 특징점 경로, 원본 근거 이미지를 생성.
- `tests/test_gap_observation_support.py`: **22개 합성 시험 통과**. 실제 OpenCV로 합성 픽셀 이동·정지·화면 흔들림·특징점 소실을 시험했다. 실제 007/030 및 기존 저장소 전체 회귀·사용자 로컬 환경의 실행은 아직 미수행이다.

GPU·실제 CCTV를 실행했다고 보고하지 않는다. 새 코드만으로 오탐 감소를 주장하지 않는다. 기본 판정/카드/검토 DB는 변경하지 않는다.

## 1. 기존 관측을 빠짐없이 진단

최신 main을 로컬 변경 보존 방식으로 반영한다. 기존 실행 환경과 기존 Run·작업자 흐름을 사용한다. 새 서버나 실행 큐는 필요 없다.

각 영상의 EXP-0035 소실 의심 **전부**를 처리한다. 007의 정상 접근만 성공 사례로 골라내거나 70–73초를 ‘정답 시간’으로 규칙에 넣지 않는다. 참고 비교 범위는 007 정상 접근 52.5–58초와 기존 의심 70–73초, 030 접근·90–94초·후기 구간이다.

```bash
.venv/bin/python -m unittest discover -s tests -p test_gap_observation_support.py -v
.venv/bin/python -m sceneguard.exp0039_application \
  --baseline outputs/exp0035/007-v1.json --output outputs/exp0039/007-v1
.venv/bin/python -m sceneguard.exp0039_application \
  --baseline outputs/exp0035/030-v1.json --output outputs/exp0039/030-v1
```

경로가 다르면 실제 기존 EXP-0035 결과 위치를 찾아 인수로 전달한다. 누락된 원시 결과를 공개 보고서 숫자로 역산하지 않는다. `.venv`에 cv2/PyAV가 없으면 이미 갖춘 CV 환경을 사용하고 기존 환경을 무조건 갱신하지 않는다.

알림 직전 마지막 관측부터 **그 알림이 처음 발생할 수 있었던 시각까지만** 사용한다. 이후 재등장을 소급해 과거 판단의 근거로 삼지 않는다. 구분 항목:

| 저장 근거 | 해석 |
|---|---|
| 다른 확정 ID의 검출이 근처에 있음 | 연결 단절 또는 다른 사람일 수 있음; 동일인 정답 아님 |
| 미확정/미연결 검출이 근처에 있음 | 검출은 남았는데 기존 추적 관측에서 제외됐을 가능성 |
| 추적 점수 하한 아래의 저장 검출만 있음 | 진단 근거. 기존 추적 임계값은 그대로 |
| 해당 위치에 저장 검출이 없음 | 저장된 detector 출력 부재. 원본 사람 부재라는 뜻 아님 |

`detections`와 `states`에 같은 cache_index가 중복돼도 한 검출로 센다. `lost_prediction`은 실제 관측에 섞지 않는다. 현재 FCOS 내부 필터에 이미 제거된 출력은 캐시에 없으므로, ‘원본 전체 후보가 없다’고 확대하지 않는다.

## 2. 짧은 원본 영상 추적

각 소실 이전의 실제 박스를 자동 시작점으로 잡고, 최대 약 0.75초의 이전 관측과 기존 소실 대기 구간만 읽는다. 원본 해상도/PTS를 사용한다. 새 모델·사람 라벨·박스 작업은 없다.

`goodFeaturesToTrack` + `calcOpticalFlowPyrLK`의 전후방 오차 검사를 사용한다. 대상 박스 안쪽에서 점을 고르고 다른 검출과 겹친 부분은 제외한다. 주변 배경점의 이동과 대상점의 이동을 따로 기록한다. 관측이 끊긴 뒤 새로운 점을 재주입하지 않는다. 점이 사라졌다가 갑자기 다른 사람 위에서 복원된 것처럼 표시하면 안 된다.

- 실제 검출은 사각형, 영상 대응점은 점/경로로 구분한다. 영상 대응점을 실제 새 검출 박스나 숨은 사람 좌표로 표시하지 않는다.
- 정지한 문·배경의 점이 오래 살아남는 것만으로 대상이 계속 보인다고 판단하지 않는다.
- 화면 전체 흔들림은 배경 움직임과 대조한다. 배경 기준이 부족하면 유보한다.
- 원본의 다른 사람으로 옮겨 붙을 수 있으므로 복수 후보·시작 겹침은 별도 표시한다.
- **보조 경로 실패는 기존 침입 의심의 취소 조건이 아니다.** 이 조건들은 특징점 신뢰도만 위한 것이며 CV 의심 생성의 새 허들이 아니다.

출력은 `summary.json`, 소실별 `sXXXX-support.json`, `evidence/`의 시작·최종 관측·알림 시각 원본 이미지다. 저장된 점 경로를 기존 비교 영상 위에 덧붙인 짧은 시연 자료도 만들고 기존 화면에 등록한다. 기존 MP4/원본/출력은 덮어쓰지 않는다.

## 3. 오탐 감소는 별도 비교 사본에서 확인

이 모듈의 기본 출력은 **알림 변경 0인 진단/보조 자료**다. ‘점이 살아남았음’만으로 정상 알림을 삭제하는 실수를 피하기 위한 구분이지, 개선 비교를 하지 말라는 뜻이 아니다.

`image_continuation_supported_review_only` 사례에서 실제 원본과 점 경로를 확인한다. 같은 대상의 이미지 정보가 문 앞에서 계속 이어지고, 문/다른 사람으로 옮겨 붙지 않았으며, 다른 침입 근거를 지우는 경우가 아니라면 **원본 알림을 보존한 별도 제안 보기**에서만 해당 소실 알림의 반복 통지를 줄이는 방안을 한 번 비교한다. 자동 `침입 아님`/`침입 확인`이나 ID 병합은 하지 않는다. 단순히 주변에 사람이 남아 있음은 제외 근거가 아니다.

기존 gap/양측 관측 알림을 지우지 않는다. 마지막 관측 박스의 출발 영역이 불명확하다는 이유만으로 새 광학 흐름 정보를 검토하지도 않고 버리지 않는다. 위치·방향은 원본 경로의 보조 설명으로 사용한다. 검토만으로 효과가 있다고 주장하지 말고 제안 보기의 알림/카드와 원래 참조를 실제 비교해라. 기능 시험용 표기를 사람 정답으로 바꾸지 않는다.

숫자는 반드시 **전체 후보, 알려진 정상 접근의 오탐, 필요한 의심 유지, 잘못 낮춘 의심, 판단 유보**를 구분한다. 기존 18알림/5카드라는 분모가 변했다면 어떤 원래 행이 어떻게 처리됐는지 남긴다. 중복 카드 감소를 침입 정확도 개선으로 계산하지 않는다. 자동 기본 채택은 하지 않는다.

## 4. 저장 검출이 정말 없는 경우만 제한적인 확대 검출

먼저 CPU 결과를 확인한다. 검출 출력이 계속 남은 구간을 근거 없이 새 detector로 다시 돌리지 않는다.

알림 대기 구간의 절반 이상에서 `no_local_box_in_saved_cache`이고 원본에는 관측 가능한 대상이 남은 진단 사례가 있으면, **동일 FCOS 가중치로 기존 카메라 ROI를 입력 크롭으로 사용하는 별도 비교**를 허용한다. 최대 2개, 각 최대 3초의 연속 구간이다. 없으면 이 단계는 실행하지 않는다. 적합한 사례를 이 문서의 정답 시간에 맞춰 만들지 않는다.

카메라 ROI·침입 선·사용자 영역은 그대로다. 기존 비교와 동일 모델/내부 필터/점수/입력 크기를 사용하고, 달라지는 것은 모델 입력이 전체 화면 대신 기존 ROI라는 점뿐이다. CPU 준비에서 정확한 crop offset→원본 좌표 복원·경계 자름·중복 검출 처리를 테스트하고, 기존 canonical GPU 큐에서만 실행한다. 새 모델·파인튜닝·전체 영상 재검출·해상도/임계값 sweep은 하지 않는다.

기존 `video_cards`나 캐시 파일의 메타를 조작해 ROI 결과를 전체 화면 결과로 위장하지 않는다. 별도 캐시와 비교에 crop/scale 정보를 명시한다. 이 구간 비교로 기존 전체 구간의 추적/카드를 자동 덮어쓰지 않는다. 새 관측이 실제 누락 대상을 포함하는지 원본을 보고 확인해야 하며 출력 박스 수 증가만을 성공으로 세지 않는다.

## 완료 기준

1. 007·030 실제 입력에 CPU 진단과 원본 특징 추적을 적용한다. 실패 사례도 남긴다.
2. 알림이 사라지는 **원인 단계**, 새로 얻은 영상 근거, 정상 오탐과 필요한 의심의 변화 또는 변화 없음이 한 표에 보여야 한다.
3. 확대 검출을 수행했다면 실행한 구간·선정 이유·새 관측 품질·비용을 따로 보고한다. 미실행도 명확히 기록한다.
4. 기존 담당3에 원본/기존 관측/새 보조 관측 비교 자료와 `EXP-0039-results.md`, 독립 검토·전달 기록을 등록한다. 실제 재생/이미지 표시 확인을 HTTP 성공으로 대신하지 않는다.
5. 코드·비식별 집계·보고서만 GitHub에 게시한다. 원본 영상·크롭·좌표·raw 결과·DB는 로컬에 둔다.

VLM·SAM·학습을 새로 추가하지 않는다. 이번에는 영상 근거의 질을 검증한다. 효과가 없으면 구체적으로 어떤 정보가 부족했는지 남기며, 성공/불가능을 과장하지 않는다.
