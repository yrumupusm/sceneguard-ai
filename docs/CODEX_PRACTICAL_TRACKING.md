# 현재 작업 — 파인튜닝 제외, 누락 허용 추적으로 MVP 완성

사용자의 최신 결정: 자체 파인튜닝 모델을 사용하지 않고, 한 프레임 검출 누락으로 실패시키지 않으며, 넘기 전후의 사람을 어느 정도 연결하는 실용적인 미니 프로젝트를 만든다. 이전 `CODEX_NEXT_TASK.md`/`AGENTS.md`에 있는 EXP-0027 종료·Roboflow 라벨 검수 대기는 과거 배치 상태다. 이번 작업은 [EXP-0028 구현·실행 문서](experiments/EXP-0028-practical-tracking.md)를 우선한다.

먼저 최신 코드를 정상 동기화하고 로컬 미커밋 변경·기존 결과를 보존한다. 새 `sceneguard.gap_boundary`와 `sceneguard.replay_gap_tracking`의 CPU 테스트를 실행한 다음, 기존 사전학습 FCOS의 030/007 연속 캐시로 strict/gap 비교를 실제 실행하라. 이미 만들어진 코드를 활용하고 실험 계획 문서만 더 만드는 것으로 끝내지 말 것.

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*gap*.py' -v
.venv/bin/python -m sceneguard.replay_gap_tracking 030 007 --retain-seconds 3 \
  --output-root outputs/exp0028/practical-v1
```

위 환경은 기존 EXP-0005 추적 의존성이 있는 환경이어야 한다. 다음으로 실제 영상에 두 구성의 ID/관측·예측/후보 알림을 나란히 표시하는 로컬 비교 영상을 만들어 기존 결과 화면에 등록한다. 새 렌더러 연결과 실제 캐시 실행은 원격 코드 작성 단계에서 아직 완료되지 않았다.

결론은 같은 사람 연결, ID 오연결, 통과 누락, 접근 중 오탐을 영상 단위로 간단히 보고한다. 모든 프레임 정밀 주석이나 Roboflow 113장 검수 완료를 진행 조건으로 걸지 않는다. 다만 박스 개수 증가를 실제 개선이라고 바꾸지 않는다.

3초 기억은 재식별 보장이 아니다. 실제 전후 ID가 계속 끊기면 동일 검출 입력에서 BoT-SORT+사전학습 ReID 하나를 다음 비교로 진행한다. 임베더/API/라이선스와 원본 접근을 먼저 확인하고, 직접 재학습은 하지 않는다. 고정 7장 정지 화면이 아니라 넘기 전후를 포함한 연속 영상으로 판단한다. 필요한 연속 검출 구간 확장만 기존 GPU 큐를 사용한다. 새 큐·유료 서비스·이미지 외부 업로드는 하지 않는다.

기존 보수적 구현과 실패 기록은 비교 기준으로 남긴다. 기존 best/last 가중치나 데이터를 물리적으로 삭제하지 않는다. 코드/테스트와 실제 영상 성능을 구분하여 완료 보고한다.
