# EXP-0044 — 입구 방향과 소실로 자동 판정

2026-11-01 최신 사용자 승인. 원래 목표로 돌아간다. **선 가까이에서 안쪽으로 이동하다 사라지면 자동 침입 검출, 방향이 애매하거나 반대쪽이면 침입 의심**이다. 이는 오류가 가능한 카메라 규칙의 자동 판정이며 사용자 확인 결과와 분리한다. 과거의 침입 검출 금지/실험 종료 지시는 당시 범위이고 이번 승인은 침입 검출 규칙의 별도 비교를 허용한다.

## 준비 상태

- `sceneguard/directional_loss.py`: 안쪽 법선/같은 점의 이동 방향, 소실 판정, 원본 후보에 대한 별도 자동 상태.
- `sceneguard/exp0044_application.py`: EXP35 소실 후보와 EXP42 저장 경로를 재사용하는 CPU 실행기.
- `tests/test_directional_loss.py`: 작성 환경의 CPU 시험 **43개 통과**. 핵심 기하/분류 36개와 모의 grouping을 쓰는 계약 7개다. OpenCV 재실행 시험, 실제 CCTV, 기존 grouping/UI 전체 통합 시험은 아직 아니다.
- 기본 MVP, 기존 18개 후보 payload, 모델, 사용자 영역, 수동 검토 DB/알림 영수증은 변경하지 않았다. 새 모델/학습/수동 박스/VLM/새 특징 추적은 필요 없다.

## 이번 규칙

1. 기존 EXP35 `recent_gate_presence_then_loss` 후보를 사용한다. 원래 1초 소실 대기와 실제 종료 시각을 유지한다. 특징창의 2.5초 수명 종료를 사람 소실로 세지 않는다. 영상 종료도 소실 증거가 아니다.
2. 기존 `inside`/`outside` 영역의 중심 차이로 선의 안쪽 법선 방향을 계산한다. 선의 점 순서를 뒤집어도 안쪽이 뒤집히지 않는다. 안쪽 화살표를 기존 영역 위에 표시해 의미가 맞는지 확인하되 판정 영역을 다시 튜닝하지 않는다. 방향 설정을 얻지 못하면 의심으로 남긴다.
3. 대상의 실제 관측에 시작점이 연결된 경로만 사용한다. 동일 cache index를 우선하고 겹치는 실제 seed도 허용한다. 대상의 마지막 관측 범위에 있던 **동일 point ID의 전후 이동**을 사용하며 전체 화면 점을 한 번에 평균내지 않는다. 짧은 이력 1초, 약0.5초 전 대비, 저장 카메라 이동을 제외한 좌표를 쓴다.
4. 거의 정지한 점은 이동 평균에서 빼고 이동량을 절사 평균한다. 초기 잡음 기준은 이동1px, 안쪽/바깥쪽 성분2px와 전체 이동 대비0.35, 최소3점이다. 이것은 침입 행동 점수가 아니다. 방향을 못 정해도 소실 의심을 막지 않는다. 전신·정확한 신원·VLM 동의·반대편 재등장을 요구하지 않는다.
5. 마지막 실제 박스가 유한 선 근처이고 방향이 안쪽이며, 짧은 대기 뒤 연속 관측이 확인되지 않으면 **침입 검출**. 가까움은 기존 방식과 같은 최근 높이의0.8/최소12px를 초기값으로 쓴다. 바로 앞 관측의 높이만 사용한다. 이전 3초의 근접 근거만 있고 마지막은 멀면 기존 의심은 보존하되 침입 검출으로 올리지 않는다.
6. 문 근처 소실에서 방향 불명/정지/평행/바깥쪽은 **침입 의심**. 바깥 방향 하나만으로 정상 이탈로 처리하지 않는다. 실제 보행로 이탈이 관측된 경우의 기존 EXP35 제외 처리는 유지한다.
7. 기존 대상에 붙어 있던 같은 점이 새 실제 박스의 같은 쪽에서 이어질 때만 ID 단절 가능성으로 소실 통지를 보류한다. 근처에 다른 사람이 남았다는 사실만으로 취소하지 않는다. 원래 마지막 대상 점 대비 대응 비율을 사용해 일부 점이 사라진 것을 남은 점만의 분모로 숨기지 않는다. 선을 건너 관측이 이어지면 의심을 남기며, 독립 경계 근거도 보존한다. 이것은 `계속 보이면 침입 아님` 규칙이 아니다.
8. 판정은 원래 알림 시점까지의 근거만 사용한다. 이미 대기하던 대상도 뒤의 소실 후보에서 새로 평가한다. 미래 재등장이나 사용자 정답 시각은 입력하지 않는다. 침입 검출은 정확한 경계 통과의 직접 관측이 아니라 사용자가 승인한 방향+소실 가정이다.

위쪽 움직임, 형태 변화, 가속도, EXP40/41의0.55 연속성 경보 제외, EXP42/43의 변화 점수는 **이번 판정에 쓰지 않는다**. 저장 경로만 가져온다. 기존 경보의 시각을 앞당기는 실험이 아니며 침입 검출 수 증가를 정확도 향상으로 세지 않는다.

## 로컬 실행

기존 로컬 변경을 보존해 최신 main을 반영하고 기존 환경을 사용한다. 관련 파일만 검증하며 수만 파일 전체 재감사나 새 서버/큐로 확대하지 않는다.

```bash
.venv-cv-batch02/bin/python -m unittest discover -s tests -p test_directional_loss.py -v
.venv-cv-batch02/bin/python -m sceneguard.exp0044_application \
  --baseline outputs/exp0035/007-v1.json --paths outputs/exp0042/007-v1 \
  --output outputs/exp0044/007-v1
.venv-cv-batch02/bin/python -m sceneguard.exp0044_application \
  --baseline outputs/exp0035/030-v1.json --paths outputs/exp0042/030-v1 \
  --output outputs/exp0044/030-v1
```

실행 전에 기존 `validated_inputs`, `catalog_frame`, `group_notifications`와 실제 통합을 확인한다. 이 실행기는 새 검출/flow를 만들지 않는다. 구조·경로 오류는 고치되 영역/시각/ID별 예외를 넣지 않는다. 실제 상태가 전부 의심이면 그대로 보고하고 유효한 방향을 얻지 못한 이유를 제시한다.

## 실제로 마칠 것

- 원래 소실 14건 전체의 마지막 위치, 안쪽 화살표, 평균 이동 화살표, 마지막 실제 관측, 1초 대기, 판정 시각/상태를 기존 원본에 표시한다. 이전 모든 점 궤적을 길게 그리기보다 현재 방향과 소실 위치 중심으로 보여준다. 새 검출 박스나 숨은 신체를 만들지 않는다.
- 출력 `decisions.json`, `geometry.json`, `directional-cards.json`과 원래 `baseline-cards.json`을 함께 보여준다. 경보 제외/확인 승격의 이유를 개별 후보 참조로 남긴다. 자동 상태는 `automatic_status`/`automatic_confirmation`, 작성자는 `decision_source=automatic_rule`, `human_verified=false`다. 사용자 수동 검토를 덮어쓰지 않는다.
- 사건은 전체 원래 후보로 먼저 묶는다. 한 명의 연속 관측으로 다른 사람의 알림을 취소하지 않는다. 새로운 변화 후보를 섞어 필요한 원래 경보를 앞 접근 카드에 흡수시키지 않는다. 자동 상태가 의심→확인으로 바뀌면 같은 카드에서 표시하고 `first_confirmation_pts`를 따로 보여준다. 사람마다 새 카드를 만들지 않는다.
- 기존 담당3에 이 상태 필드용 최소 표시 어댑터를 붙인다. `status`의 원래 의심 payload를 침입 검출으로 덮어써 과거 자료를 바꾸지 않는다. 기본 판정 이력과 자동 정책 층을 분리하고 화면에서 **침입 검출**과 사용자 검토 결과를 구분한다. 비교 보기는 실알림 발송을 끈다.
- 007 접근/대기와 침입 소실, 030 전체 저장 구간에서 침입 검출이 장면과 맞는지 비교한다. 특히 접근만 했는데 침입 검출이 나오면 오확인으로 기록한다. 이미 받은 사용자 검수는 재사용하고 정밀 박스·모든 점의 동일인 정답을 다시 요구하지 않는다. 실제 비교에서 얻지 못한 정확도 %를 만들지 않는다.
- 실제 재생·되감기·확인 시점 전 미래 상태 미표시·폴링 유지, 기존 검토 DB 보존을 확인하고 결과/독립 검토/전달 기록을 GitHub에 게시한다. 사용자 설정에 맞춘 구현 완료와 실제 영상 성능을 구분한다. 기본 MVP 자동 교체는 아직 하지 않는다.
