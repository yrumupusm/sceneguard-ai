## 변경·검증

`MVP-1.0-rc3`: 양방향 연속 관측 통과, 안쪽 출발이 있는 바깥 방향 문 소실을 확인에 반영한다. `outward_crossing_loss`는 기존 단순 `outward_loss` 해제와 구분한다. 원래 후보·시각은 보존한다. 저장된 검출·추적·특징점 자료로만 새 규칙을 재생하며 새 GPU/검출/추적/flow 실행은 없다.

현재 동작 회귀311개 통과. 독립 검토의 별도 관련180개 시험과 diff 검사 통과, 추가 지적 없음. 과거EXP0048 소스 바이트 동일성을 요구하는1개 시험은 이전 변경과 마찬가지로 현재 동작 시험에서 분리했다. 과거 receipt/소스 해시를 갱신해 통과시키지 않았다. 검증 기록: `outputs/validation/bidirectional-crossing-v1/tests.json`, `independent-review.json`.

## 전체 저장 관측값 재평가 완료

45개 전부 성공, 실패0. 최종 `run-002`는 소스 커밋 `33d0ce9976517910179baf4ba470fab0b49ce812`의 Python 바이트와 모두 일치하며 실행 중 코드 변경이 없다. 기존 원본·측정값·과거 보고서·정답 manifest의 보호 해시를 전후 확인했다. CPU 규칙 재생의 전체 경과시간은408.2초(동시 작업2개)이며 영상 추론 FPS가 아니다. 메타데이터 수정 전run-001은21개 완료된 부분 실행으로 보존했다.

014·016·018·020·021·038은 승인된 최신C5 영역의 기존 관측 자료를 사용했다. 따라서 이번 비교의 수정 전 침입 확인은 최초 테스트24건이 아니라 영역 수정 후30건이다. 같은 입력의 기존 결과와 rc3를 공식0-based 정답 구간으로 비교했다.006의 정답 프레임 불일치는 미해결로 유지하고,008은 의미 검수 보류 메모를 남기되 공식 분모에서 제외하지 않았다.

추가 확인은004의61.600초(연속 관측 진입)와012의75.766667초(연속 관측 안→밖) 두 사건뿐이다. 앞서004를 고친 효과까지 포함한 비교이며, 양방향 허용만의 추가 회복은012다. 다른 영상의 기존 확인 시각과 성공한 정답 매칭은 유지됐다. 새 바깥 방향 소실 규칙이 실제 영상에서 추가 확인을 만들지는 않았다. 해당 경로의 기능 검증은 합성 회귀 시험이며 실영상 회복 성과로 주장하지 않는다.

전체 precision/F1은 미확정이다. 개발 과정에서 반복 검수한 영상과 공유 카메라를 사용했으므로 독립 일반화 성능이 아니다. 사건 구간 안의 확인 근거를 세는 평가이며 최초 알림 정확도나 사람별 재현율과 다르다.

로컬 최종 자료는 `outputs/validation/bidirectional-crossing-v1/run-002/`의 `summary.json`, `before-report.json`, `after-report.json`, `per-video-comparison.json`, `confirmation-changes.json`, `provenance.json`이다. 상위 폴더 `replay.py`와 `finalize.py`로 재현할 수 있다. 사용자 전달용 CSV는 `SceneGuard_양방향수정후_침입누락검수.csv`로 기존 목록과 별도로 저장했다.

기존 포트폴리오와 웹의 과거 실험 수치는 이 재생과 별도이며 자동 교체하지 않는다. 페이지5의 소실 중심 설명은 다음 편집 시 새 연속 관측 및 양방향 범위를 반영해야 한다.
