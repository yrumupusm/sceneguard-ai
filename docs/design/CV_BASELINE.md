# 가장 단순한 CV baseline 설계

- 2026-10-27 / **설계만, 구현·추론·학습 미실행**. 특정 검출기·추적 라이브러리·가중치 미선정.
- 목표: 녹화 CCTV에서 지정 경계의 **통과 후보 시각과 근거**를 반환. 물리적 울타리 넘기 완료·법적 무단침입을 자동 확정하지 않는다.
- 근거와 대안: [ADR-0005](../decisions/ADR-0005-minimal-boundary-baseline-design.md). 평가 자료: [구성안](../data/AIHUB_INTRUSION_EVALUATION_PLAN.md).

## 입력과 출력 계약

입력은 로컬 MP4, 원본 PTS, camera/boundary ID, 정규화 좌표의 경계 선분·감시 ROI·양쪽 영역·허용 관찰 방향, 실행 설정 버전이다. 향후 사전학습 사람 검출기 1개를 고정하고 학습 없이 시작하는 설계다. 모델명·라이선스·가중치 해시·입력 해상도·실행 FPS는 구현 전 결정한다. 최초 검증은 원본 프레임 순서와 PTS를 유지하며 샘플링은 별도 비교 실험으로 둔다.

공식 JSON·사용자 정답·사건 구간·정답 기반 크롭은 추론 입력에 넣지 않는다. 전체 영상으로 상태를 이어가고 평가 단계에서만 검수 시간 마스크를 적용한다. 시간 간격·검출 누락은 원본 PTS로 처리한다.

출력 제안:

- 실행 메타데이터: source/config/model hash, 유효 처리 시간, 실패·누락 구간.
- 프레임 기록(로컬): PTS, 사람 bbox, confidence, 임시 track ID, 관측/예측 여부.
- 사건 후보: video/camera/boundary ID, local track ID, 양측 관측 PTS, `candidate_pts`, 실제 출력 시점 `emitted_at_pts`, 방향, 근거 프레임 참조, quality flags.
- `physical_climb_completion=unknown` 기본값. 영상 끝까지 확정할 수 없는 상태는 unknown/truncated로 남기며 자동 완료시키지 않는다.

## 최소 처리 규칙 제안

사람 검출 → 인접 프레임 bbox의 IoU 기반 일대일 연결(가장 단순한 임시 ID) → bbox 하단 중심의 ROI/경계 양측 변화 → 후보 출력. 정밀 tracker를 필수 구성으로 선결정하지 않는다.

1. 동일 ID의 **실제 검출**이 유한 경계 선분 양측에 있어야 후보를 만든다. 한쪽 최초 등장·ROI 입장·경계 근접·접촉만으로 출력하지 않는다.
2. 경계 주변 여유 폭(hysteresis band)과 양측 최소 지속 시간으로 흔들림을 억제한다. 값은 개발 표본에서 고정하고 테스트에서 조정하지 않는다.
3. 연결이 모호하거나 검출 간격이 허용 범위를 넘으면 unknown으로 끊는다. 사라졌다 나타난 두 점을 무조건 직선으로 이어 통과시키지 않는다. 가림 복구·다중 사람 ID 전환은 명시적 실패 후보다.
4. 후보 시각은 양측 실제 관측 사이의 범위로 저장하고 필요 시 중간값을 추정치로 병기한다. 출력 지연과 추정 사건 시각을 분리한다. 동일 track/boundary 반복 경보는 개발에서 정한 중복 억제 시간으로 합치되 실제 왕복은 별도 방향 사건으로 유지한다.

bbox 하단 중심은 실제 발 좌표가 아니며 울타리 위 신체 자세·가림에 취약하다. 특히 031의 접촉·미완료와 006의 평행 보행을 실패 검증 사례로 사용한다. 사람/ROI 존재만 보는 규칙은 더 단순하지만 이 둘을 분리하지 못하므로 진단용 비교에 한정한다. 최소 연결이 실제로 부족할 때만 SORT 등 추적 보강을 검토한다.

## 평가 계약과 지표 (실측 없음)

**주 평가 단위:** 검수된 경계별 통과 사건. 사람별 구분이 확인되면 각 사람/방향별 사건, 불가능한 군중 구간은 별도 episode 평가로 분리하고 두 결과를 섞지 않는다. 공식 다중 사람 구간 하나를 사람 수만큼 임의 복제하지 않는다.

- 매칭: 같은 video/boundary/방향의 예측과 사용자 확정 사건에 대해 통과 허용 시각 범위(불확실 경계 포함)를 사용한다. 허용 오차 δ는 개발에서 사전 고정한다. 범위 내 예측-정답 쌍을 최대 일대일 매칭하고 동률은 시각 거리로 결정. 동일 사건의 나머지 경보는 중복 FP로 집계한다. 모호한 주체는 별도 episode 규칙으로만 평가한다.
- `Precision=TP/(TP+FP)`, `Recall=TP/(TP+FN)`, F1 및 원시 TP/FP/FN·사건 수. 사건/비이벤트가 모두 검수된 **평가 시간 마스크 내부**만 집계. 미검수 구간의 경보는 unscored로 별도 계수한다. 분모 0이면 N/A.
- 음성 구간 FP와 FP/hour = FP / (검수된 음성 초/3600). 실제 음성 초·구간 수·카메라 수를 함께 표기. 006의 약 13초는 현재 후보라 분모에 포함하지 않음.
- 감지 지연은 `emitted_at_pts − user_climb_start`, 사건 시각 오차는 추정 통과 시각과 사용자 통과 시각의 차이로 **별도** 보고한다. 첫 사람 등장이나 경계 접촉을 넘기 시작 대용으로 쓰지 않는다. 이 baseline은 통과 후 확인 방식이므로 시작 감지를 보장하지 않는다. 미탐은 지연 계산에서 조용히 제거하지 말고 미탐 수를 함께 보고한다.
- 031 미완료 주체는 완료 사건 recall·종료 오차 분모에서 제외하고 시도/관측 중단 사례로 별도 보고. 이미 완료한 주체가 검수되면 그 사건만 포함. 끝이 불명확한 공식 구간을 이용한 종료 IoU 점수는 보류한다.
- 공식 라벨 대비 구간 평가는 사용자 검수 평가와 분리한 보조 결과만 허용. 006의 프레임 수 불일치와 0/1-based 미확정으로 정밀 시각 점수는 해당 문제 해결 후 산출한다.
- 효율: 전체 디코딩+전처리+검출+연결+규칙+출력의 처리 FPS, 단계별 및 전체 p50/p95 시간, peak VRAM, 유효 처리/실패 프레임 수. 워밍업·GPU 동기화·해상도·장비·패키지 버전 조건을 명시한다. 영상 FPS와 처리 FPS, 영상 시각 지연과 벽시계 처리 시간을 구분한다.
- camera/site 그룹별 결과와 전체 값을 함께 보고, 같은 카메라 진단과 독립 카메라 평가를 분리한다. track 정답이 없으므로 IDF1/HOTA를 측정했다고 주장하지 않는다.

## 구현 전 다음 작업

정밀 사용자 라벨·검수 범위·분할 동결 → 경계 설정 절차/좌표 및 매칭 δ 결정 → 검출기 1개 후보의 권리·환경·작은 사람 해상도 적합성 확인 → 사용자 구현 승인. 추가 학습·ReID·행동 모델·VLM·대시보드는 현재 설계의 필수 요소가 아니다.
