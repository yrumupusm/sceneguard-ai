# MVP 실제 검증

실제 분석·기본 보기 검증 결과다. 합성 시험, 실제 원본 분석, 웹 재생, 사람 의미 검수 및 일반화 성능을 별도로 기록한다.

007 48–105초와 030 84–100초는 기존 개발 회귀 자료다. 새로운 session ID는 과거 실험 ID와 다를 수 있으므로 원본 시각·상태·근거·알림 횟수를 비교한다. 알려진 007 후반 일반 통행은 기존 사용자 검수를 재사용한다. 실제 해제 사례가 없으면 미검증이며 무경보나 관찰 종료를 해제 성공으로 세지 않는다.

독립 검토의 실제 RuleBackend 합성 시험은 후보0건과 기본후보0건+문후보있음, 시간 prefix를 확인했다. 이는 실제 CCTV 정확도가 아니다. 실제 실행 결과는 아래와 같다.

## 실제 입력 분석 결과

네 구간 모두 기존 검출만 재사용하고, 원본에서 현재 추적·CPU 특징 경로·최신 판정·근거 영상을 새로 생성했다. 과거 EXP49 파일은 완료 결과의 회귀 비교용으로만 읽었다. 새 GPU 추론·모델·학습은 없었다.

| 입력 | 프레임 | 후보 / 사건 | 첫 의심 / 확인 | 문 주변 관찰 종료 |
|---|---:|---:|---|---|
|007 48–105초|1,710|18 / 1|55.633 / 72.133초|74.567초, 확인 이력 보존|
|030 84–100초|480|20 / 1|86.033 / 92.733초|구간 끝에서 유예 미충족, 진행 중|
|007 84–104초 정상 통행|600|0 / 0|없음|사건 없음|
|007 45–48초 추가 기술 검증|90|0 / 0|없음|사건 없음|

007/030은 각각 의심·확인 알림 의도 1개씩이며 030 후속 후보는 같은 사건의 추가 근거다. 후보/근거 수는 사람 수가 아니다. 개발 회귀 두 구간의 원래 후보 payload, 근거 상태·확인/해제 시각과 카드 시각은 새 실행 ID를 구분한 비교에서 일치했다.

정상 84–104초는 기존 사용자 관찰을 재사용했다. 45–48초는 앞선 EXP37에 사용한 짧은 구간이므로 독립 평가 자료가 아니다. 적합한 미사용 캐시를 확인하지 못했다. 전체007의 다른 캐시는 모델이 다르고006은 현재 native30fps 지원과 맞지 않아 다른 캐시/카메라로 우회하지 않았다. 다른 카메라 일반화나 독립 정확도/F1은 미검증이다.

실제 의심 해제는 네 입력에서 0건이다. 정상 통행 무경보와 관찰 종료를 해제 성공으로 계산하지 않는다. 합성 해제 규칙 시험과 실제 해제 성능은 구분한다.

## 입력 보존과 재실행

원본의 바이트 동일 복사본으로 입력 변경 검사를 수행했다. 변경된 복사본은 실행 단계 전에 거부됐으며 모델/CPU 특징 계산을 시작하지 않았다. 원본은 수정하지 않았고 복사본은 복구했다. 동일 요청 재실행은 완료 단계 해시를 대조해 재사용한다. 등록·기본 화면의 실제 검증은 별도 전달 절에 기록한다.

## 처리 비용

첫 실행 실측이며 검출 캐시 검증·추적·CPU 영상 특징·판정·두 단계 근거 렌더를 포함한다. 병렬 CPU 작업과 디스크 부하의 영향을 받으므로 독립 벤치마크가 아니다. 새 GPU 검출은 이번 네 실행에 없었다.

| 구간 길이 | 입력 | 전체 경과 | CPU 특징 경과 | 최신 판정 경과 | 최종 근거 렌더 |
|---:|---|---:|---:|---:|---:|
|57초|007 회귀|222.77초|118.81초|6.68초|44.65초|
|16초|030 회귀|110.60초|50.10초|4.35초|33.08초|
|20초|007 정상|103.56초|48.88초|1.29초|18.60초|
|3초|007 추가|20.86초|9.88초|0.05초|5.19초|

표의 세부 단계 합계는 전체가 아니다. 기존 frontend 근거 렌더·검증도 전체 비용에 포함된다. 재실행은 경로/판정/영상 stage를 재사용하며 추가 검출·추적·CPU 특징 프레임은 0이다. 캐시 재사용 속도나 사건의 원본 시각을 실시간 추론 FPS/경보 지연으로 보고하지 않는다.

## 실제 기본 화면과 보존

기존 8765 서비스의 새 기본 영상 분석에서 신규 사용자 선택 상태의007 기본 열림, 실제 짧은 재생·seek·되감기·의심/확인/관찰 종료를 확인했다.030의93.2초와97.5초는 같은 확인 카드다. 정상007의 빈 결과는 오류 없이 열리고 재생됐다. 새로고침 뒤 선택·재생 시각, 명시적인 화면 갱신 뒤 video 노드·시각·카드가 유지됐다.

**정기 폴링을 통과하는 연속 재생은 미검증이다.** 마지막 독립된18초 관측 시도는 시작 `play()`에서 Chromium `AbortError`(video-only background media paused to save power)를 반환했다.18초 관측이 수행된 것처럼 쓰지 않는다. 앞선 짧은 재생·수동 갱신·API 성공으로 이 항목을 대체하지 않는다. 브라우저 절전 오류의 관측이며 앱의 무중단 재생을 보장하지 않는다.

서비스 재시작 뒤 기존63개 등록과 artifact 항목을 보존했고 새4개를 추가했다. 검토 현재2건/이력5건·알림claim10건의 DB와 기존 수동 검토 API 읽기가 유지됐다. 새 검토 메모를 작성하거나 영수증을 초기화하지 않았다. 독립 검토에서 SQLite 전체 논리 dump가 일치함을 확인했으며 DB 파일 바이트 해시는 달라 바이트 동일 보존으로 주장하지 않는다. UI의 검토 입력 컨트롤은 확인했지만 이번 검증에서 새 메모 쓰기를 반복하지 않았다.

새 등록의 미디어 허용 목록 누락으로 첫404를 확인하고 검증된MVP bundle만 허용하도록 수정했다. 기존 동일서비스 listener의 PID·명령·환경을 확인해 정상 종료한 뒤 기존 lab 관리 경로로 재시작했다. API206과 실제영상재생을 따로 확인했다. 기본 선택 API/JS 연결을 대조했고 MVP 저장키를 이전 실험과 분리했다. 원래 EXP 표시와 결과는 보존했다.

실제 브라우저·DB 영수증은 로컬 서비스 runtime의 `mvp0002-web-receipt.json`과 `mvp0002-snapshot-20261101-212640`에 있다. [독립 검토](reviews/MVP-V1-independent-review.md)는 코드/전체출력/75지표 검증과 웹담당 실제 영수증 검토를 구분한다.
