# SceneGuard — 가정한 사용자 업무 흐름과 제품 검증

- 상태: **제품 가설**, 사용자인터뷰/실효성 검증 **미수행**
- 근거: [ADR-0003](decisions/ADR-0003-incident-review-product-direction.md)
- 가정 사용자: 산업현장 안전 담당자 / 사고·이상상황 영상 검토 담당자

## 사용 시나리오
담당자가 사고나 이상상황이 의심되는 짧은 영상을 전달받고, 영상을 반복 재생하면서 어떤 객체/행동이 등장하는지 확인한 후 사건 기록을 작성한다고 가정한다.

### 최소 업무 흐름
1. 담당자가 **선택한** 짧은 영상 클립을 등록한다.
2. 시스템이 시각적으로 확인 가능한 복수 행동·사건 후보를 구조화해 제시한다 (모델 아직 미선정).
3. 근거 프레임/구간을 보여줄 수 있는 경우 함께 제시한다. 원본 정답에 사건 시각 라벨이 없으면 모델 예측 근거를 사람 검수 대상으로 표시한다.
4. 담당자가 행동, 설명, 근거, 판단 보류 여부를 검토·수정·확정한다.
5. 확정된 정보를 저장하고, 이후 사건·행동·날짜(있는 경우) 조건으로 찾아볼 수 있게 한다 (추후 확장).

### 출력 레코드 제안 (최종 스키마 미정)
- video_id / source_uri (저작권/개인정보에 안전한 로컬 참조)
- predicted_actions[]: 모델이 제안한 행동 및 분류체계 ID
- visible_evidence[]: 검수할 프레임/구간 후보, 프레임 시각, 근거 수준
- narrative: 관찰 사실에 한정한 사건 설명
- uncertainty / unknowns: 원인·권한 등 영상만으로 확인 불가한 부분
- review_status: 미검토 / 수정 요청 / 검토 완료
- corrections[]: 사람 수정 이력
- inference_metadata: 모델/설정 버전, 데이터 접근 조건, 처리 지연 (실측 시)
- 검색 가능한 확정 태그는 **사람이 검수한 결과**와 모델 미검수 결과를 분리

## 문제 해결/기술 선택에 대한 질문
- 기초 라벨이 multi-label이라면 어떤 행동 목록으로 결과를 구조화할 것인가?
- 샘플링으로 시간적 사건을 놓칠 위험과 처리 비용 간 균형은?
- CV 검출·추적이 필요한가? 실제로 필요하지 않으면 도입하지 않는다.
- VLM이 허구의 안전원인/책임을 생성할 경우 어떻게 차단·표시·검수할 것인가?
- 근거 장면 추출과 사건 시작/종료 정답을 혼동하지 않을 수 있는가?
- 데이터셋이 벤치마크 평가에는 충분해도 사용자 경험 개선 증거에는 부족하지 않은가?

## 데이터와 기능의 경계
iSafetyBench의 정답 태그/설명은 **평가·참조용**이지 추론 입력용이 아니다. 실시간 원본 CCTV 이벤트 발견과 즉각 위험 예방은 별도의 데이터/평가가 필요한 후속 연구다.

## 성능·효용 평가 가설
- 영상 분류 품질: class별 Precision/Recall/F1, 다중 행동 누락/오탐
- 사건 설명 품질: 사실 일치, 부정확한 원인 추론, 근거 구간의 적절성
- 제품 효용: 실제 동일 유형 클립에서 AI 미사용 vs AI 보조 기록 작성 시간, 수정 필요 비율, 검색 시간
- 처리 성능: 입력 길이·해상도·모델·VRAM·전체 지연
- 측정 전/사용자 인터뷰 전에는 어떤 개선 효과도 확정적으로 주장하지 않는다.

## 현재 범위(우선순위)
**먼저 데이터 감사만 수행**한다. 모델 성능 테스트, API, UI, 검색 저장소는 데이터 적합성이 확인된 후 별도 ADR과 계획으로 결정한다.
