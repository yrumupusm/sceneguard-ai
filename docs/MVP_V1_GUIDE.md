# SceneGuard MVP 1.0 사용 안내 — 통합 후보

> 현재 단계: 통합 실행기 RC와 연결 시험 준비. 실제 로컬 전체 분석·기본 화면 등록은 최종 검증 대상이다. 실행 성공 뒤 확정 명령/화면/환경을 이 문서에 보완한다.

## 무엇을 하는가

고정 CCTV 영상에서 문 주변 사람 관측을 바탕으로 침입 의심을 생성하고, 문 근처 이력과 안쪽 이동·소실이 있으면 자동 침입 확인을 표시한다. 같은 문 주변 상황은 사건 하나로 유지하고, 관측이 끊긴 뒤에는 관찰을 종료하되 판정 이력을 보존한다. 원본 근거 영상과 수동 검토는 자동 판정과 별개다.

```text
로컬 영상 + 명시적 카메라/scene/문 구역
 → 검증된 검출 캐시 또는 기존 큐의 FCOS 검출
 → ByteTrack 관측과 초기 의심
 → 현재 영상의 CPU 특징점 경로
 → 문 주변 의심·방향/소실·후속 상태
 → 실제 문 관측으로 사건 유지/종료
 → 원본 근거 영상 + 시간순 사건 상태 + 별도 수동 검토
```

새 실행은 과거 실험 결과 디렉터리 연쇄 재생을 요구하지 않는다. 기존 알고리즘 함수는 재사용한다. 거절한 위쪽 움직임·형태 변화 action 점수, 자체 파인튜닝, VLM의 필수 승인은 이 경로에 없다.

## 필요한 로컬 자원

기존 C3/C6 카메라 설정, 원본 30fps 영상, 검증된 FCOS 검출 캐시 또는 기존 canonical GPU 큐 접근, 기존 CV 환경(PyAV/OpenCV 등), 현재 scene과 문 다각형 JSON이 필요하다. 공개 저장소만 내려받으면 비공개 원본과 설정이 자동으로 생기는 구성은 아니다. 사용자 CCTV/모델/실제 좌표/검토 DB/인증정보는 저장소에 넣지 않는다.

007은 기존 승인된 inside 수정 scene을 쓰고 030은 현행 scene을 쓴다. 문 구역 파일은 카메라·원본 크기·선택 scene에 결속된다. 다른 카메라의 구역을 자동 추정하지 않는다. 최초 검증 단계에서 기존 실험 request로 위치를 찾은 뒤 로컬 카메라 프로필로 선택 경로를 정리한다.

## 실행

```bash
python -m sceneguard.mvp_pipeline --help

# 기존 로컬 CV 환경에서 실행. 실제 파일 경로는 카메라별 로컬 프로필로 지정한다.
python -m sceneguard.mvp_pipeline \
  --video "$VIDEO" --camera C3 --scene "$SCENE" --portal "$PORTAL" \
  --cache "$DETECTOR_CACHE" --start 48 --end 105 \
  --output outputs/mvp-v1/my-recording
```

`--whole`은 `--start/--end` 대신 사용한다. 현재 구현은 명시적으로 C3/C6와 native 30fps 입력을 지원한다. 캐시가 없으면 기존 큐의 네 실행 식별자 `--run-id --task-id --dispatch-id --owner`를 함께 넘겨야 하며, 없으면 차단 결과를 반환한다. 새 큐·새 모델을 만들지 않는다.

같은 입력·설정·코드·출력 경로로 재실행하면 완료 stage를 검증 후 재사용한다. 변경된 입력으로 기존 출력을 덮어쓰지 말고 새 출력 경로를 쓴다. 전체 분석은 비실시간이며 모든 원본 PTS를 보존한다. 저장 자료 처리 시간을 실시간 모델 FPS로 부르지 않는다.

출력:

- `status.json`: analyzing / blocked / failed / analysis_complete. `analysis_complete`는 화면 등록 완료와 다르다.
- `decision/cards.json`: 시간순 사건/근거/자동 상태와 알림 의도.
- `image-paths/frame-evidence.jsonl`: 현재 원본에서 계산한 특징 경로. 저장된 같은 요청 재사용과 신규 계산을 구분한다.
- `evidence/`: 원본 전체/사건별 근거 클립과 원본-재생 시계.
- `viewer-manifest.json`: 기존 화면 어댑터 연결용 로컬 파일·해시. RC에서 `adapter_required`이며 최종 통합 때 실제 등록 경로를 연결한다.

## 상태의 의미

|표시|의미|
|---|---|
|침입 의심|문 주변의 확인할 만한 관측. 출입 권한이나 위법 여부 판단 아님|
|침입 확인 · 자동|정한 카메라 규칙에 따른 사건 판정. 사람의 수동 확인/오류 없는 사실 인증과 다름|
|의심 해제|연결된 바깥 이탈 근거에 따른 잠정 해제. 실제 영상 검증 범위는 별도 표기|
|문 주변 관찰 종료|현재 문 구역 관찰을 닫음. 의심 해제·현장 안전·사람 모두 퇴장과 다름|

첫 의심/첫 확인은 사건별로 구분한다. 확인 사건의 후속 관측은 별도 새 경보를 반복하지 않는다. 개별 박스가 미결이어도 사건에 유효한 확인 근거가 있으면 사건은 확인일 수 있다. `pending`이나 관측열 수를 사람 수로 표시하지 않는다.

## 확인된 범위와 남은 제한

개발 비교에서 007/030의 사건 단위 의심→확인, 후속 관측 유지가 확인됐다. 007은 문 주변 관찰 종료 후 일반 보행에 새 의심이 없는 흐름을 장면으로 확인했다. 이 기록은 새 통합 실행기의 실제 검증을 대신하지 않는다.

정상 접근 오경보, 부분 신체·가림·ID/박스 혼합, 관측 공백, 다른 영상/카메라의 일반화는 남은 제한이다. 실제 바깥 이탈의 의심 해제는 아직 입증하지 못했다. 정확도/F1/시간당 오탐률, 운영 실시간 성능은 검증된 수치가 없다. 새 평가 구간이 없으면 없는 것으로 기록하며, 일반 통행의 무경보나 관찰 종료를 해제 성공으로 계산하지 않는다.

최종 실행·UI·재실행 검증 결과 및 제한은 `MVP_V1_RELEASE.md`에 실제 완료 후 기록한다. 이전 실험을 삭제하거나 검토 이력·알림 영수증을 초기화하지 않는다.
