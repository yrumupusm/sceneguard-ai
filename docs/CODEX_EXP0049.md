# EXP-0049 — 문 주변 실제 관측으로 사건 유지·종료

2026-11-01 최신 사용자 승인. 같은 입구의 이어지는 침입 상황을 10초 제한 때문에 새 의심 카드로 나누지 않는다. **검출/침입/해제 조건을 더 붙이는 작업이 아니라 사건 묶음만 바꾸는 비교**다. 기존 종료 문구는 이전 범위다. 기본 MVP와 이전 결과·수동 검토·알림 영수증은 보존한다.

## 배경과 범위

제공된 030 영상의 대화상 검토에서는 92~94초 및 96.6~98.5초가 같은 입구에서 이어지는 안쪽 이동·가림 문맥으로 보였다. 97.433초 별도 미결 카드를 새로운 정상 접근으로 자동 해석하지 않는다. 이 관찰은 정확한 사람 ID나 물리적 경계 통과 시각의 정답이 아니다. 바깥 raw 방향 진단 세 건을 억지로 해제에 연결하지 않는다. 007 후반 일반 통행은 기존 사용자 검수와 의심 없음 결과를 재사용한다.

새 `gate_activity_episodes.py`와 `exp0049_application.py`는 **성공한 EXP48 v2의 후보 및 시각별 개별 근거 상태를 동결 재생**한다. 이미 선택한 확인/해제/관측 연결은 새로 계산하거나 전파하지 않는다. 원래 사건 ID는 출처로 보존하고 새 사건 소속만 별도로 부여한다. 모든 프레임에서 개별 근거의 전체 필드/원래 판단 시각이 EXP48의 당시 상태와 같은지 검사한다. 현재 상황 묶음과 개별 관측 판정을 분리하기 위한 의도적인 범위다.

## 이번 단일 비교 규칙

1. **현재 실제 박스**가 기존 EXP46 문 다각형에 해당하면 문 주변 관측으로 센다. 기존 `PortalGate.locate`의 중심 또는 면적 절반 겹침과 실제 검출 점수 0.25를 그대로 사용한다. 원본 실제 박스만 사용하며 LAST·예측·과거 박스는 유지 근거가 아니다. 안쪽 영역 전체나 무관한 통로까지 관측 범위를 넓히지 않는다.
2. 관측이 이어지는 동안 기존 사건을 유지한다. 후보 간 3초/첫 후보 이후 10초는 새 분할 기준이 아니다. **문 주변 실제 관측이 3초간 없을 때 관찰을 종료**한다. 유예는 확인을 3초 늦추는 대기가 아니다. 단순 존재만으로 의심 카드/경보를 생성하지 않는다.
3. 문 주변 관측 없이 후보만 반복돼도 유예를 무한 연장하지 않는다. 최초 후보 시점 외에는 실제 관측만 유지 시계를 갱신한다. 관측이 없는 기존 후보도 버리지 않고 별도 사건에 기록한다.
4. **관찰 종료와 의심 해제는 다르다.** 닫힌 사건은 확인/의심/해제의 원래 자동 상태를 유지한다. `observation_status`와 `automatic_status`를 따로 표시한다. 방향 불명 의심은 닫힌 검토 이력으로 남고 정상 판정으로 바뀌지 않는다. 실제 소스 공백은 `source_gap_not_verified_empty`로 중단하며 빈 문을 관측했다고 간주하지 않는다. 영상 끝에 가짜 빈 프레임을 추가하지 않는다.
5. 같은 사건의 첫 의심은 한 번, 첫 확인 전환은 한 번 알린다. 확인 뒤의 새 후보는 그 사건의 미결 추가 근거로 남아도 별도의 의심 카드/반복 알림을 만들지 않는다. 모든 개별 근거를 확인으로 바꾸지 않는다. 종료 후 새 관측 상황은 새 사건이며, 나중 근거가 닫힌 사건에 도착해도 그 사건을 재개하지 않고 원래 근거만 갱신한다.
6. 새 모델/학습/검출/ByteTrack/flow/VLM/수동 사람 박스/영역 재조정/정밀 신원 요구는 없다. 결과를 보고 빈 문 유예를 늘리거나 특정 시각/ID에 예외를 넣지 않는다. 지속적인 문 근처 보행자나 오검출은 사건을 오래 유지할 수 있고, 검출 공백은 실제 상황을 분할할 수 있다는 한계를 기록한다.

## 작성 환경에서 확인한 것

합성/순수 함수 **54시험**과 문법 검사 통과. 10초 초과 관측·후보 없는 관측 지속·부분/전체 해제·별도 대상 보호·같은 시각 확인·후속 미결 유지·관찰 종료·재접근·소스 공백·영상 끝·되감기·중복 입력·안정 알림 키·원래 시각별 근거 보존을 검사했다. 위치 판단 시험은 직사각형 fixture이며 실제 실행기는 기존 PortalGate를 가져온다. 실제 CCTV/전체 입력/기존 웹 통합은 로컬에서 확인해야 한다. 최초 시험 한 건은 fixture의 final/timeline이 같은 객체를 공유해 불일치 조작이 두 곳에 반영되는 문제였고, 시험 객체만 분리한 뒤 54개를 통과했다. 이를 CCTV 성공률이나 실제 실행 완료로 표현하지 않는다.

## 로컬 실행

로컬 변경을 먼저 보존하고 최신 main을 반영한다. 성공한 EXP48 `007-v2`/`030-v2`를 사용한다. 원래 입력의 해시를 새 설정 해시로 바꾸지 않는다. 이전 출력이 있는 경로는 덮어쓰지 않는다.

```bash
.venv-cv-batch02/bin/python -m unittest discover -s tests -p 'test_gate_activity_episodes.py' -v
.venv-cv-batch02/bin/python -m unittest discover -s tests -p 'test_exp0049_application.py' -v
.venv-cv-batch02/bin/python -m sceneguard.exp0049_application --previous outputs/exp0048/007-v2 --paths outputs/exp0042/007-v1 --portal-result outputs/exp0046/007-v1 --output outputs/exp0049/007-v1
.venv-cv-batch02/bin/python -m sceneguard.exp0049_application --previous outputs/exp0048/030-v2 --paths outputs/exp0042/030-v1 --portal-result outputs/exp0046/030-v1 --output outputs/exp0049/030-v1
```

원래 두 전체 구간에 같은 규칙을 한 번씩 비교한다. 계약/입력 오류는 기존 출력을 보존하고 원인을 고친 뒤 재시도를 기록하되, 조건 탐색으로 확대하지 않는다. EXP48 동결 산출물의 상태 snapshot을 빠짐없이 사용하며 최종 상태를 과거 초기값으로 넣지 않는다.

## 평가·화면 연결

- 030의 이어지는 문 주변 관측이 하나의 사건으로 유지되는지, 97.433초 후속 근거가 새 미결 카드가 아닌 같은 확인 사건에 붙는지 확인한다. 실제 문 구역의 관측이 끊겨 새 카드가 생기면 해당 빈 구간과 원본을 보여주고 숫자만 바꾸지 않는다.
- 007도 같은 규칙으로 확인한다. 앞선 접근과 뒤 침입을 같은 연속 상황으로 묶을 수 있지만, 과거 접근 관측 자체를 확인된 침입 근거로 승격하지 않는다. 후반 일반 보행으로 의심이 새로 만들어지거나 이미 끝난 사건이 무한 연장되지 않는지 본다.
- 원래 38개 후보 payload와 EXP48 시각별 근거 상태·선택된 A/후속 확인·해제 시각은 정확히 유지한다. 카드 수/소속/첫 의심 알림의 합쳐짐은 이번 비교의 허용된 변경이다. 과거 카드 ID/첫 알림 개수 불변을 추가 veto로 삼지 않는다. 중요한 첫 확인은 같은 근거 시각에 보여야 하며, 이를 새 조기 검출이라고 부르지 않는다.
- 기존 담당3에 **EXP48 / 문 관측 사건 보기**를 비교 등록한다. 새 계약 `gate_activity_episodes_v1`의 open/closed와 의심/확인/해제를 분리한다. active 목록은 open 사건만, 이력은 closed 사건도 보이게 한다. `source_resolution_log`의 카드 ID는 원래 EXP48 출처이지 새 카드 ID가 아니다.
- 원본/실제 문 박스/최근 문 관측 시각/관찰 종료 시각/판정 시각을 간단히 표시한다. 전체 미디어를 다시 무더기로 만들기보다 전체 2영상과 달라진 짧은 구간을 우선한다. 되감기는 `activity_cards_at`의 당시 snapshot만 사용하며 미래 확인/종료를 표시하지 않는다.
- 실제 재생/되감기/상태/폴링/재시작 후 알림 키를 확인한다. 앞선 브라우저 시간초과는 판정 재실행이 아니라 별도 UI 검증 과제다. API 확인과 실제 재생 검증을 구분하고, 시간초과면 미완료를 명시한다. 운영 외부 알림/receipt claim을 호출하거나 DB를 초기화하지 않는다.
- 결과·독립 검토·전달을 GitHub에 기록한다. 사건 정리의 개선과 검출 정확도/해제 성공률은 별개이며, 실제 해제 예가 없으면 미평가다. 이미 확인한 장면은 다시 묻지 않고 새로 애매한 구간만 원본 확인을 요청한다. 기본 MVP 자동 교체는 하지 않는다.
