# ADR-0017 — Qwen의 행동 구분에 시간적 신체 근거 요구

- 날짜: 2026-10-28
- 상태: 비교 실험 전 잠정 가설; 행동 성능 미검증
- 관련: [EXP-0015 사용자 라벨](../experiments/EXP-0015-user-label-revision.md), [EXP-0015 독립 검토](../reviews/EXP-0015-independent-review.md), [EXP-0016](../experiments/EXP-0016-prompt-evidence-rubric.md)

## 문제와 제약

사용자 검수에서 q02·q03·q05는 접근/대기 또는 넘기 시도가 없는 구간인데 B/C가 후보를 냈고, q04는 실제 시도/진행이 보이는 구간인데 B가 후보를 내지 못하고 C만 냈다. q01/q06은 사용자가 시도를 확인하지 않았다. 저장된 q02 B의 근거 문장은 보도 위 걷기와 차량을 말하면서 `stepping_over_boundary` 및 완료를 함께 기록했다. q03 C와 q05 B/C는 사용자가 확인하지 않은 stepping 동작을 서술했다. q04 C는 climbing attempt를 서술하고 완료를 확정하지 않았다.

저장 결과만으로는 잘못된 후보의 원인이 프롬프트 지시인지, 시각 표현 한계인지, 장면 가림/축척인지 확정할 수 없다. 일부 원문·입력 metadata에는 당시 확장 프롬프트 전문이 없다. 따라서 프롬프트가 원인이라는 설명은 가설이다.

한 비교에서 모델·가중치·입력 해상도/ROI·창·PTS·샘플링·생성 설정·파서 중 두 개 이상을 바꾸지 않는다. 개발 q01–q06을 정답 최적화에 반복 사용하지 않으며, 출력 후보를 모두 보류/삭제해 오탐이 줄었다고 주장하지 않는다.

## 비교할 대안

| 대안 | 근거 | 장점 | 한계/위험 |
| --- | --- | --- | --- |
| shared prompt만 수정: 프레임 순서에 따른 신체 움직임과 경계 관계를 요구 | q02/q03/q05의 출력에서 행동 분류와 서술 근거의 불일치가 관찰됨 | 모델·입력·후처리는 그대로 둔 한 축 비교 | 프롬프트 지시가 시각 모호성/가림을 해결한다고 보장할 수 없음 |
| 인접 창의 candidate 일관성 후처리 | q03 인접 창 중 일부는 candidate가 아니었음 | 이미 생성된 후보 간 시간 정보를 쓸 수 있음 | q05 인접 B/C 창에도 잘못된 후보가 이어져 이 사례의 원인을 설명/제거하기 어려움; 지연 추가 |
| 서술-라벨의 규칙 기반 후처리 | 일부 오류는 출력 action과 evidence의 모순으로 보임 | 생성 재실행 없이 저렴함 | q05처럼 모델이 잘못된 stepping을 명시하면 그대로 통과 가능; 파서 의미를 새로 바꿈 |
| 새 ROI/모델/검출기 | 작은 인물/경계 픽셀 가설 | 시각 정보 표현을 바꿀 수 있음 | 추가 축/가중치 또는 ROI 선택 근거가 필요; 이번 원인 증거에서 우선 선택할 수 없음 |

## 선택과 이유

이번 비교는 **공유 프롬프트의 관찰 기준만 수정**한다. 접근·대기·단순 접촉은 시도 근거가 아니며, 프레임 순서에 따른 발·다리·신체의 경계 상대 이동을 설명한 뒤 `stepping_over_boundary`/`climbing_attempt_or_in_progress`를 선택하게 한다. 가림이나 모호성에서는 불확실성을 기록하게 한다. 열린 문, 근접성, 횡단보도, 다른 사람의 동작에서 넘기/완료를 추론하지 않게 한다. 완료는 해당 동일 인물이 반대편으로 이동한 것이 같은 창 안에서 보일 때만 기록한다.

이 변경은 신체 부위를 검출하거나 attempt의 정답 기준을 새로 정의하지 않는다. 출력 schema, 모델, 입력 view, ROI, 샘플링, generation, parser, 후처리는 고정한다. 기존 B/C 출력은 기준값으로 보존한다. q01–q06에서는 두 view 모두 새 문구를 같은 프레임에 적용하고, 이전 B/C 결과와 비교한다. 사용자가 검수한 v01–v04 독립 개발외 창에서는 기존/새 문구를 같은 full-frame 입력에 대조한다. E01_004/E01_021에는 이 실험이 사용할 기존 교정 ROI가 없으므로 두 번째 입력 view를 만들지 않는다. 이 표본은 촬영 그룹 독립성이나 맹검 테스트를 보장하지 않는다.

## 검증 방법

q04 시도 후보가 남는지, q02/q03/q05 잘못된 후보가 감소하는지, q01/q06이 candidate로 바뀌지 않는지를 먼저 본다. 후보 상태를 전부 보류하거나 없애는 결과는 개선이 아니다. 새 설명은 사용자 관찰과 별개로 근거를 확인한다. 확정 정답은 개발 표본에만 한정하며 최종 정확도/F1/FPR을 만들지 않는다. 시간·VRAM은 생성 job에서만 측정하고 CPU 캐시 재생을 추론 FPS라고 부르지 않는다.

독립 창 라벨: v01 시도/진행(completion 미평가), v02 비사건, v03 시도/진행(문을 통과한 것이 아니라 옆 빈틈; 경계 위치 관계는 불확실; completion 미평가), v04 비사건. 모델 입력에는 익명 window ID와 원본 프레임만 넣고 라벨·공식 참조·과거 답변은 주지 않는다.

## 결과와 재검토

실행 전 사양이다. GPU 자원 gate를 통과한 실제 비교, 총괄 검토, 독립 Astra 검토 후 결과를 [EXP-0016](../experiments/EXP-0016-prompt-evidence-rubric.md)에 연결한다. 행동 성능 개선이 확인되지 않거나 q04가 사라지면 이 prompt를 채택하지 않는다.
