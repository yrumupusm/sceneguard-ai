# ADR-0026 — 데이터셋 비교에서 양방향 통과를 침입 검출로 사용

날짜: 2026-11-04. 상태: 사용자 승인, 구현·검증 결과는 [후속 기록](../BIDIRECTIONAL_CROSSING_REVIEW.md).

사용자 지시: “일단 데이터셋 정답대로 검출하는지를 테스트해야하니 안 > 밖도 침입 검출로 쓰자”. 기존 ADR-0025의 진입만 확인 범위를 이번 데이터셋 비교에 한해 양방향으로 확장한다. 데이터셋 정답이나 과거 결과를 바꾸지 않는다.

## 문제와 선택

현재 씬은 양방향 후보를 허용하지만 기존 확인은 inward 위주이며 outward 소실은 의심 해제에 쓰였다. 공식 침입 라벨에는 안쪽에서 울타리를 넘어 바깥으로 나가는 사건도 있다. 사용자 검수로005·012·013·015·021·028·043·044·045 등이 이런 상황임을 확인했다.

단순히 모든 outward를 확인으로 바꾸면 문 바깥에서 접근했다가 돌아서는 사람도 양성으로 만들 수 있다. 따라서 다음 두 경로로 확장한다.

1. 연속 관측: 기존 visible gate crossing의 안정된 출발/도착 영역, 실제 박스 연속성, 유한 문 선분 통과와 방향 일치를 양방향으로 검사한다. 소실 대기 없음.
2. 소실: 기존 실제 소실 대기 및 미해결 관측 지속 조건을 유지한다. 최근 실제 관측에 안정된 안쪽 출발 영역, 유한 문 근처 관측, 바깥 방향 특징점 이동이 함께 있어야 outward gate loss로 확인한다. 바깥으로 걷는다는 사실만으로 확인하지 않는다.

새 후속 소실은 한 관측에 연결된 최신 사건의 근거 하나만 확인한다. 다른 사람·이전 사건으로 확인이 전파되지 않게 기존 scoped lifecycle 소유권을 유지한다. 기존 바깥쪽 단순 이탈의 해제 동작과 과거 EXP 재생 기본값은 보존한다. MVP 새 실행 버전은 rc3이다.

## 검증·반증 조건

양방향 긍정 사례, 접근 후 되돌아감, 문 연장선 밖 통과, 관측 단절·크기 급변, 미래 관측, 소실 미관측, 다른 사건에 전파되는 경우를 검사한다. 저장 입력을 재사용한 CPU 규칙 재생에서 기존 입력의 해시와 공식 정답 구간을 보존한다. 기존 측정값으로 확인을 못 하는 사례를 정답에 맞추려고 임계값이나 영역을 임의로 조정하지 않는다.

영역/추적/소실 근거 부족, 초기 화면부터 문 위인 사람, 여러 인물 연결, 정답보다 이른/늦은 확인은 별도 문제다. 양방향 허용이 모든 반대 방향 누락을 해결한다는 뜻은 아니다. 실사용의 침입/이탈 표시는 후속 제품 결정이며 권한 없는 출입을 영상만으로 확인했다는 뜻도 아니다.
