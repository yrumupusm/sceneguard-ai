# ADR-0014 — 실험 완료와 게시·화면 확인을 연결

- 날짜: 2026-10-28
- 상태: 사용자 요청 범위의 완료 절차 구현. 첫 실제 모델 실험은 미실행.

현재 Orca 세팅은 기존 결과를 조회하지만 담당 카드가 항상 미배정이며, 새 결과를 catalog와 로컬 artifact allowlist에 따로 입력해야 한다. 이 상태에서는 worker_done이나 GitHub push를 사용자가 실제로 열 수 있는 결과의 완료로 오인할 수 있다.

실제 native Task/Dispatch와 experiment_id의 배정을 공개 인덱스에 연결하고, 같은 native 관측의 신선도를 확인해 카드에 작업 상태를 표시한다. 실행 결과·검토 판정·모델 채택은 별도 표시한다. 결과를 제출할 때는 공통 CLI가 보고서/측정치/검토 SHA와 로컬 artifact 목록을 검증해 등록한다. 총괄의 검토가 있어야 완료 등록하며 자동 생성한 설명을 검토나 정답으로 쓰지 않는다.

등록은 GitHub 게시나 브라우저 확인을 수행하지 않는다. 별도 검증 명령은 원격 ref/게시 파일과 실제 로컬 페이지의 선택·그래프·영상 재생을 각각 확인해 다른 receipt를 남긴다. 담당 카드에서 완료 결과를 열 수 있어야 전체 작업이 끝난다. 실패/미측정/누락 영상도 숨기지 않고 확인 실패 또는 미확인으로 남긴다.

새 scheduler, 자동 모델 실행, 공개 웹 쓰기 API는 만들지 않는다. 기존 Orca 권한과 공통 GPU 실행기, GET/HEAD 전용 viewer를 유지한다. 직접 JSON 편집만을 운영 절차로 삼는 대안보다 검증과 재실행이 가능하며, 임의 shell을 실행하는 자동 완료 hook보다 범위가 작다. CLI는 총괄이 명시적으로 호출하고 같은 내용의 재실행은 중복 등록을 만들지 않는다.

자료 변경 시 오래된 검토/게시/화면 receipt를 현재 결과에 적용할 수 없다. 첫 실제 실험에서 실행 중 상태와 완료 후 전체 흐름을 별도로 검증하며, 이번 TEST fixture 성공을 실제 모델 실험 성공으로 보고하지 않는다. 운영 계약은 [EXPERIMENT_DELIVERY](../orchestration/EXPERIMENT_DELIVERY.md)다.
