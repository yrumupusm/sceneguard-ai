# ADR-0024 — 기존 외형 비교 6쌍의 Qwen 8B NF4 대조

2026-10-31. 선택: **독립 개발 비교만 승인; 기존 MVP 모델 교체 없음**. 실제 실행 및 채택 판단은 [EXP-0038 지침](../CODEX_EXP0038.md)과 후속 결과 보고서에 분리한다.

EXP-0034의 2B는 두 사람이 섞인 입력을 호환으로 답하고, 가려진 하의를 차이로 사용했다. 입력 손실과 모델 해석의 영향을 분리하기 위해 새 박스·영상·질문을 만들지 않고 같은 6쌍·27 이미지 슬롯을 더 큰 모델에 전달한다. 기존 4B는 이 6쌍의 결과가 없어 직접 기준선으로 삼지 않는다. 크기 확대가 원본에 없는 정보를 복원한다는 가정은 하지 않는다.

## 선택과 공식 근거

- 모델은 [공식 Qwen3-VL-8B-Instruct 고정 revision](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct/tree/0c351dd01ed87e9c1b53cbc748cba10e6187ff3b) 한 개다. 공식 카드와 Hub metadata의 라이선스는 Apache-2.0이며 Thinking 모델이 아니다.
- 4개 BF16 safetensors를 다운로드한 뒤 로드할 때 언어 Linear만 NF4/double quant/BF16 compute로 바꾼다. [Transformers 4.57.1 bitsandbytes 문서](https://huggingface.co/docs/transformers/v4.57.1/quantization/bitsandbytes)에 따른 경로이며, 비양자화 시각부·임베딩·독립 출력 head는 BF16으로 유지한다. 공식 파일의 LFS SHA256 또는 Git blob ID와 다운로드 바이트를 대조한다.
- 이미 설치된 `.venv-vlm-batch02`의 torch 2.5.1+cu124, Transformers 4.57.1, bitsandbytes 0.48.1, Accelerate 1.11.0을 우선 재사용한다. 준비를 위해 기존 CV/2B 환경을 업그레이드하지 않는다.
- RTX 3080 10GB에서 시작 여유 8,192MiB를 요구한다. 이는 적재 성공 보장이 아니다. CUDA0 전체 배치, SDPA, batch1이며 CPU/disk offload나 입력 축소 fallback을 하지 않는다.

## 대안과 비교 한계

| 구성 | 이번 처리 |
|---|---|
|기존 2B BF16|EXP-0034 저장 결과를 기준으로 보존; 재추론 없음|
|8B 전체 BF16|원본 가중치만 약17.5GB여서 10GB 장치의 이번 경로에서 제외|
|8B 언어 NF4 + 시각/비양자화 BF16|한 번 적재·6회 순차 생성하는 유일한 새 구성|
|4B 재실행·다른 모델·입력/질문 튜닝|이번 비교 범위 밖; 실행하지 않음|

비교 축은 실제 배포 구성 전체다. 크기·시각 인코더·양자화가 함께 달라지므로 차이를 NF4 또는 모델 크기의 단독 효과로 해석하지 않는다. 공식 processor의 실제 RGB·grid·토큰과 질문 확장을 기록하고 2B와의 차이도 보고한다. 원본 순서, A/B 구성, 이미지 예산, 질문, 파서, greedy/192토큰은 고정한다.

## 판단 기준

P5 혼합 입력과 P2/P6 가림에서 불확실성을 적절히 남기는지, 명확한 다른 의복 대조 P3/P4를 유지하는지를 함께 본다. 형식 통과, 파싱 실패 대체 unknown, 모델이 직접 선택한 unknown을 나눈다. 새로운 사용자 동일인 정답 없이 정확도/F1을 만들지 않는다.

모델 적재·양자화, 요청별 전처리/생성, 전체 큐 시간과 Torch/장치 메모리를 구분한다. 다른 다섯 쌍의 중앙값은 반복 성능 측정이나 SLA가 아니다. 품질 또는 메모리 조건을 충족하지 못하면 채택 보류로 종료하며 재질문·재학습·기본 교체를 자동 수행하지 않는다. 기존 의심·사건 카드·수동 검토 흐름은 이 실험과 독립적으로 유지한다.
